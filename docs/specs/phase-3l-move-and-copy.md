# Spec：階段三 (3l) — 刪除私人帳本時搬走交易、複製交易、標註交易

> 狀態：**草稿，待核可**
> 依據：
>
> - 2d §8「複製交易到其他帳本」：私人帳本想變共享的唯一解法，「本步之後儘早排入」。
> - 3k 範圍外「私人帳本刪除時合併」。
> - 開發者 2026-10-19：「先把複製交易的功能完成，要完成才能比較完整的測試功能」。前提清單的回答：
>   - 從共享帳本直接搬走會影響其他人，所以搬移只從私人帳本出發。
>   - 「有兩種情況：第一種是刪除帳本，那原本帳本的交易一定是搬過去另一個帳本；第二種是單純的複製交易（可能有重複的交易想要另外記一筆，那就用複製功能）」。
>   - 私人帳本裡可以帶走的交易：全部。
>   - 刪除時「可以選擇」搬或不搬；不搬的照 3k 顯示帳戶影響。
>   - 複製是新的一筆，日期是今天；可以記到別本。
> - 開發者 2026-10-20：明細右側加「⋯」，選單有編輯、複製、刪除、標註；複製不放在編輯面板裡。標註「用顏色比較方便」，「標註的交易會特別顯示在首頁」。細節的回答：只有我看得到、只有一種顏色、首頁列所有帳本、明細用列左邊的色條。
> - 開發者 2026-10-20（看過預覽頁後）改刪除流程：封存與刪除做成一顆；先跳出刪除影響帳戶的畫面，底下有刪除、封存；中間問要不要搬到其他帳本；要搬就先列出交易讓我選，選完才選帳本；回到影響畫面，還有沒選的就再問一次。也就是使用者自己決定哪些交易搬到哪本。
>
> 前置：3k（#137）已合併並部署到 dev。
> 改寫的既有決策：3j 決策 186（私人帳本刪除一律撤銷）、2d §8 的「複製交易到其他帳本」改成本 spec 的兩個功能。
> 執行順序：本 spec（含預覽頁）→ plan 與 todo → 一個 PR（後端＋畫面）。

## 1. 目標與成功樣貌

現在刪除私人帳本，交易跟著帳本一起消失，記在裡面的借還被撤銷。想把私人帳本改成共享帳本的人，只能新建一本共享帳本、舊的交易全部重記。另外，同一筆消費常常重複發生（每天的早餐、每月的訂閱），現在只能每次從頭填。

本步做三件事：

- **刪除私人帳本時，可以把交易搬到我的其他帳本**，包括共享帳本。我自己挑哪幾筆搬到哪一本，可以分成好幾組搬到不同帳本。搬過去的交易就是原來那幾筆，帳戶餘額不變、可以照常修改。
- **複製交易**：從一筆交易開出新增表單，內容先帶好，改完存成新的一筆。
- **標註交易**：把要留意的交易標起來（例如還沒報帳的），明細看得出來，首頁集中列出。

用一個例子貫穿全篇。我有私人帳本「日常」與「旅行基金」，還有共享帳本「家用」（我、小美）。「旅行基金」裡有：

| #   | 交易     | 帳戶                        | 金額                                 |
| --- | -------- | --------------------------- | ------------------------------------ |
| 1   | 機票訂金 | 信用卡                      | −$5,000                              |
| 2   | 存入     | 現金 → 旅行帳戶（帳戶互轉） | $2,000                               |
| 3   | 借給阿德 | 現金                        | −$1,000（個人借還，阿德欠我 $1,000） |

假設刪除前信用卡 −$5,000、現金 $10,000、旅行帳戶 $2,000。

本步完成後：

1. 我在「旅行基金」的帳本頁按「刪除帳本」（原本的「封存帳本」「刪除帳本」合成這一顆）→ 對話框「刪除「旅行基金」」。一開始什麼都不搬，所以帳戶段列出全部影響：「信用卡 −$5,000 → $0」「現金 $10,000 → $13,000」「旅行帳戶 $2,000 → $0」；往來段「阿德 $1,000 → $0」。中間一行「搬到其他帳本 ›」，下面是帳本名稱欄與「取消」「封存」「刪除」。
2. 點「搬到其他帳本」→ 選擇畫面列出 3 筆、全部沒勾。我勾存入與借給阿德，按「下一步」→ 選帳本「家用」→ 回到對話框。搬移段多一組「2 筆 → 家用 ×」；帳戶段只剩「信用卡 −$5,000 → $0」，往來段消失。還有 1 筆沒選，所以「搬到其他帳本」還在。
3. 再點一次 → 選擇畫面只剩機票訂金。勾它、選「日常」→ 搬移段兩組。全部選完，「搬到其他帳本」與帳戶段都不見了。
4. 打名稱、按「刪除」→「家用」多了存入，小美看得到，付款人是我、沒有分帳；借給阿德也在「家用」，但它是我的個人借還，只有我看得到（同 3b）。「日常」多了機票訂金。我的帳戶餘額不變；借還頁的阿德照樣是「阿德 ─▶ 我 $1,000」。
5. 換一個情況：第 2 步之後按「家用」那組的「×」→ 那 2 筆回到沒搬，帳戶段與往來段照第 1 步重新出現。這時按「刪除」，就是現在 3j 的刪除。
6. 換一個情況：在對話框按「封存」→ 帳本封存，什麼都不搬、不刪。
7. 在「日常」的明細，點「早餐 $80 現金」右側的「⋯」，選「複製」→ 新增表單打開，帳本「日常」、日期今天、金額 $80、分類早餐、帳戶現金、名稱早餐都帶好。按「新增」→ 多一筆今天的早餐，現金再扣 $80。
8. 複製時把帳本換成「家用」→ 分類改成「家用」裡同名的「早餐」（沒有同名的就空著讓我選），其他欄位不變。
9. 在「家用」點「計程車 $300」的「⋯」，選「標註」→ 這一列左邊出現一條色條。小美看不到我的標註。
10. 回到首頁，不管現在選哪本帳本，「標註」卡都列出計程車，標著帳本名「家用」。點它打開那筆的編輯面板；從「⋯」選「取消標註」後，它從首頁消失。

### 範圍外

- **從共享帳本搬走交易**：會影響其他成員的帳與餘額。要把自己的帳帶出共享帳本，用 3k 的退出並合併。
- **不刪帳本、只搬選取的交易**（批次搬移）：開發者這次只要刪除時搬與複製。要的話另案。
- **一次複製多筆**、**定期自動記帳**：另案。
- **複製借還、結清、合併來的「我付、有分帳」**：它們各有記法（借還頁、結清按鈕），複製按鈕不出現。
- **標註的多種顏色、替標註取名、依標註篩選明細**：這次只有一種。

## 3. 資料模型

搬移與複製**不改資料模型**。標註需要一張新表（開發者 2026-10-20 同意做標註；表的形狀待核可）：

```prisma
/// 我標註的交易（3l 決策 222）。只屬於標註的人，所以不放在 Transaction 上。
model TransactionMark {
  userId        String
  transactionId String
  createdAt     DateTime @default(now())

  user        User        @relation(fields: [userId], references: [id], onDelete: Cascade)
  transaction Transaction @relation(fields: [transactionId], references: [id], onDelete: Cascade)

  @@id([userId, transactionId])
  @@index([transactionId])
}
```

- 替代方案是在 `Transaction` 加一個欄位：簡單，但共享帳本的成員會看到同一個標註、也會互相蓋掉，違反決策 222。
- 一個 migration：只建表，不動既有資料。

搬移只改 `Transaction.ledgerId`、`DebtEntry` 與 `Split` 所在帳本的關聯（3k 決策 197 已經這樣做）、分類對應時可能新建 `Category`。複製走既有的建立端點。

## 4. API

### 4.1 `POST /ledgers/{ledgerId}/leave-preview`、`POST /ledgers/{ledgerId}/leave`（改）

request 多一個欄位（私人帳本用）：

```ts
interface LeaveMove {
  /** 搬到哪一本（決策 212）。 */
  targetLedgerId: string;
  /** 這組要搬的項目，值是 `LedgerLeaveItem.id`。至少 1 個。 */
  itemIds: string[];
}

interface LeaveRequest {
  // 3k 既有的 targetLedgerId、excludedItemIds、deleteLedger、confirm 不變
  /** 私人帳本刪除時的搬移（3l 決策 209）。不在任何一組的項目＝不搬。 */
  moves?: LeaveMove[];
}
```

- 私人帳本：必須帶 `deleteLedger: true` 與 `moves`（可以是空陣列＝全部不搬）；不能帶 `targetLedgerId`、`excludedItemIds`。不符 → 400。共享帳本照 3k，不能帶 `moves`（→ 400），除非開發者決定 3k 也改成這套（§10 第 7 點）。
- `moves` 的檢查，違反都是 400：同一個項目出現在兩組；同一本目標帳本出現兩次（前端會先併成一組）；某組 `itemIds` 是空的；項目 id 不屬於這次預覽；目標是要刪的這本。
- 只有擁有者（私人帳本的擁有者就是我）；封存的 → 預覽 `blockedBy: 'LEDGER_ARCHIVED'`、執行 409（同 3k）。
- 預覽回應的形狀不變：`items` 是全部項目（照決策 211 分組），前端自己濾掉已經在某一組的；`accounts`、`withdrawals` 只算沒搬的；`carryOvers` 恆為空陣列（私人帳本沒有帳本裡的人）。
- 執行：分類對應（每組對自己的目標帳本）→ 各組改 `ledgerId` → 沒搬的照 3j 決策 186 撤銷 → 刪帳本。
- 錯誤：任一組的目標帳本不能記帳 → 403；封存 → 409；`confirm` 不等於帳本名稱 → 400（同 3k）。

### 4.2 標註（新）

- `PUT /ledgers/{ledgerId}/transactions/{transactionId}/mark` → 204；`DELETE` 同一路徑 → 204。兩個都可以重複呼叫（已標再標、沒標再取消都 204）。
- 權限：這本帳本的成員（檢視者以上，封存也可以）；交易不在這本帳本或已刪除 → 404。
- 交易回應多 `marked: boolean`（呼叫者自己的標註）。所有回傳 `Transaction` 的端點都帶。
- `GET /transactions/marked?page=&limit=` → `Paginated<MarkedTransaction>`：我現在是成員的帳本裡、沒刪除、我標註的交易，依日期、再依建立時間由新到舊。`MarkedTransaction` 是 `Transaction` 加 `ledger: { id, name }`。`limit` 預設 10、最多 100。

### 4.3 shared

- `LeaveRequest` 加 `moves?: LeaveMove[]`、新型別 `LeaveMove`（§4.1）；註解補「私人帳本刪除也用這組型別，搬移不是合併」。`LedgerLeavePreview` 不加欄位。
- 交易回應不為搬移加欄位：搬過去的交易就是原交易，不標來源。
- 新型別：`Transaction.marked`、`MarkedTransaction`、`ListMarkedTransactionsQuery`。

## 5. 成功條件

- **SC-N1**（全部搬到一本）：§1 的旅行基金 3 筆一組搬到日常 → 3 筆在日常，id 不變；信用卡、現金、旅行帳戶餘額不變；阿德往來餘額不變、往來紀錄可以照常改；旅行基金查不到（404）。
- **SC-N2**（分組搬，含共享帳本）：§1 第 2～4 步 → 存入與借給阿德在家用、機票訂金在日常；小美看得到存入、付款人是我、她的帳與餘額不變；看不到借給阿德。
- **SC-N3**（部分搬）：只有「2 筆 → 家用」一組 → 預覽帳戶段只有「信用卡 −$5,000 → $0」，執行後結果與預覽一致，機票訂金跟帳本一起刪掉。
- **SC-N4**（不搬）：`moves: []` 的結果與 3j 刪除私人帳本（`withdrawDebts=true`）相同：帳戶影響一致、借還撤銷、連動的對方收到撤銷。
- **SC-N14**（`moves` 的檢查）：§4.1 列的 5 種不合法 request 都 400；私人帳本沒帶 `moves` 或帶 `targetLedgerId` → 400；共享帳本帶 `moves` → 400。
- **SC-N5**（分類）：目標帳本有同名分類就用、沒有就新建一個同名同圖示的；不會指到被刪帳本的分類。
- **SC-N6**（綁在一起）：有結清分支的還款、個人分帳、合併來的「我付、有分帳」，勾或不勾都整組一起；不會留下一半。
- **SC-N7**（隔離）：別人的私人帳本預覽與執行 → 404；目標是我沒有寫入權的帳本 → 403；目標是封存的 → 409；搬移只動呼叫者自己的資料。
- **SC-N8**（複製）：§1 的早餐複製 → 新的一筆、日期今天、其他欄位相同，原交易不變；換到家用 → 分類對到同名、付款人是我、沒有分帳。
- **SC-N9**（複製的範圍）：借還、結清、合併來的「我付、有分帳」的「⋯」選單沒有「複製」。
- **SC-N10**（標註）：§1 的計程車標註後，我的明細有色條、`marked: true`；小美的同一筆 `marked: false`。取消後回到 `false`。重複標註、重複取消都 204。
- **SC-N11**（首頁）：`GET /transactions/marked` 列出我所有帳本的標註，不含已刪除的交易、不含我已退出的帳本、不含別人的標註；順序由新到舊；首頁卡片照列，沒有標註時不顯示。
- **SC-N12**（標註的隔離）：不是成員標別人帳本的交易 → 404；`ledgerId` 與交易不符 → 404；檢視者可以標。
- **SC-N13**（標註跟著交易）：標註過的交易被 3l 搬到另一本後，`marked` 仍是 `true`，首頁標的帳本名是新的帳本。

## 7. 界線

- **Always**：數字由後端算，預覽與執行同一套計畫；搬移在單一資料庫交易內完成；分類對應到目標帳本自己的分類。
- **Ask first**：改資料模型；開放從共享帳本搬移；一次複製多筆。
- **Never**：前端自己算帳戶影響；搬移時留下指向被刪帳本的分類或交易；複製時沿用另一本帳本的分類 id。
