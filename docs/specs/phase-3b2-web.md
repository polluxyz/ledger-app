## 1. 目標與成功樣貌

使用者在借還檢視與總覽就能完成連動的整個流程：

1. 在選人的下拉選單裡找到人，已連動的人旁邊標「連動」。不記帳也能先新增一個人。
2. 從某個人的往來帳「邀請連動」：輸入對方的 email，或產生一條連結傳給對方。送出的邀請在往來帳看得到，也能取消。
3. 對方在總覽的「待確認」卡片接受，或打開連結在邀請頁接受。接受時選「他在我的往來帳裡是誰」，預設新增一個以對方名字命名的人。
4. 連動後記的每一筆，旁邊標「等對方確認」「已同步」或「對方未接受」。
5. 對方在總覽一筆一筆確認收到的紀錄。新增的紀錄在卡片內展開，選帳本與帳戶；修改的紀錄寫出「$120 → $150」。
6. 改或刪已同步的紀錄時，看到一段平和的說明：會送給對方確認，對方不接受也沒關係。
7. 解除連動後，名字與紀錄都留著，只是之後各記各的。

設計原則沿用 3b-1：**以使用者的角度考量，不能繁瑣，但不能因此失去嚴謹。** 開發者 2026-09-25 補充：帳本以個人為主，連動只是「知道有同步」就好。

### 範圍外

- 顯示對方帳上的餘額（W26，改變 `phase-3b2-linking.md` 決策 60 的畫面部分）。
- 側欄或頁首的待確認數量（`phase-3b2-linking.md` §9）。
- 查看送出的提議清單。發起者從每筆紀錄的同步標籤就知道狀態。
- 通知、推播。

## 4. 畫面規格

範例：你是「陳大文」，往來帳有「小明」（已和使用者「王小明」連動）、「阿華」、「媽媽」。

### 4.1 選人的下拉選單（W24、W25）

- 輸入框聚焦或打字時展開清單。沒打字時列出全部（後端排序，餘額不為 0 的在前）；打字後停止 300ms 送出 `GET /counterparties?q=`。
- 每列：名字；連動的人後面加「連動」標籤。
- 輸入的名字沒有完全相同的人 → 最後一列「＋ 新增「小華」」。輸入空白時沒有這一列。
- 清單一次取 50 人。超過時最後一列寫「繼續輸入以縮小範圍」。
- 選定後關閉清單，輸入框下方顯示 3b-1 的餘額提示；新名字顯示「新對象，送出時建立」。
- 鍵盤：上下鍵移動、Enter 選取、Esc 關閉。用 ARIA combobox 模式（`role="combobox"`、`listbox`、`aria-activedescendant`）。
- 用在接受連動邀請時（W39）：只列 `link === null` 的人，預填對方的顯示名稱。

### 4.2 借還檢視（W26）

- 清單上方加一顆「新增」按鈕。小視窗：一個欄位「名字」，按「新增」送出。撞名時顯示後端錯誤。
- 清單每一列，連動的人名字後面加「連動」標籤。

### 4.3 往來帳（W27～W32）

由上往下：

1. 標題：名字；連動中加「連動」標籤；右邊「改名」。
2. 大字餘額（沿用）。連動中時，下方一行小字「已和 王小明 連動」。
3. 送出中的 email 邀請（W29）：一行「已邀請 name@example.com，等對方接受」，旁邊「取消邀請」。取消呼叫 `POST /friend-requests/{id}/cancel`，不另開確認視窗。
4. 動作列：
   - 「記一筆」（沿用）。
   - 「免除剩餘」（沿用）。
   - 「邀請連動」：沒連動、也沒有送出中的邀請時顯示。
   - 「解除連動」：連動中顯示。
   - 「刪除對象」：沒有任何往來紀錄、且沒連動時顯示。
5. 往來紀錄：每列在「未記帳」標籤的位置多一個同步標籤（W30）。

**邀請連動視窗（W28）**

- 標題「邀請連動：阿華」。
- 說明：「對方接受後，你們之後記的借還會互相同步。之前的紀錄不會同步。」
- 上段：欄位「對方註冊用的 email」＋「送出」。成功後關閉視窗，往來帳出現第 3 點那一行。
- 「或」。
- 下段：「產生連結」按鈕。產生後顯示唯讀欄位 `https://<目前網域>/invite#<token>`、「複製」按鈕、「有效到 14:32。只能用一次，重新產生會讓舊連結失效。」複製成功時按鈕暫時改成「已複製」；複製失敗時選取欄位文字。
- 錯誤直接顯示在該段下方（§4.6）。`LINK_INVITE_FROM_THEM` 另加一個「到總覽接受」連結。

### 4.4 警告文案（W31）

**展開區（W37）**

- 連動邀請：W39 的下拉選單＋說明一行＋「取消」「接受並連動」。成功後收起，並提供「查看往來帳」連結。
- 新增提議（借出、借入、還款）：
  1. 預覽（W43）：「記完後你欠小明 $80」。
  2. 「記在哪本帳本」：可編輯的帳本（EDITOR 以上、未封存），預設目前作用中的帳本。
  3. 帳戶：帳本連動帳戶餘額時才顯示，不預選、必填。標籤依種類：借入「借到的錢進哪個帳戶」、借出「從哪個帳戶借出」、他還你「收進哪個帳戶」、你還他「從哪個帳戶付出」。
  4. 勾選框「不記入帳本（只記往來）」，勾了帳本與帳戶停用，送 `record: null`。
  5. 「取消」「接受」。
- 錯誤（W38）：`NOTHING_TO_REPAY`「你帳上和小明目前兩清，這筆還款記不進去。你可以拒絕，再和王小明對一下帳。」；`REPAYMENT_EXCEEDS_BALANCE`「這筆還款超過你帳上的欠款。你可以拒絕，再和王小明對一下帳。」主要按鈕換成「改成拒絕」。

`counterpartyId` 為 `null` 的提議（解除連動後殘留）不會出現，因為解除時後端已經把它們取消。

## 8. 界線

- **Always**：同步狀態、配對、送出中的邀請、餘額一律取自 API；需要記帳的接受一定明確給 `record`（物件或 `null`）；token 只放在 `#` 之後，接受後立刻從網址清掉。
- **Ask first**：F25、F26 以外的任何後端變更（先改 `phase-3b2-linking.md`）；新增套件；側欄或頁首的改動。
- **Never**：畫面出現「好友」；前端推導同步狀態或對方餘額；不經使用者按「接受」就寫入任何紀錄；把 token 寫進 localStorage、sessionStorage 或送進伺服器的網址路徑。
