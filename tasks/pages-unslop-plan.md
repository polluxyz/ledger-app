## 順序與相依

1. T0 協調者：spec、plan、todo、2j W207／W220／W221／W222 修訂註記、`docs/README.md` 規格表，同一個 docs commit。2n 的 plan、todo 移到 `tasks/archive/`。
2. 第 1 組 commit「共用元件」：
   - T1 分段切換鈕統一樣式（W320）。
   - T2 卡片外觀與 ≤900px 44px 觸控區（W320）。
3. 第 2 組 commit「身份與個人資料」：
   - T3 登入、註冊身份版面與 `AuthDialog` 表單樣式（W318）。
   - T4 個人資料（W319）。
4. 第 3 組 commit「統計頁」：
   - T5 範圍列、摘要、黏頂分頁（W313）。
   - T6 分類與成員兩欄（W314、W315）。
   - T7 趨勢合成圖與詳情列、舊網址與 localStorage 正規化（W316、W317）。
5. T8 全套驗證、前後截圖、每組單獨 revert 後 typecheck 與 test。
6. T9 協調者驗收：讀完整 diff，自己重跑 typecheck、test 與相關 e2e，開 PR，等 CI 全綠。
7. T10 demo：現版與新版並排給開發者看，不合併。

相依：

- 第 2、3 組使用第 1 組的切換鈕與卡片樣式，所以第 1 組先做。
- 第 2 組與第 3 組互不相依。第 2 組風險較低，先做。
- T7 依賴 T6 的切換列位置（趨勢不再有圖型切換，但方向列的對齊方式要一致）。
- 每組 commit 要能單獨 revert：後面的組不可修改前面組新增的共用樣式名稱。若要改，回到前面那組的 commit 改。

## 替代方案與取捨

- 趨勢保留長條／折線切換，只拿掉表格：開發者要求合成一張圖（spec 依據）。
- 趨勢合成圖改成橫向捲動：開發者選 12 個月擠一張細柱（spec 依據）。
- 手機兩欄改成清單在上：開發者選圖在上、清單在下。
- 用 CSS `order` 調換手機順序：鍵盤與讀屏順序會和畫面不一致。改成依寬度改渲染順序（決策 416）。
- 個人資料套用 SH-2 共用表單骨架：會連帶影響其他表單，超出範圍（決策 421）。
- 身份彈窗也加品牌欄：彈窗寬度不夠，會壓縮表單（決策 420）。
- 分 3 個 PR：開發者選 1 個 PR 分 3 組 commit，方便一起看 demo（決策 423）。

## demo 方式

1. API：協調者在本工作區用 `ledger_web_unslop_test` 的一份 demo 資料（虛構名字與金額）啟動 API，埠 3200。`CORS_ORIGIN` 同時允許 5180 與 5181。
2. 現版：main 工作區（`D:/Projects/ledger-app`，HEAD 是 PR base）只啟動 web dev server，埠 5181，`VITE_API_BASE_URL` 指向 3200。不改 main 工作區的任何檔案。
3. 新版：本工作區啟動 web dev server，埠 5180，同一個 API。
4. 給開發者兩個網址與一組 demo 帳號。開發者看完後協調者關掉 3 個 server。
5. demo 資料、截圖、網址都不含真實 email、token 或連線字串。
