# Spec：2m — 首頁風格與財務趨勢

狀態：開發者在逐次確認預覽後指示「好 幫我實裝」，並指定實裝完成後交由 Claude Code 驗收。此核可涵蓋下列已討論的介面；實作不另增加功能。

## 目標與範圍

首頁維持八張卡與原有版面儲存格式，套用黑金／象牙金的層次、數字、留白與清單樣式。替換首頁折線圖與借還摘要，保留所有帳戶、分類配色、最近／標註、待處理、AI 草稿、帳本切換與版面編輯。

1. 財務趨勢：左側「總資產變化」、右側「每月結餘」，預設左側，兩種都只用柱狀圖。總資產是個人帳戶每月月底總額；結餘是所選帳本的收入減支出。最近 12 個月，主數字、資料範圍、刻度與月份詳情同步切換。
2. 動畫：選取底板滑動、柱形與零線平順變化、數字與說明淡入。快速連點以最後一次為準，使用者關閉動畫時立即切換。動畫中的位置插值只用於繪圖，不作為帳務金額。
3. 借還：付款方在左、收款方在右，圓形頭像下是姓名；中間上方「需要支付」，箭頭指向收款方，下方是完整金額。正數為對方付我，負數為我付對方；兩清不畫箭頭。姓名單行省略但讀屏與提示保留全名。
4. 其他卡：重點數字放大、結餘淡金底、分類細進度條、清單分隔與間距調整。保留正式首頁「總覽」入口及既有導覽與記帳入口，預覽裝飾文案不取代功能。

## 資料與邊界

- 使用既有 `/accounts/balance-trend` 與 `/ledgers/{ledgerId}/statistics/trend`，分別呈現 `total` 與 `net`；不在前端計算結餘，不將資產相減當成結餘。
- 每月結餘沿用帳本口徑，切換帳本後不呈現前一本帳本資料。個人資產不受帳本切換影響。
- 沒有帳本只提供總資產；月結餘選項停用並說明原因。訪客不呼叫受保護端點。
- 載入／錯誤不當成零。重新抓取沿用已有資料；寫入後沿用共用快取失效流程更新。
- Always：設計 token、整數分、既有授權與資料隔離、鍵盤操作、手機與可調寬高。
- Ask first：API、schema、相依、CI 或範圍變更。
- Never：新增彙總金額、借還重新排序、改版面契約、未驗收合併、直接修改 dev 資料。

## 可驗證成功條件

- SC-V1：切換項順序正確，兩個指標以各自 API 回應呈現，12 個月、主數字、範圍與負號一致。
- SC-V2：正值由零線向上、負值向下；全零、常數、單一月份與極大安全整數不產生無效座標或誇大零值。
- SC-V3：滑動與柱形動畫可見；快速切換、資料更新、改寬高、關閉動畫、卸載皆不留下舊動畫或錯誤數值。
- SC-V4：滑鼠、觸控點選、Tab、Enter／Space 與左右鍵可取得各月份的精確金額。
- SC-V5：借還雙向、兩清、零錢、長姓名與大金額正確，390px 及 309px 卡片不溢出或重疊。
- SC-V6：深淺主題、分類三種配色、全部帳戶、自訂版面、最近／標註與 AI 入口保持可用；新版首頁沒有折線或月份清單。
- SC-V7：無帳本、查詢失敗、換帳本與新增交易後更新流程有驗證；關閉動畫立即切換。
- SC-V8：format、lint、typecheck、單元測試與 build 通過；首頁與版面編輯 e2e 驗證並記錄，交給 Claude Code 獨立驗收後才可合併。

## 測試策略

元件測試驗證金額、方向、空狀態與鍵盤；座標單元測試包含全零及正負極值。首頁整合測試使用正式 App 與 mock fetch 驗證兩個資料來源與切帳本。Playwright 對真實 API 驗證首頁／版面編輯，另以瀏覽器量測動畫、主題、窄卡與長姓名。HTML 預覽只作視覺參考，不進版控。
