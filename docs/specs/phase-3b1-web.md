## 1. 目標與成功樣貌

讓開發者**實際操作**單邊借還，找出 3b-1 規則的問題，再進 3b-2。

本步完成後，使用者在交易頁就能：

1. 記一筆借出或借入，跟記支出一樣在右側欄的表單填。
2. 記一筆還款：選是哪一筆債務，金額預設為未清餘額。差幾塊就算了，或對方多給了，勾「以此結清」。
3. 看每個人跟我之間的淨額，以及每一筆還沒結清的債務。
4. 點一筆借還交易，看那筆債務的詳情：還款紀錄、改內容、免除、刪除。

設計原則（開發者 2026-09-24）：**以使用者的角度考量，不能繁瑣，但不能因此失去嚴謹，因為牽涉到錢。**

### 範圍外

- 好友（3a）的畫面：留到 3b-2 的畫面，因為連動要先有好友。
- 連動、提議：3b-2。
- 首頁 dashboard 的借還卡片。
- 交易篩選器的型別下拉加入借還型別。要看借還，切到「借還」檢視（§4.2）。
- 統計報表。

## 4. 畫面規格

### 4.1 交易表單的「借還」分頁（W2、W3）

分頁列：支出／收入／轉帳／**借還**。選了借還，下面換成 3 個選項：**借出／借入／還款**。

**借出、借入**的欄位：

| 欄位     | 規則                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| 對方名字 | 必填，1～100 字。輸入時提示既有的名字（取自每人淨額），避免「小明」「小明 」被當成兩個人                      |
| 金額     | 必填，正整數                                                                                                  |
| 日期     | 預設今天                                                                                                      |
| 帳戶     | 與一般交易相同：帳本＝作用中帳本；連動帳本必填帳戶，非連動帳本沒有這個欄位                                    |
| 備註     | 選填                                                                                                          |
| 舊債     | 勾選框「這是舊債，不記入帳本」，預設不勾。勾了之後帳戶欄變灰、送出時不帶 `record`，並顯示「帳戶餘額不會變動」 |

**還款**的欄位：

| 欄位       | 規則                                                                                                           |
| ---------- | -------------------------------------------------------------------------------------------------------------- |
| 債務       | 必填。下拉列出未結清的債務，每項顯示「借給小明 · 剩 $3,000」或「向阿華借 · 剩 $1,200」                         |
| 金額       | 選了債務後預設為它的未清餘額                                                                                   |
| 日期       | 預設今天                                                                                                       |
| 帳戶       | 同上。送出時明確帶 `record`（作用中帳本＋選的帳戶），不依賴後端的「沿用本金交易」預設，畫面顯示什麼就記到哪裡  |
| 備註       | 選填                                                                                                           |
| 不記入帳本 | 勾選框，預設不勾。勾了送出 `record: null`（明確不產生交易，3b-1 修訂），帳戶欄變灰，並顯示「帳戶餘額不會變動」 |
| 以此結清   | 見下                                                                                                           |

**「以此結清」**（決策 30）：

- 金額等於未清餘額時不顯示（本來就會結清）。
- 金額**少於**未清餘額時顯示勾選框，預設不勾。不勾＝部分還款。勾了顯示「差額 −3：對方少還 3 元，這筆債務會結清」。
- 金額**多於**未清餘額時顯示勾選框，並提示「超過未清餘額，要以此結清才能送出」。沒勾就送出，照常顯示後端的 `409 DEBT_OVERPAYMENT` 訊息。
- 差額的正負號從使用者角度寫成白話：借出時「對方少還／多給」，借入時「我少付／多付」。
- 這裡的差額只是**送出前的預覽**（金額減未清餘額）。送出後畫面上的差額一律取自回應的 `settlementDifference`（W9）。

送出成功後：表單清空，留在「借還」分頁，列表與淨額重新載入。

### 4.2 借還檢視（W4）

交易頁標題下方的切換：**明細**／**借還**。網址 `?view=debts`，重新整理後停在同一個檢視。

- **每人淨額卡片**：每人一張，顯示名字與金額。正數寫「欠我」、負數寫「我欠」。沒有未結清的債務時顯示「目前沒有未結清的借還」。
- **狀態分頁**：未結清（預設）／已結清／已免除。
- **債務列表**：每列顯示方向與對方（「借給小明」「向阿華借」）、日期、本金、未清餘額或狀態標籤。舊債加「舊債」標籤。每頁 20 筆。
- 點一列 → 右側欄顯示債務詳情（§4.3）。
- 借還不分帳本：頁首的帳本切換器仍在（新增表單要用），但借還檢視上方註明「借還紀錄不分帳本」。

### 4.3 債務詳情（右側欄，W5）

從兩個地方打開：借還檢視點一列；明細檢視點一筆借還交易（`debtId` 有值時）。

內容：

- 標題「借給小明」或「向阿華借」、狀態標籤、日期、備註。
- 本金、未清餘額。**不顯示「已還」**：那要在前端相減，違反 W9。
- 以結清還款結清時，顯示「結清差額 +2（對方多給）」。
- 還款紀錄：日期、金額、帳戶、備註；結清的那筆加「結清」標籤。每筆有「刪除」。
- 動作按鈕依狀態顯示（只為體驗，後端照樣擋）：

| 按鈕     | 何時顯示      | 形式                                                                 |
| -------- | ------------- | -------------------------------------------------------------------- |
| 記還款   | `OPEN`        | 小視窗，欄位同 §4.1 的還款（債務已決定，不用選）                     |
| 編輯     | 一律          | 小視窗。有結清還款時本金欄不顯示，旁註「先刪除結清的還款才能改本金」 |
| 免除剩餘 | 借出且 `OPEN` | 確認視窗，寫明「免除後不可撤銷」                                     |
| 刪除     | 一律          | 確認視窗，寫明「連同所有還款與交易一起刪除，帳戶餘額會回到借出前」   |

刪除還款也跳確認視窗，寫明「對應的交易會一起刪除」。

### 4.4 明細檢視的借還交易

- 借還交易照 3b-1 的樣子顯示：標籤（借出、借入、收回、償還）、正負號、中性色，沒有編輯與刪除按鈕。
- `debtId` 有值 → 可點，打開債務詳情。
- `debtId` 是 `null`（帳本裡別人的借還交易）→ 不可點，滑鼠移上去**沒有**可點的樣式。這順便修掉 3b-1 留下的問題（`tasks/archive/phase-3b1-plan.md` §6）。

### 4.5 錯誤訊息

在 `lib/error-messages.ts` 補上：

| 代碼                           | 訊息                                                         |
| ------------------------------ | ------------------------------------------------------------ |
| `DEBT_OVERPAYMENT`             | 金額超過未清餘額。如果對方多給了，請勾選「以此結清」。       |
| `DEBT_NOT_OPEN`                | 這筆借還已經結清或免除了。要改本金，請先刪除結清的那筆還款。 |
| `DEBT_NOT_FORGIVABLE`          | 只有借出去的錢可以免除。                                     |
| `DEBT_TRANSACTION_READ_ONLY`   | 借還交易要從借還詳情修改。                                   |
| `LEDGER_HAS_DEBT_TRANSACTIONS` | 這本帳本有借還交易，不能刪除。請改用封存。                   |

文案在 plan 階段可再修，但不可以比後端更具體（`error-messages.ts` 檔頭規則 2）。

## 5. 可驗證的成功條件

- **SC-W1**：在借還分頁建立借出 5,000、記進現金 → 現金餘額少 5,000；明細檢視出現一筆「借出」；借還檢視出現「小明 欠我 $5,000」。
- **SC-W2**：在借還分頁選「還款」、選那筆債務 → 金額欄預設 5,000。改成 2,000 送出 → 詳情的未清餘額 3,000、狀態未結清。
- **SC-W3**：再記 2,990 並勾「以此結清」→ 送出前顯示「差額 −10」；送出後狀態已結清、詳情顯示「結清差額 −10」，數字取自 API；現金多了 2,990。
- **SC-W4**：金額超過未清餘額且沒勾結清 → 顯示 §4.5 的 `DEBT_OVERPAYMENT` 訊息，什麼都沒寫入。
- **SC-W5**：勾「這是舊債」建立 → 送出的 body 沒有 `record`；帳戶餘額不變；這筆只出現在借還檢視，不出現在明細。
- **SC-W6**：明細檢視點「收回」那筆 → 右側欄打開那筆債務的詳情。共享帳本的其他成員看到同一筆交易時不可點，也沒有可點樣式。
- **SC-W7**：「免除剩餘」只在借出且未結清時出現；確認視窗寫明不可撤銷。借入的債務沒有這顆按鈕。
- **SC-W8**：刪除債務 → 確認後帳戶餘額回到借出前；借還檢視與明細都不再出現。
- **SC-W9**：`?view=debts` 重新整理後仍在借還檢視；側欄沒有新增項目。
- **SC-W10**：前端沒有計算未清餘額、淨額、已還總額、結清差額（送出前的預覽除外，§4.1）。驗證方式：審查 `features/debts/` 的程式碼，確認只有一處預覽的相減。
- **SC-W11**：`pnpm lint / typecheck / test / build / format:check` 與兩套 e2e 全綠。

## 6. 測試策略

- **元件測試**（Vitest + Testing Library）：`DebtEntryForm` 的 3 種模式與送出的 body（含舊債不帶 `record`、還款明確帶 `record`、`settles`）；`PaymentFields` 的結清勾選框在少於、等於、多於未清餘額時的顯示；`DebtDetail` 的按鈕依狀態顯示；`TransactionList` 的借還列可點與不可點。
- **e2e**（Playwright）：`debts.spec.ts` 跑一次 SC-W1 → W2 → W3 → W6 → W8 的完整流程，外加 SC-W5 舊債。
- **回歸**：既有的交易、帳戶 e2e 維持綠燈。

## 7. 界線

- **Always**：顯示的金額與狀態取自 API；送出還款時明確帶 `record`（或明確不帶，當使用者勾了不記入帳本）；刪除與免除先確認。
- **Ask first**：任何後端變更（先改 `phase-3b-debts.md`）；新增套件；側欄或首頁的改動。
- **Never**：在前端計算未清餘額、淨額、已還總額（§4.1 的送出前預覽除外）；讓借還交易走一般交易的編輯或刪除；把差額另外記成收入或支出交易。

## 8. 待開發者確認的假設

1. 還款的帳戶預設與一般交易表單相同（第一個帳戶），**不**自動帶入借出時的帳戶。理由：Debt 回應裡沒有本金交易的帳戶，要多打一個 API 才拿得到。實際用了覺得不順手，再開後端小改動在回應裡加上它。
2. 借還檢視的淨額卡片人數多時會換行，本步不設上限。實際用到再處理。
