# Spec：階段三 (3j) — 帳本的退出、刪除、封存

> 狀態：**草稿，待開發者核可**
> 依據：開發者 2026-10-16～17 操作 3i 後的討論：
>
> - 借還紀錄改金額、日期、備註、撤銷時不檢查帳本寫入權（3i plan §6）→「可以」補上；「封存的帳本應該是任何人都無法改」。
> - 對方送來的修改、撤銷，封存後也不能接受 → 同時做「取消封存」（開發者選 A）；封存「不用再打名稱」。
> - 「共享帳本退出時，裡面的交易並不會有任何變化，重點是退出的那個使用者有沒有影響到自己帳戶的變化」「退出對個人端而言等於刪除」。
> - 「如果其他人都退出了，應該就可以直接刪除」；刪除與退出都先顯示「影響哪些帳戶」，讓使用者決定刪除還是封存。
> - 有借還時「可以選擇要不要複製到別的帳本；如果都不複製，就是選擇要不要撤銷再退出」。
>
> 畫面：預覽頁 `docs/artifacts/step-3j-ledger-cleanup-preview.html`（不進版控）。
> 前置：3i（#128）已合併並部署到 dev。
> 改寫的既有決策：2c 決策 11（封存取代刪除、有別人的交易不能刪）；3b 決策 21（有借還交易不能刪）；3h 決策 165 的「所有帳本的交易都算進來」；2c §8 的「解除封存帳本」（待定 → 本步做）。
> 執行順序：本 spec → plan 與 todo → 實作 PR。

## 1. 目標與成功樣貌

帳本現在有 3 個問題：

1. 借還紀錄在檢視者身分或封存的帳本裡還改得動、撤銷得了。
2. 封存回不去，封存前還要打名稱。
3. 退出共享帳本後，自己記的交易看不到，卻還算在自己的帳戶餘額；刪除帳本的條件又太嚴，自己一個人的帳本記錯了也刪不掉。

本步用一條規則把第 3 點理順：**帳戶餘額只算帳戶主人目前還在的帳本裡的交易**。退出對自己等於刪除，對留下來的人什麼都沒變；別人都退出後，刪除帳本只影響自己，所以可以刪。

用 dev 的測試資料（我＝test；小華＝c@c.com；花蓮三日是共享帳本）：

1. 小華在花蓮三日被降為檢視者，借還頁上那本帳本的紀錄沒有「修改」「撤銷」；直接打 API 改金額 → 403。帳本封存後撤銷 → 409。
2. 擁有者打開已封存的帳本，按「取消封存」→ 帳本回到切換器，又能記帳。封存時只跳確認，不用打名稱。
3. 小華按「退出花蓮三日」→ 先看到「他的現金 $X → $Y」。確認後，花蓮三日的交易一筆都沒少，我照樣看得到小華記的那幾筆；小華的現金不再算那些交易。
4. 小華在花蓮三日記過借還 → 退出畫面多一段「往來」，按鈕是「撤銷並退出」。按下後那幾筆借還被撤銷，連動的對象收到撤銷請他確認。
5. 花蓮三日只剩我一個人 → 按「刪除帳本」，先看到我的帳戶餘額變化，下面有「封存」與「刪除」。按刪除（打對名稱）→ 帳本消失；已經退出的人，餘額都不變。還有別的成員時，對話框只給「封存」。
6. 我在私人帳本「日本旅遊」借過明哥 $500 → 也能刪除，那筆借出照「撤銷」處理。

### 範圍外

- **複製或合併到別的帳本**（開發者提的「退出時把借還複製到別的帳本」也在內）：等複製功能（2c §8「封存時的消費規整」）一起做，到時候在退出與刪除對話框加上這個選項。
- **隱藏帳本**：要記每個人各自隱藏了哪些帳本，需要改 schema，另案。
- **封存的帳本退出**：維持不能退出（2c §8「封存帳本仍可退出」不做）。要退出就先取消封存。
- 借還頁的列顯示名稱與分類、共享帳本其他成員看到的借出標籤（3i 已知限制）：另案。

## 3. 資料模型

**不改 schema。** 改的是規則：

- 餘額查詢加一個條件：交易所在帳本的成員裡有帳戶主人（決策 186）。
- 刪除帳本前要先處理資料庫的關聯：往來紀錄 → 交易（`DebtEntry.transactionId`）、往來紀錄 → 分帳（`DebtEntry.splitId`）、分帳 → 帳本（`Split.ledgerId`）都是 `Restrict`。做法：撤銷後，把指向這本帳本的往來紀錄（此時都已撤銷）的 `transactionId`、`splitId` 設成 `null`，刪掉分帳，再刪帳本。往來紀錄本身留著，對方的待確認、配對紀錄都還在。**如果做不到、一定要改 schema，停下來問開發者。**

## 4. API

### 4.1 `POST /ledgers/{ledgerId}/unarchive`（新）

- 權限：擁有者（`LedgerAccessGuard` 的 OWNER，加 `@AllowOnArchived`）。不是成員 404，非擁有者 403。
- 沒封存 → 409 `LEDGER_NOT_ARCHIVED`。成功回 `LedgerDetail`。

### 4.2 `GET /ledgers/{ledgerId}/removal-preview`（新）

任何成員都能查（檢視者也要能看退出的影響）；封存的帳本也能查。

```ts
interface LedgerRemovalPreview {
  accounts: Array<{
    accountId: string;
    name: string;
    isTemporary: boolean;
    balance: Cents; // 現在
    balanceAfter: Cents; // 退出或刪除後
  }>; // 只列有變化的帳戶
  counterparties: Array<{
    counterpartyId: string;
    displayName: string;
    linked: boolean; // 連動中：撤銷會送給對方確認
    balance: Cents;
    balanceAfter: Cents;
  }>; // 只列我在這本帳本有借還的對象
  withdrawsDebts: boolean; // 退出或刪除時會撤銷借還（決策 188）
  leave: {
    allowed: boolean;
    blockedBy: 'PERSONAL_LEDGER' | 'LAST_OWNER' | 'LEDGER_ARCHIVED' | null;
  };
  delete: {
    allowed: boolean;
    blockedBy: 'NOT_OWNER' | 'HAS_OTHER_MEMBERS' | null;
  };
}
```

- 退出與刪除對我的影響是同一份數字（刪除只在只剩我時允許，兩者扣掉的交易相同）。
- 只回呼叫者自己的帳戶與對象，不回別人的。

### 4.3 `DELETE /ledgers/{ledgerId}/members/{userId}`

- 退出自己：多一個 query `withdrawDebts`。我在這本帳本有借還而沒帶 `true` → 409 `DEBT_WITHDRAWAL_REQUIRED`；帶了 → 撤銷後退出，同一個資料庫交易。
- 移除別人：對方在這本帳本有記到他帳戶的有效交易 → 409 `MEMBER_HAS_TRANSACTIONS`（決策 190）。
- 其他規則（最後一位擁有者、封存不能退出）照舊。

### 4.4 `DELETE /ledgers/{ledgerId}`

- 還有別的成員 → 409 `LEDGER_HAS_OTHER_MEMBERS`。
- 拿掉「有別人的交易」（`LEDGER_HAS_OTHERS_TRANSACTIONS`）與「有借還交易」（`LEDGER_HAS_DEBT_TRANSACTIONS`）兩個限制，改成：有我的借還而沒帶 `withdrawDebts=true` → 409 `DEBT_WITHDRAWAL_REQUIRED`。
- 保險：別人（已退出的人）在這本帳本還有**沒撤銷**的往來紀錄（3j 以前退出的舊資料）→ 409 `LEDGER_HAS_DEBT_TRANSACTIONS`，不替別人撤銷。
- `confirm`（帳本名稱）照舊必填。

### 4.5 借還的寫入（決策 183）

`PATCH /debt-entries/{id}`、`DELETE /debt-entries/{id}`、`POST /debt-proposals/{id}/accept`（修改、撤銷兩種）多 404／403／409 三種錯誤，條件同 `assertLedgerWritable`。

### 4.6 帳戶餘額（決策 186）

`GET /accounts` 的 `balance` 改成只算帳戶主人是成員的帳本。回應格式不變。帳戶「有沒有被用過」（能不能刪）照舊看所有交易：退出的帳本裡還有交易時，帳戶照樣刪不掉（3h 的 409）。

### 4.7 shared

- 新型別 `LedgerRemovalPreview`。
- 新錯誤碼：`LEDGER_NOT_ARCHIVED`、`LEDGER_HAS_OTHER_MEMBERS`、`DEBT_WITHDRAWAL_REQUIRED`、`MEMBER_HAS_TRANSACTIONS`。

## 5. 成功條件

- **SC-J1**（借還寫入權）：降為檢視者後 `PATCH { amount }`、`PATCH { note }`、`DELETE` → 403；帳本封存後 → 409 `LEDGER_ARCHIVED`；接受對方的修改、撤銷 → 同上；拒絕 → 200。失敗時往來紀錄、交易、提議都不變。
- **SC-J2**（取消封存）：擁有者 → 200，之後能記帳、`GET /ledgers` 預設就列出；編輯者 → 403；不是成員 → 404；沒封存 → 409 `LEDGER_NOT_ARCHIVED`。
- **SC-J3**（餘額）：小華在共享帳本用現金記支出 $800 → 小華現金 −800；小華退出 → 小華現金回到原值，我照樣讀得到那筆交易；小華重新被加入 → 又是 −800。別人記到小華臨時帳戶的，同樣跟著退出與加入變化。
- **SC-J4**（退出與借還）：小華在這本帳本有借出 → 不帶 `withdrawDebts` 退出 → 409，什麼都沒變；帶 `true` → 借出被撤銷、連動的對象收到撤銷提議、小華退出；帳本裡小華記的一般交易一筆都沒少。
- **SC-J5**（預覽）：預覽的 `balanceAfter` 等於實際退出或刪除後 `GET /accounts`、對象餘額的數字。
- **SC-J6**（刪除）：還有別的成員 → 409 `LEDGER_HAS_OTHER_MEMBERS`；別人已退出、留下交易 → 204，他們的帳戶餘額不變；私人帳本有借出、還款含分支、分帳 → 帶 `withdrawDebts=true` 後 204，連動的對象收到撤銷提議，對方的往來紀錄不變；以前撤銷過的借還不擋。
- **SC-J7**（移除成員）：對方在這本帳本有記到他帳戶的交易 → 409 `MEMBER_HAS_TRANSACTIONS`；沒有 → 204。
- **SC-J8**（隔離）：不是成員查預覽、取消封存 → 404；預覽只含呼叫者自己的帳戶與對象；`withdrawDebts` 只撤銷呼叫者自己的往來紀錄，絕不撤銷別人的。
- **SC-J9**（畫面）：§1 的 1～6 做得到。元件測試涵蓋：刪除對話框的 3 種樣子（能刪、還有成員、已封存不顯示封存）、還有成員時按「退出」切到退出的影響畫面、刪除要打對名稱才能按、退出對話框有沒有借還的兩種按鈕、封存不用打名稱、取消封存只有擁有者看得到、借還頁的修改與撤銷照每一筆的帳本判斷。

## 6. 測試策略

- **隔離測試**（協調者先寫、先紅）：SC-J1、SC-J8，與 SC-J2 的權限部分。
- **單元測試**：餘額只算成員帳本、預覽的扣除與實際執行用同一個函式、刪除前的關聯處理。
- **API e2e**：SC-J1～J8。
- **Web**：元件測試涵蓋 SC-J9；Web e2e 一條主線：記一筆共享帳本支出 → 另一個成員退出（看到影響）→ 餘額變化 → 剩自己後刪除帳本（看到影響、打名稱）→ 帳本消失。

## 7. 界線

- **Always**：退出、刪除、撤銷借還在同一個資料庫交易裡完成；預覽與執行用同一套計算；只撤銷呼叫者自己的往來紀錄。
- **Ask first**：改 schema（例如關聯改成 `SetNull`）；替別人撤銷；退出或刪除時動到別人記的交易。
- **Never**：刪除帳本時刪掉往來紀錄本身（對方的待確認會跟著消失）；前端自己算預覽的數字。
