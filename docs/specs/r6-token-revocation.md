## 0. 假設

開發者 2026-11-18 回「核可」以下 10 條。

1. **範圍**：只處理「登出後，這一次登入的憑證失效」。不做裝置清單、「登出所有裝置」、改密碼。
2. **機制 C**：新增登入紀錄表，每次登入存 1 筆，欄位有 id、使用者、到期時間、撤銷時間。憑證多帶 `sid`，指向它屬於哪一筆登入。後端每次收到請求，確認這一筆登入沒有被撤銷、也沒有過期。
3. **新增 API**：`POST /api/auth/logout`，只撤銷目前這一筆登入，成功回 204。
4. **效期**：固定 7 天，使用期間不自動延長。仍可用 `JWT_EXPIRES_IN` 調整。啟動時檢查這個設定，必須是正值、單位正確。
5. **接受的風險**（寫進 spec）：
   - 憑證被偷，而你一直沒登出，它最多還能用 7 天。
   - 裝置遺失時，現在沒辦法從別台裝置撤銷它的登入。「登出所有裝置」記成之後的需求。
6. **舊憑證**：部署後，沒有 `sid` 的舊憑證一律拒絕，每個人重新登入 1 次。
7. **資料庫故障**：回 5xx，不回 401。資料庫短暫出錯時不會把所有人登出。
8. **網頁登出**：
   - 先呼叫登出 API，最多等一段固定時間。失敗或逾時都照樣清掉瀏覽器存的憑證。
   - 收到 401 時只清瀏覽器存的憑證，不再呼叫登出 API。
   - 舊請求晚到的回應，不能清掉新登入的憑證。
   - 網頁的部分派給 Codex。
9. **清理**：每次有人登入成功時，順便刪掉少量已過期的紀錄，不加排程套件。安全檢查本身就拒絕過期紀錄，不靠清理準時。
10. **效能**：每個需要登入的請求多 1 次主鍵查詢。以目前流量可以接受，這次不量測。

## 1. 目標與成功樣貌

我在網咖的電腦登入記帳網頁，用完按「登出」。現在這樣做之後，有人從瀏覽器的 localStorage（瀏覽器內建的本機儲存）抄走那張憑證，接下來 7 天仍能讀寫我的帳本。本步讓「登出」真的在伺服器端生效。

做法：每次登入，後端在登入紀錄表新增 1 筆，把這筆的 id 當成 `sid` 放進憑證。之後每個請求，guard（守門程式，每個請求進到業務邏輯前先經過它）除了驗簽章，還要查這筆紀錄。按登出時，後端把這筆標成「已撤銷」，這張憑證之後一律回 401。

例子：

1. 我在手機網頁和桌機各登入 1 次。後端有 2 筆登入紀錄，2 張憑證的 `sid` 不同。
2. 我在桌機按「登出」。網頁送 `POST /api/auth/logout`，後端撤銷桌機那 1 筆，回 204。網頁清掉本機憑證，回到登入頁。
3. 有人拿桌機那張舊憑證打 `/api/users/me` → 401。
4. 手機那張憑證不受影響，照常記帳。
5. 7 天後手機那張憑證到期 → 401，網頁回到登入頁，重新登入。

### 範圍外

- 「登出所有裝置」、裝置清單、改密碼、忘記密碼：之後的需求（假設 1、5）。
- 使用期間自動延長效期、續期憑證（refresh token）：不做（假設 4）。
- 改用 httpOnly cookie（腳本讀不到的 cookie）存憑證：`apps/web/src/lib/token-storage.ts:4` 記為未來工作，本步不動。
- 多分頁同步登出：桌機開 2 個分頁，在 A 分頁登出，B 分頁下一個請求收到 401 後才回登入頁。不另外做分頁間廣播。
- 行動 App：尚未建立。App 建立時照本 spec 的登出契約。

## 3. 資料模型

新增 1 張表，需要 1 個 Prisma migration。`User` 加反向關聯，不改其他現有的表。

```prisma
/// 一次登入（R6）。JWT 的 sid 指向這一列；登出時填 revokedAt。
model AuthSession {
  id         String    @id @default(uuid())
  userId     String
  expiresAt  DateTime  // 和 JWT 的 exp 同一個截止時間（決策 375）
  revokedAt  DateTime? // 有值＝已登出
  createdAt  DateTime  @default(now())
  updatedAt  DateTime  @updatedAt

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId])
  @@index([expiresAt])
}
```

- 不存裝置名稱、IP、最後使用時間。之後做裝置清單時再加。
- `userId` 的索引給之後「登出所有裝置」用；`expiresAt` 的索引給清理用（決策 380）。
- `onDelete: Cascade`：帳號真的刪除時紀錄一起刪。目前沒有刪帳號功能，這是預留的正確行為。
- 表名與欄位最終寫法由 plan 定，不改上面的語意。

## 5. 成功條件

API 端的 SC 用 API e2e（真的 PostgreSQL）驗證，進 CI。網頁端的 SC 用 Vitest 與 Playwright，進 CI。

**每一條「被拒絕」的測試，都要同時斷言狀態碼和「沒有讀到或改到資料」。** 不能只看狀態碼。

- **SC-TV1**（SEC-2 本體）：登入 → 打 `/api/users/me` 得 200 → 登出得 204 → 同一張憑證再打 `/api/users/me` 得 401，回應不含使用者資料。
- **SC-TV2**（多登入互不影響）：同一個人登入 2 次，得到憑證 A、B。登出 A 後：A 打 `/users/me` 得 401；B 得 200，也能新增 1 筆交易。
- **SC-TV3**（`sid` 唯一）：同一個人在同一秒內登入 2 次，2 張憑證的 `sid` 不同，資料表有 2 筆。
- **SC-TV4**（重複與無效登出）：
  1. 同一張憑證登出 2 次 → 第 2 次 401。
  2. 不帶憑證、亂碼憑證 → 401。
  3. 以上都不改動任何紀錄的 `revokedAt`。
- **SC-TV5**（跨使用者）：用正確密鑰簽一張 `sub` 是 B、`sid` 是 A 的登入紀錄的憑證 → 401，回應不含 A 或 B 的資料。A 的紀錄沒有被撤銷。
- **SC-TV6**（格式錯誤與舊憑證）：用正確密鑰簽以下憑證，打 `/users/me` 全部 401：
  1. 沒有 `sid`（等同部署前的舊憑證）。
  2. 沒有 `exp`。
  3. `sid`、`sub` 不是字串，或是空字串。
  4. `sid` 是不存在的 UUID。
- **SC-TV7**（過期）：
  1. 把紀錄的 `expiresAt` 改成過去，憑證本身還沒到期 → 401。
  2. 憑證的 `exp` 已過、紀錄還沒到期 → 401。
- **SC-TV8**（重啟後仍有效）：登出後關掉 API，再起一個新的 API 實例 → 舊憑證仍 401。
- **SC-TV9**（資料庫故障）：guard 單元測試讓查詢丟錯 → 結果是 500 類錯誤，不是 401，請求沒有放行。
- **SC-TV10**（簽發與效期）：
  1. 登入後，憑證的 `exp` 和紀錄的 `expiresAt` 是同一秒。
  2. `JWT_EXPIRES_IN` 為 `0d`、`-1d`、`7`、`7x`、空字串時，環境變數驗證失敗；`7d`、`24h`、`30m`、`45s` 通過。
- **SC-TV11**（清理）：
  1. 登入成功後，已過期的紀錄被刪掉（不分使用者）。
  2. 已撤銷但未到期的紀錄還在。
  3. 清理丟錯時，登入仍回 200 和憑證。
- **SC-TV12**（契約）：OpenAPI 列出 `POST /auth/logout`，標註 bearer 認證、204、401。登入回應格式和現在相同。
- **SC-TV13**（網頁登出，Vitest）：
  1. 按登出時，用點擊當下的憑證送登出請求。
  2. 登出 API 成功、失敗、5 秒逾時，3 種情況本機都清乾淨：憑證、首頁編輯狀態、作用中帳本、查詢快取。
  3. 等待期間再按登出，只送 1 次。
- **SC-TV14**（網頁 401，Vitest）：
  1. 一般請求收到 401 → 本機清乾淨，沒有送登出請求。
  2. 舊憑證的請求晚到 401 → 新憑證不被清掉（現有 `apps/web/src/lib/api-client.test.ts:107` 保留）。
  3. 登出請求晚到的回應 → 之後登入的新憑證不被清掉。
- **SC-TV15**（端對端，Playwright）：登入 → 從 localStorage 讀出憑證 → 按登出 → 回到登入頁 → 用剛才的憑證直接打 `/api/users/me` 得 401。
- **SC-TV16**（回歸）：`pnpm lint`、`typecheck`、`test`、`build`、`format:check` 全綠；兩套 e2e 全綠。決策 384 (b) 的 3 個測試改成真登入，原本的斷言不放寬。

## 7. 界線

- **Always**：guard 每個請求都查登入紀錄；查紀錄時比對 `userId` 與 `sub`；登出只撤銷目前的 `sid`；資料庫故障回 5xx；e2e 用真的登入取得憑證。
- **Ask first**：「登出所有裝置」、裝置清單、改密碼；改用 cookie 存憑證；加續期憑證或自動延長效期；加快取；加清理排程；加套件；改 CI。
- **Never**：guard 退回只驗簽章就放行；把資料庫錯誤轉成 401；資料表存完整憑證；用 body 或路徑參數指定要撤銷的 `sid`；網頁收到 401 時呼叫登出 API；把「伺服器已撤銷」顯示在登出失敗的情況；放寬既有測試的斷言來讓它通過。
