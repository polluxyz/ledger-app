# 工作區交接

接手時讀本頁與自己工作區的交接檔。各區維護自己的現況、下一步、待決事項與操作限制。驗收明細寫進 plan 或 PR。交接更新併入該工作的最後一個 PR。

| 工作區                                  | 現況與下一步                                                            | 測試資料庫           |
| --------------------------------------- | ----------------------------------------------------------------------- | -------------------- |
| [main](handoff/main.md)                 | 統整方向、優先順序、跨線相依與共用資源。建立任務並指派工作區與 worker。 | `ledger_test`        |
| [ai-4a](handoff/ai-4a.md)               | Haiku 的程式已合併。先做真實模型驗收，再做語音現場驗收。                | `ledger_ai_test`     |
| [review-specs](handoff/review-specs.md) | R6 已部署。R5 等開發者決定正式部署位置。                                | `ledger_review_test` |

各區負責自己的規劃、執行、測試與驗收。需要開發者決定時，在該區直接討論。規格核可、跨線相依解除、驗收完成或 PR 合併時，向 main 回報結果、驗證證據與剩餘事項。派工、額度、換 session 與每週整理見[多代理派工與交接](orca-multi-agent.md)。

## 共用資源與操作限制

- 新編號由 main 統一分配。目前下一個決策號為 407，下一個 W 號為 W307。R5 保留決策 385～394、W300～W306 與 `SC-BK`。
- Web 端對端測試使用固定連接埠 3100、5273。同時只跑一組。API 端對端測試使用不同資料庫時可並行。
- 共用檔案有衝突時，由後合併的一方更新分支並解決。dev 環境一律由主工作區部署，步驟見 [main](handoff/main.md)。
- 邀請其他使用者測試之前，先完成隱私政策、AI 使用告知與同意，並向模型供應商確認用途。見[新分類規格 §8](specs/phase-4a-ai-new-category.md)。

已結案的首頁與統計工作見 [stats-2j](handoff/stats-2j.md)。查舊編號或設計偏好時，再讀[歷次分配與開發者偏好](https://github.com/polluxyz/ledger-app/blob/d190f4fd76c6f261e0bd84ff68d43eb46b2c4f25/docs/handoff.md)。
