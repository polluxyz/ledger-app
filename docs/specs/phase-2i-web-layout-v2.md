## 1. 目標與成功樣貌

2h 定下了黑金視覺，但版面還有四個問題：

| 問題               | 現況                                                                     |
| ------------------ | ------------------------------------------------------------------------ |
| 側欄收合是瞬間切換 | 沒有動畫；帳本區塊從兩行字變成方塊，下面的導覽 icon 跟著往上跳           |
| 收合鈕會換位置     | 展開時在站名右邊，收合後 72px 放不下                                     |
| 首頁塞太多         | 統計卡、篩選、20 筆交易、新增表單、帳戶餘額都在同一頁                    |
| 中間區貼齊左邊     | 管理頁內容只有 600–800px 寬，右邊一大片空白；2560px 時交易列欄位隔得很遠 |

做完之後：

- **左側欄**：開合有動畫（約 220ms）。收合前後，每個 icon 的位置（上下與左右）完全相同。
- **使用者選單**：點側欄底部的使用者，浮出「設定、個人資料、登出」。點「設定」再浮出設定選單，裡面是外觀（跟隨系統／淺色／深色）。
- **帳本切換器**移到總覽與交易頁的標題上方，做成一眼看得出「可以點」的按鈕。側欄不再有帳本區塊。
- **首頁是 dashboard**：統計卡、最近 5 筆交易、帳戶餘額。交易表格、篩選、分頁搬到新的「交易」分頁 `/transactions`。
- **頁面分兩類**：
  - **記帳頁**（總覽、交易）：有右側欄，預設打開、可以收起、開合有動畫。裡面是「新增一筆交易」，點一筆交易就換成「編輯交易」。標題列最右邊有「＋ 新增交易」。
  - **管理頁**（帳本、帳本明細、帳戶、分類、個人資料）：沒有右側欄，也沒有「＋ 新增交易」。
- **中間區置中**：內容在左側欄與右側欄（管理頁則是視窗右緣）之間置中，側欄開合時跟著平滑移動。記帳頁用寬的最大寬度，管理頁用窄的。

## 3. 可驗證的成功條件

### SC-31｜左側欄

1. 收合前後，品牌、每個導覽 icon、收合鈕 icon、使用者頭像的中心座標差 ≤ 0.5px。
2. 開合有寬度動畫，時間 250–350ms（修訂 6：「抽屜」）；文字跟著往左滑出並淡出。系統設定「減少動態效果」時沒有動畫（修訂 7）。
3. 收合時文字仍然視覺隱藏（不是移除），無障礙名稱不變。
4. 側欄不再有帳本區塊、深淺色切換列、「個人資料」連結（分別移到頁首與使用者選單）。
5. 導覽多一個「交易」連結（`/transactions`）。
6. 901–1199px：側欄預設收合，「展開側欄」可以按；展開後浮在內容上（中間區不移動），點連結、Esc、點外面都會收回。≤ 900px：☰ 可以展開側欄（沿用 2h）。

### SC-32｜使用者選單與設定彈窗

1. 點側欄底部的使用者，浮出「設定、個人資料、登出」。按鈕的 `aria-expanded` 跟著變。「登出」仍是名稱為「登出」的按鈕（既有測試用 `getByRole('button', { name: '登出' })` 找它）。
2. 點「設定」關閉浮出區塊並**跳出彈窗**（modal `dialog`，名稱「設定」）。彈窗裡的「外觀」是三張可以點的預覽卡（跟隨系統／淺色／深色，`role="radio"`），選了立刻生效並記住（沿用 SC-29）。之後的設定也放在這個彈窗。
3. 鍵盤可以完成全部操作：Enter／Space 開啟、Tab 或 ↑↓ 移動；彈窗裡方向鍵在三張卡之間移動；Esc 關閉彈窗並把焦點送回觸發按鈕。點選單外面會關閉選單。
4. 側欄收合時選單仍然可用，浮在側欄右邊。

### SC-33｜帳本切換器在頁首

1. 總覽與交易頁的上方橫條左邊是帳本切換器，外觀是帶邊框的按鈕樣式（帳本 icon、帳本名稱、私人／共享標籤、向下箭頭），滑過與聚焦時有明顯變化。無障礙名稱是「作用中帳本」。
2. 只有一本帳本時顯示成同樣外觀但**沒有**向下箭頭、不能點（沿用 2h「只有一本時是文字」的行為）。
3. 切換後，該頁資料與右側欄的表單同時換成新帳本。
4. 管理頁沒有帳本切換器。

### SC-34｜首頁 dashboard 與交易分頁

1. `/` 登入後顯示：頁首、3 張「即將推出」統計卡、最近 5 筆交易（附「查看全部」連到 `/transactions`）、帳戶餘額（附「管理」連到 `/accounts`）。
2. `/transactions` 是 2h 首頁的交易表格：篩選、依日期分組的列表、分頁、鉛筆與垃圾桶。行為與 2h 相同（SC-25.2～SC-25.6 移到這一頁）。
3. `/transactions` 需要登入（掛在 `ProtectedRoute` 之下）。
4. 1440×900 的 `/transactions` 首屏至少看得到 10 筆交易（SC-24.3 移到這一頁）。

### SC-35｜右側欄

1. 只有總覽與交易頁有右側欄，**預設關閉**。管理頁沒有右側欄，也沒有「＋ 新增交易」。
2. 打開、收起都有抽屜式動畫（250–350ms）：欄位變寬的同時內容從右邊滑入；減少動態效果時沒有動畫。開關狀態不記憶，換頁就關。
3. 總覽與交易頁上方橫條的右邊有「＋ 新增交易」。按下去右側欄打開並把焦點送到金額欄；已經打開時直接把焦點送到金額欄。
4. 點交易頁或 dashboard 的一筆交易，右側欄打開並換成「編輯交易」（非 modal 的 `dialog`，名稱不變）。儲存、取消、Esc 回到新增，焦點回到觸發的元素（沿用 SC-25.3）。
5. 新增表單的群組名稱仍是「新增一筆交易」；右側欄標題旁的關閉鈕名稱是「收起新增面板」。
6. ≤ 900px 右側欄是蓋在內容上的抽屜，預設關閉，不造成橫向捲動。

### SC-36｜中間區置中與對齊

1. ≥ 901px 時，中間內容在可用空間內置中：記帳頁右側欄打開時是左右兩側欄之間，其他情況是左側欄與視窗右緣之間。內容左右兩邊的留白差 ≤ 1px。
2. 左側欄或右側欄開合後，內容仍然置中，而且移動是連續的動畫，不是瞬間跳過去。
3. 所有頁面的內容最大寬度都是 `--content-max`（72rem）。包裝是透明的，沒有底色與框。
4. 右側欄關閉時，總覽、交易、帳本、帳本明細、帳戶、分類、個人資料的標題左緣相同（誤差 ≤ 1px；即 2h 的 SC-24.5）。

### SC-37｜相容與測試

1. e2e 只改導航步驟（§6 表格列出每一處），**斷言一行不改**。
2. 單元測試只增不減；修改選取方式的每一處列在 PR 描述（沿用 SC-27.2）。
3. 新增測試：使用者選單與設定選單（開關、鍵盤、Esc 焦點回歸）、右側欄開合與記憶、只在記帳頁出現、「＋ 新增交易」的焦點、頁首帳本切換器、dashboard 最近 5 筆、`/transactions` 的路由保護、901–1199px 的浮動展開。e2e 新增 SC-31.1、SC-35.2、SC-36.1、SC-36.2 的量測。
4. `pnpm lint`、`typecheck`、`test`、`format:check`、`build`、兩套 e2e 全綠。不新增任何 npm 相依。
5. 沿用：SC-24.6（375–2560px 不橫向捲動）、SC-26.7（焦點框看得見）、SC-29（深淺色與不閃）。

### SC-38｜上方橫條（修訂 3、4）

1. 所有登入頁的中間區最上方有一條橫條，捲動時固定在上方。橫條的內容與下方的包裝同寬、左右對齊（72rem）。
2. 橫條左邊：總覽與交易頁放帳本切換器；帳本明細頁放「← 帳本」返回連結；其他頁面先空著，預留給之後的功能。
3. 橫條右邊：**頁面層級的主要按鈕**——總覽與交易的「＋ 新增交易」、帳戶的「新增帳戶」、帳本的「建立帳本」、帳本明細的「改名」。無障礙名稱與 `aria-expanded` 都不變；往下展開的表單仍然出現在標題下方（2h §4.7）。
4. 只屬於某一區塊的按鈕留在原地：分類卡片裡的「新增支出分類／新增收入分類」、成員區塊的「加入成員」。
5. 標題上方不再有任何一行字（帳本切換器與返回連結都移進橫條），所以每一頁的標題高度也相同。

### 4.2 版面結構

```
記帳頁（總覽、交易）
┌────────┬──────────────────────────────┬───────────┐
│ 側欄   │        中間區（置中）          │  右側欄    │
│ 240/72 │   ┌────────────────────┐     │  360 / 0  │
│        │   │ 內容 max 72rem     │     │           │
└────────┴──────────────────────────────┴───────────┘

管理頁（帳本、帳本明細、帳戶、分類、個人資料）
┌────────┬──────────────────────────────────────────┐
│ 側欄   │              中間區（置中）                │
│ 240/72 │        ┌──────────────────┐              │
│        │        │ 內容 max 52rem   │              │
└────────┴──────────────────────────────────────────┘
```

- 外殼是三欄 grid：`grid-template-columns: var(--sidebar-current) minmax(0, 1fr) var(--panel-current)`。管理頁的第三欄固定是 0。
- 兩側欄寬度變化時，瀏覽器對 `grid-template-columns` 做過渡，中間區自然跟著移動。中間內容用 `margin-inline: auto` 加最大寬度置中。
- 右側欄的**欄位**屬於外殼，**內容**屬於頁面：記帳頁把面板內容用 React portal 放進外殼的右側欄位置，並向 `RightPanelProvider` 登記「這一頁有右側欄」。沒有登記的頁面，第三欄寬度就是 0。這樣管理頁不需要知道右側欄的存在，記帳頁也不需要自己處理三欄版面。
- 兩個側欄都用 `position: sticky; height: 100vh`，中間區自己捲動。

### 4.3 左側欄：icon 不動的做法

- 每一列固定高度（品牌 48px、導覽 40px、底部各列 40px）。沒有任何一列在收合時改變高度。
- icon 固定在離左邊同一個距離。收合只是把側欄寬度從 240px 縮到 72px，右邊的文字被裁掉並淡出（`opacity`，約 160ms）。
- 選中標示（底色與左緣金線）的右邊界跟著寬度一起縮。
- 由上到下：品牌 → 導覽（首頁、交易、帳本、帳戶、分類）→ 彈性空白 → 收合側欄 → 使用者。
- 901–1199px：預設收合，但收合鈕仍然顯示（假設 4）。展開時側欄浮在內容上（寬 240px、帶陰影），外殼的第一欄維持 72px，所以中間區不移動。點連結、Esc、點外面收回；不寫進 localStorage。
- ≤ 900px：沿用 2h 的 ☰。

### 4.4 使用者選單

- 觸發按鈕是整個使用者列（頭像＋名字），無障礙名稱是「〈名字〉的選單」。email 仍然只放在 `title`（2h 的決定，避免 `getByText(email)` 撞到成員列表）。
- 第一層：設定（有向右的箭頭，表示還有下一層）、個人資料（連結）、登出（按鈕，名稱仍是「登出」）。
- 第二層「設定選單」浮在第一層的右邊；空間不夠時疊在第一層上方。
- 用**揭露式（disclosure）**而不是 ARIA `menu`：觸發按鈕帶 `aria-expanded`，浮出區塊裡是原生 `<button>`（設定、登出）、`<a>`（個人資料）與外觀的 radio 群組。原因：`role="menuitem"` 會讓「登出」不再是 button，既有 e2e 與單元測試的 `getByRole('button', { name: '登出' })` 就得改斷言。另外加上 ↑↓、→、←、Esc 的鍵盤操作。不引用任何選單套件。

### 4.5 右側欄

- 標題「新增一筆交易」旁邊有收起鈕（`»` 圖示，名稱「收起新增面板」）。收起後寬度 0，不留窄條——要打開用頁首的「＋ 新增交易」。
- 編輯模式沿用 2h 的 `Dialog` panel 變體與 `TransactionDialog`。
- 新增與編輯互斥（沿用 2h 的 D9）：兩張表單的欄位標籤相同，同時存在會讓 `getByLabelText` 對到兩個。

### 4.6 頁首的帳本切換器

- `PageHeader` 的 `context` 那一行（2h 顯示「📖 日常開銷・私人帳本」）在記帳頁改放 `LedgerSwitcher`。
- **外觀要看得出可以點**（假設 7）：
  - 帶邊框的膠囊形按鈕：帳本 icon、帳本名稱（粗體）、「私人／共享」小標籤、向下箭頭。
  - 滑過：邊框與文字轉成強調色；聚焦：沿用全站的焦點框。
  - 仍然是原生 `<select>` 疊在按鈕外觀上（2h 的做法），鍵盤與螢幕閱讀器行為不變。
  - 只有一本帳本時：同樣的膠囊外觀，但沒有箭頭、沒有滑過效果。
- `LedgerSwitcher` 不再有側欄收合狀態的樣式，相關 CSS 移除。

- 2j 的圖表加在第三列，本步不放佔位。

### 4.8 中間區寬度

所有頁面同一個 `--content-max: 72rem`（修訂 2）。包裝是透明的（修訂 1），只負責置中與寬度；卡片仍然是各自的卡片。上方橫條的內容也用同一個寬度（修訂 3）。

### 4.9 動畫

- 時間：側欄與右側欄的寬度 320ms，文字跟著滑出並淡出（同 320ms），右側欄內容從右邊滑入；選單 160ms。緩動 `cubic-bezier(.4, 0, .2, 1)`（前後都慢，看得到過程）。寫成 `--motion-*` token（修訂 6）。
- `prefers-reduced-motion: reduce` 時全部 0ms。
- 只用 CSS `transition`。`grid-template-columns` 的過渡在 Chrome 107+、Firefox 66+、Safari 16+ 都支援；不支援的瀏覽器只是沒有動畫，版面照樣正確。

### 4.11 第二輪修訂（2026-09-23，開發者看過 PR #56 的畫面後）

開發者的回饋（原文）：

> 這個部分的間距太短（帳本切換器與標題）／每個分頁的標題(總覽 交易 帳本...) 都幫我對齊 寬也要盡量一致 可以在中間的區塊多一個包裝 把這些內容放在這個包裝中 帳本選擇器則是上方的橫條(橫條的部分未來應該會新增東西 目前先保留)／然後頁面預設不要顯示右側交易欄位 使用者點選新增交易在跳出即可／左右兩側的bar都沒有動畫 我希望可以看到開收的過程 像是抽屜收進去的感覺／設定點進去應該要跳出彈窗才對

樣版 `docs/artifacts/step-2i-03-revision.html` 上的選擇（原文）：

> 1. 中間的包裝長什麼樣子→透明包裝（每個頁面的標題記得要對齊 使用體驗上會有差）；2. 包裝的寬度（每一頁都一樣）→72rem；3. 上方的橫條→對齊包裝；4. 「＋ 新增交易」放哪裡→橫條右邊（並且 新增帳戶 新增帳本 那些選項也比照辦理）；5. 右側欄打開時→推開內容；6. 開合動畫→抽屜；7. 系統設了「減少動畫」時→照系統設定；8. 設定彈窗→照樣版。其餘照樣版。

**「看不到動畫」的調查**：實測當時的版本，左側欄收合時寬度經過 12 個中間值、右側欄 13 個，動畫是有的。看不到的原因可能是 Windows 關了「動畫效果」（瀏覽器因此回報 `prefers-reduced-motion: reduce`，我們把動畫時間設成 0），或 220ms 加上先快後慢的緩動，大約 100ms 就收掉大半。修訂 6 改成 320ms、前後都慢的緩動，並讓文字與右側欄內容一起滑動；修訂 7 維持尊重系統設定。

**被取代的條文**：假設 1（預設打開、記憶）、假設 10 與 §4.8（兩種寬度）、SC-32.2（第二層浮出選單）、SC-35.1–35.3、SC-36.3–36.4、§4.6（切換器在標題上方）、§4.9 的 220ms。

**協調者的解讀**：「新增帳戶、新增帳本那些選項也比照辦理」解讀為「標題列右邊的頁面層級按鈕全部移到橫條右邊」，所以帳本明細的「改名」也一起移；只屬於某一區塊的按鈕（分類卡片、成員區塊）不動。

## 7. 界線

**Always**

- 無障礙名稱不改（新加的「交易」連結與選單除外）。
- 收合時文字用視覺隱藏，不用 `display: none`。
- 動畫尊重 `prefers-reduced-motion`。
- 顏色、間距、動畫時間全部來自 `global.css` 的 token。

**Ask first**

- 假設 14 以外的任何 e2e 斷言修改。
- 新增 npm 相依（本步預期為零）。
- 任何後端或 API 的變動（本步預期為零；dashboard 的數字留給 2j）。

**Never**

- 在前端加總金額或算統計（單一後端原則）。
- 為了讓 e2e 不用改而在首頁保留舊表格（提案 D7-B 已否決）。
