## 1. 目標與成功樣貌

2j 把資產趨勢圖放在首頁最上面，佔掉整個寬度，3 張收支卡被擠到下面。下面的卡片又各自獨立：最近交易、標註、帳戶各一張，帳戶全部列出沒有上限。結果是第一眼看到的是一張大圖，不是這個月的數字。

本步重排首頁，不新增資料。順便修 3 個首頁上現有的前端問題（決策 306～308）。

- **最上面是本月 3 張卡**（支出、收入、結餘），規則照 2j W201。
- **中間一排兩張卡**：左邊「最近｜標註」合成一張卡，用分頁切換；右邊是較小的資產趨勢卡。
- **下面是「我的」**：資產卡（總額、本月支出分類、帳戶）與借還卡並排。

用一個例子貫穿全篇。使用者有 12 個帳戶，在「日常」帳本這個月有 15 個支出分類，標註了 2 筆交易，跟 7 個人有未結清的借還，另有 1 本共享帳本還沒指向對象。

桌機（內容區寬度放得下兩欄）：

```text
[ 本月支出 ] [ 本月收入 ] [ 結餘 ]
[ 最近｜標註 2           ] [ 資產趨勢（12 個月） ]
我的
[ 資產                 管理 ] [ 借還               全部 → ]
  $58,190   本月支出 · 日常 明細 →   (人) → $500
            ■ 晚餐 ……                (人) ← $1,200
            （先列 5 類，全部 15 類）  ……（5 人）
  （帳戶全部列出）                     全部 7 人 →
                                       （未指向的共享帳本）
```

手機 390px：同樣的順序排成一欄。

### 範圍外

- 新的 API、新的統計數字、新的資料欄位。（2l 修訂：新增版面資料表與端點，見 [2l](phase-2l-home-layout.md) §3、§4）
- B、C 兩版：只留在預覽頁當紀錄，不實作。
- 統計頁的配色設定；配色偏好跨裝置同步。
- 借還依金額排序（要改 API，見 §10 第 4 項）。
- 資產的逐月明細頁。
- 替標註列新增複製、刪除。

### 已知限制

- 資產總額取資產趨勢最後一個月（本月月底）的值（決策 301）。如果有日期在下個月以後的交易，它和帳戶頁的餘額會不一樣。
- 共享帳本的分類段是整本帳本的支出，資產卡其他內容是「我」的。分類段標上帳本名稱與「本月」來區分（決策 303）。
- 借還卡的 5 人依名字排序，不是欠最多的 5 人（§10 第 4 項）。

## 5. 成功條件

- **SC-H1**（版面順序）：（2l 取代：見 [2l](phase-2l-home-layout.md) SC-Y1、SC-Y2）桌機與 390px，區塊順序都符合 W260。
- **SC-H2**（切帳本）：從「日常」切到「家用」→ 3 張卡、分類段、最近交易換成「家用」的；`/accounts/balance-trend`、`/accounts`、`/counterparties`、`/ledger-groups`、標註列表都沒有多打請求（決策 307）。
- **SC-H3**（寫入後同時更新）：以下每一種寫入成功後，首頁每一張受影響的卡在同一輪一起更新，不用重整；重抓期間舊數字留著，不閃成 $0 或載入中（決策 306）：
  - 首頁新增、改金額、刪除一筆交易，補帳戶。
  - AI 記帳確認寫入。
  - 新增借還、還款、分帳、結清。
  - 新增、刪除帳戶。
  - 分類改名（分類段的名稱跟著變）。
  - 單元測試驗證共用失效函式涵蓋上述每個入口，且失效的 key 包含 `ledger-statistics` 與 `balance-trend`。
- **SC-H4**（分類段不多打）：首頁載入一本帳本時，`/ledgers/{id}/statistics` 的請求數跟 2j 相同；展開、收起不打請求。
- **SC-H5**（分類段內容）：15 類 → 先列 5 類，順序與百分比文字照 API；按「全部 15 類」→ 15 類；按「收起」→ 回到 5 類。含固定分組、未分類、0 bps（「<0.01%」）。顏色依決策 309。沒有支出 →「本月沒有支出」。「明細 →」到 `/stats`，帶目前帳本與這個月，停在分類分頁。
- **SC-H6**（共享帳本的分類段）：「家用」的分類段金額是 `LEDGER` 視角的分組，標題含「家用」。
- **SC-H7**（總額）：大字等於 `balance-trend` 最後一個月的 `total`。端點失敗時那一格顯示錯誤，不顯示 $0，帳戶清單照常。
- **SC-H8**（帳戶）：（2026-10-27 修訂，見 W264）0、5、6、12 個帳戶；12 個 → 一進來就列出 12 個，沒有「全部 N 個」與「收起」；順序照 API；負數與臨時帳戶照帳戶頁顯示。5 個以下一欄；6 個以上時清單寬度 439px 一欄、440px 兩欄；寬視窗但右側記帳欄打開、卡片變窄時也照清單寬度判斷。
- **SC-H9**（借還的人）：（2l 修訂：箭頭見 [2l](phase-2l-home-layout.md) SC-Y7）請求帶 `nonZero=true&limit=5`；7 人 → 5 列加「全部 7 人 →」；金額與箭頭用 `totalBalance`，用一組 `balance` 與 `totalBalance` 正負不同的資料驗證；卡上沒有加總金額；「全部 →」到 `/transactions?view=debts&tab=overview`。

- 不碰授權與資料隔離：（2l 修訂：新端點的隔離測試見 [2l](phase-2l-home-layout.md) §6.1）沒有新的端點，沒有新的查詢條件。協調者驗收時確認 diff 裡沒有 `apps/api` 與 `packages/shared` 的改動。決策 308 修的是前端送錯帳本 id，後端原本就會擋，不改後端。
- Web 元件測試：W260～W271、SC-H2～SC-H12（SC-H8 的寬度除外）、SC-H15、SC-H16、SC-H18。「不多打請求」用真的 QueryClient、只 mock fetch，量切換前後的請求增量；決策 306 的共用失效函式有自己的測試，列出它失效的每個 key；每個寫入入口的 hook 測試各加一條「呼叫了共用函式」或「沒有呼叫」。
- Web e2e：SC-H1、SC-H3 的新增一筆、SC-H8 的寬度、SC-H13、SC-H14（390px 與桌機各一）。版面尺寸只在真的瀏覽器量，模擬瀏覽器不算 CSS 版面。

## 7. 界線

- **Always**：數字與百分比照 API 顯示；切帳本時跨帳本的資料不重抓；寫入後相關快取失效；每區各自處理錯誤。
- **Ask first**：新增或修改 API 參數（例如借還依金額排序、首頁專用的彙總端點）；加套件；改資料模型。
- **Never**：前端加總帳戶餘額或借還金額；前端算百分比或合併「其他」；拿交易列表的回應加總；把快取設成永不過期；在 localStorage 存金額、帳本或人名。

## 10. 原本待確認的項目

4 項都已定案。

1. **分類段配色**（已定案，見決策 309）：原本分歧在「每類一色」與「單色」，接著是「單色用金或灰」。開發者看過 demo 後決定三種都做成設定，預設彩色。Codex 第 2 輪的提醒照寫進決策 309：灰色不是「未分類」專屬，結清差額、呆帳、債務免除也是灰（`chart-format.ts`），所以金色區分的是「一般分類」與「固定分組」。
2. **資產趨勢卡不放「明細 →」**（雙方同意）：沒有逐月明細頁；每個月的金額滑過、點擊、鍵盤都讀得到。不改連帳戶頁，那是不同的資料。
3. **沒有標註時不顯示「標註」分頁**（雙方同意）：跟 2j 沒有標註就不出現標註卡一致。載入中與失敗另外處理（W266）。
4. **借還沿用 API 的順序**（雙方同意）：`nonZero=true` 之後就是依名字排序。卡上不寫「最多」「最急」。要依金額排就要改 `/counterparties`，不在本步。
