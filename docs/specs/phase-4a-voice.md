## 0. 假設

開發者 2026-10-29 回「同意」核可以下 11 條。

1. **範圍**：程式只改 `apps/web`。只驗桌機 Google Chrome 開 localhost。其他瀏覽器偵測得到 API 也會出現按鈕，但不算驗收。手機、HTTPS、Safari、Edge、React Native App 另案。
2. **辨識設定**：建構子用 `SpeechRecognition ?? webkitSpeechRecognition`。設定 `lang='zh-TW'`、`continuous=false`（講完一段就結束）、`interimResults=false`（不回傳說到一半的文字）、`maxAlternatives=1`。只用 final（瀏覽器認定不再修改的）結果。用瀏覽器預設模式，聲音可能送到 Google 辨識；不強制在本機辨識。
3. **不支援時**：偵測不到建構子，或不是安全環境（HTTPS 或 localhost），就不顯示按鈕。打字照常可用。
4. **後端不改**：不加 API、不做 migration、不加套件、不改 CI。辨識出的文字走現有 `POST /api/ai/parse-transaction`，照扣每人每日 50 次額度。
5. **流程 C'**：按麥克風開始聽。講完停一下，瀏覽器自動結束；也可以再按一次停止。拿到 final 就自動解析，每一輪最多解析 1 次。空白、超過 200 字、解析失敗、超額、零草稿時，文字留在輸入欄讓使用者改，不自動重試。輸入欄有字時，「開始」停用。解析成功照舊清空輸入欄。
6. **停止和取消分開**：
   - 再按麥克風＝停止（`stop()`）：不再收音，保留這一輪，等 final。
   - 以下情況＝取消：先作廢這一輪，再 `abort()`。取消、Escape 或收合、入口隱藏、切帳本、離開頁面、登出、換身分、開新的一輪、分頁切到背景（`visibilitychange` 變成 hidden）。
   - 每一輪開始時記下身分世代、來源帳本、輸入版本。結果回來時先檢查這三項，要擋得住 A→B→A（切走再切回原帳本）。
   - 文字交給解析之後是另一個階段：之後跨頁，解析照舊完成。
7. **時間上限**：從 `audiostart`（開始收音）起最多 30 秒，到時呼叫 `stop()`。`start()` 後 15 秒還沒開始收音，就作廢這一輪。停止後 10 秒等不到 final，也作廢。
8. **錯誤訊息**：見決策 354。極簡短句，自己取消造成的錯誤不顯示。
9. **隱私**：應用程式不取得、不儲存音檔。聲音可能由 Google 處理，我們不保證 Google 那邊不保存。介面不放說明句，只記在本 spec。開放給第一位其他使用者之前（邀人測試也算）要補正式告知。按鈕要有可讀的名稱。
10. **測試**：自動化測試用假的辨識器。真實測試由開發者在真的 Chrome 現場念 20 句固定稿，加 6 種逆境與 3 項冒煙。整個真實測試最多用 26 次解析。
11. **分工與編號**：實作派 Codex。決策號從 346 開始，成功條件用 `SC-SR`。

## 1. 目標與成功樣貌

打字記帳在手上拿著東西時不方便。本步在 AI 入口加一顆麥克風按鈕。使用者講一句話，瀏覽器把聲音轉成文字，文字照現有流程變成草稿。草稿照舊要使用者確認才寫入。

例子：我在桌機 Chrome 開 `http://localhost:5173`，停在「日常」帳本的交易頁。

1. 頂端橫條的 AI 入口多一顆麥克風按鈕。我按它，輸入欄展開，狀態顯示「準備中…」。第一次用時 Chrome 問麥克風權限，我按允許。
2. 狀態變成「聆聽中…」。我說「早餐六十現金」，停一下。
3. 狀態變成「辨識中…」，接著輸入欄出現「早餐 60 現金」，並自動送出解析。之後和打字送出一樣：轉圈、清空輸入欄、下方出現 1 筆草稿。
4. 我按 ✓ 才寫入。
5. 我再按麥克風，說到一半發現說錯，按 Escape。這一輪作廢，沒有送出解析，也沒有錯誤訊息。
6. 我按麥克風後沒說話。過幾秒顯示「沒聽清楚，請再試一次。」，按鈕恢復可按。

### 範圍外

- 手機（Android Chrome、iOS Safari）、HTTPS 部署、Edge、Firefox 的驗收。
- React Native App 的語音。App 不能用 Web Speech API，要另寫 spec。
- 顯示說到一半的文字（即時字幕）。
- 強制本機辨識（`processLocally`）、下載語言包、讓使用者選辨識模式。
- 後端 STT、上傳音檔、錄音檔保存。
- 連續聽很多句（`continuous=true`）、聽完自動重開。
- 語音指令（「確認」「刪掉第 2 筆」）。
- 用 AbortSignal 中斷已送出的解析請求。

## 5. 成功條件

SC-SR1～SC-SR13 用假的辨識器驗證，進 CI。SC-SR14～SC-SR16 用真的 Chrome，開發者現場操作，協調者記錄。

自動化測試只能證明程式的事件、取消、送出流程正確。它不能證明真的麥克風權限、辨識品質、Google 服務可用。

**每一條自動化測試都要斷言「送出解析的次數」與「輸入欄內容」，不能只看畫面上的字。**

- **SC-SR1**（偵測）：
  1. 沒有建構子 → 沒有麥克風按鈕，打字照常。
  2. 只有 `webkitSpeechRecognition` → 有按鈕。
  3. 只有 `SpeechRecognition` → 有按鈕，而且用它。
  4. `isSecureContext=false` → 沒有按鈕。
  5. 帳本載入中、載入錯誤、只能檢視、輸入欄有字、正在解析 → 不能開始。
  6. 載入頁面不呼叫 `start()`，也不要麥克風權限。
- **SC-SR2**（設定）：實例的 `lang`、`continuous`、`interimResults`、`maxAlternatives` 是假設 2 的值。每一輪是新的實例。
- **SC-SR3**（正常流程）：final「早餐 60 現金」→ 輸入欄是這句 → 送出 1 次解析，`text` 是這句，`ledgerId` 是開始時的帳本 → 草稿追加、輸入欄清空 → 沒有任何新增交易的請求。
- **SC-SR4**（事件順序）：以下每一種都最多送 1 次解析：
  1. final → end。
  2. 同一輪 2 次 final。
  3. final → error → end。
  4. error → end（交付前）：不送，顯示對應訊息。
  5. end 沒有 final：不送，顯示「沒聽清楚」。
  6. 只有 `isFinal=false` 的結果：不送，不進輸入欄。
- **SC-SR5**（停止與取消）：
  1. 聆聽中再按 → 呼叫 `stop()`，不呼叫 `abort()` → 之後的 final 照常送解析。
  2. 假設 6 的每個取消條件各測 1 次：呼叫 `abort()` → 之後送來的 result、error、end 都不送解析、不改輸入欄、不顯示錯誤。
  3. 取消後馬上開新一輪 → 舊實例的 end 不改新一輪的狀態。
- **SC-SR6**（有效性）：
  1. 帳本 A 開始 → 切 B → 切回 A → 舊實例送 final：不送解析。
  2. 登出、換使用者後舊實例送 final：不送解析。
  3. 輸入版本變了之後舊實例送 final：不送解析。
  4. `isVisible=false`（元件沒卸載）→ 取消。
  5. 卸載 → 取消，沒有 React 警告。
  6. StrictMode 下流程與上面相同。
- **SC-SR7**（雙擊與例外）：
  1. 連按 2 次開始 → 只建 1 個實例、呼叫 1 次 `start()`。
  2. `start()` 丟例外 → 顯示「目前無法使用語音，請改用文字。」，鎖解除，可以再按。
- **SC-SR8**（時間上限，假 timer）：
  1. `audiostart` 後 30 秒 → 呼叫 `stop()`。之後的 final 照常送解析。
  2. `start()` 後 15 秒沒有 `audiostart` → `abort()`，顯示決策 353 (b) 的訊息。
  3. 停止後 10 秒沒有 final → `abort()`，顯示決策 353 (c) 的訊息，不送解析。
  4. 任一輪結束後，它的 timer 不影響下一輪。
- **SC-SR9**（文字邊界）：
  1. final 只有空白 → 不送，顯示「沒聽清楚」。
  2. trim 後剛好 200 字（含 emoji 的情況）→ 送出。
  3. 201 字 → 完整留在輸入欄，不送，顯示「請精簡至 200 字內。」→ 刪到 200 字後按送出能送。
  4. 解析回 503、429、零草稿 → 文字留在輸入欄，顯示現有訊息，不自動重送。
- **SC-SR10**（階段邊界）：送出解析之後切到首頁 → 解析照常完成，草稿出現，和打字送出相同。
- **SC-SR11**（錯誤訊息）：決策 354 的每個錯誤碼對應的文字正確。自己取消的 `aborted` 不顯示。新一輪開始時清掉舊的語音錯誤。
- **SC-SR12**（無障礙）：按鈕名稱照 W259。Enter、Space 能開始與停止。Escape 取消。狀態在 live region。
- **SC-SR13**（Playwright e2e，fake LLM）：在載入頁面前，用同一份 `addInitScript` 注入可控制的假建構子。不用真的麥克風或 Google。
  1. 正常流程：final → 1 次解析請求 → 出現草稿 → 沒按 ✓ 前沒有寫入交易。
  2. 取消後送 final → 沒有解析請求。
  3. 沒注入建構子 → 沒有按鈕。
  4. 既有的 AI 打字 e2e 全部照舊通過。
- **SC-SR14**（真的 Chrome，20 句）：程序照 §6.1。
  1. 金額與方向都對的句子 ≥ 19/20。
  2. 整筆必要欄位都對的句子 ≥ 18/20。必要欄位：型別、金額、日期、帳本、帳戶；轉帳加轉入帳戶；收支加分類（§6.1 表格列出可接受的值）。沒有多出或少掉的草稿。標題不計。
  3. 多筆句要全部筆數都對才算 1 句對。
  4. 另外記「語音辨識本身正確」的句數（辨識出的文字裡，金額、帳戶、分類關鍵字都對）。不設門檻，用來分辨是聽錯還是模型解析錯。
  5. 全程沒按 ✓，交易列表測前測後筆數相同。
- **SC-SR15**（6 種逆境）：照 §6.2。不計入 20 句。以下 4 項必須零失敗：沒有未確認就寫入、沒有套到錯的身分或錯的一輪、一輪沒有送 2 次解析、沒有卡住不能恢復。辨識聽錯或聽出不存在的字，逐項照實記錄，不設門檻。
- **SC-SR16**（冒煙）：
  1. 在 Chrome 封鎖麥克風權限 → 按麥克風顯示「無法使用麥克風，請檢查權限。」→ 改成允許 → 再按能用。
  2. 停用或拔掉麥克風 → 顯示對應訊息，可恢復。
  3. 網路不通 → 顯示對應訊息，可恢復。
  4. 做不出某個情況（例如系統不允許停用麥克風）就記「未驗」，不用假辨識器的結果代替。

## 6. 測試策略

- **先寫、先紅**（協調者）：SC-SR5、SC-SR6。這兩條管「舊結果套到錯的身分或帳本」，是資料隔離的防線。
- Vitest 元件與 hook 測試：SC-SR1～SC-SR12。假辨識器要能手動觸發每一種事件，並記錄 `start`、`stop`、`abort` 的呼叫次數。用假 timer。
- Playwright：SC-SR13。照現有 Web e2e 的設定與 fake LLM，不改 CI，不加套件。
- 既有的 AI 打字測試（`AiEntry.test.tsx`、`ai-session.test.tsx`、AI e2e）內容不改，當成回歸測試。
- 真實測試：SC-SR14～SC-SR16，在主工作區的 dev 跑（開發者的 Chrome、`localhost:5173`）。不用 Playwright 的 Chromium，因為它不是真的 Chrome 語音服務。

### 6.1 20 句的程序

測前固定以下條件，記進 plan：

- **測試帳本**：開發者帳號下新建帳本「語音測試」。
  - 支出分類：早餐、午餐、晚餐、交通、日用品、其他。
  - 收入分類：薪資、獎金、其他收入。
  - 帳戶：現金、信用卡、儲蓄。帳戶屬於使用者，已有的帳戶照用，名稱要和這 3 個相同。
  - 測試時停在這本帳本的交易頁。
- **環境**：前後端 commit、Chrome 完整版本、Windows 版本、麥克風型號與輸入音量、Chrome 語言設定、網路類型。Google 辨識服務的版本無法得知，記「未知」。
- **朗讀**：開發者本人，同一個安靜位置，嘴巴離麥克風約 20 公分，正常語速，照編號順序。每句一輪，看到「聆聽中…」才開始念，念完等它自己結束。
- **日期**：20 句在同一天念完，並記下解析請求的 `today`。「昨天」「前天」照 `today` 算。
- **暖身**：正式開始前可以念 2 句不在清單裡的句子，確認權限與音量。暖身結果不算分。
- **記錄**：用 Chrome DevTools 的 Network 分頁看解析請求的 `text`、`today` 與回應的草稿，手動抄進 plan 的表格。不匯出 HAR（會帶 Authorization 與 cookie），不記 token 或真實帳號。沒送出解析的情況，記畫面上的文字與錯誤。
- **不確認**：全程不按 ✓ 與「全部確認」。測前測後各記一次交易筆數。
- **計分**：每句只計第一次、沒人工改字的結果。改程式後重跑，就開新的一輪紀錄，舊的保留。

## 7. 界線

- **Always**：每個事件先檢查這一輪仍有效；取消先作廢再 `abort()`；一輪最多送 1 次解析；解析結果只產生草稿；失敗保留文字；超過 200 字不截斷、不送；按鈕有可讀名稱；新的使用者可見文字照決策 354。
- **Ask first**：改辨識設定（例如開即時字幕、`processLocally`、`continuous`）；改時間上限；加自動重試或自動重開；新增套件（包括語音相關的 polyfill）；改後端或 shared；在介面加說明文字；把驗收擴大到手機或其他瀏覽器。
- **Never**：沒經使用者確認就寫入交易；取得、儲存、上傳音檔；把辨識文字寫進 log 或 localStorage；在載入頁面時自動要麥克風權限；用延遲幾百毫秒或自動重開來掩蓋事件順序的問題；用重試替換真實測試的首次結果；匯出含 Authorization 的 HAR。

## 8. 部署

dev 只在 localhost 跑，Chrome 允許 localhost 用麥克風。沒有 migration、沒有新環境變數、後端不用重開。網頁 build 後，開發者在 Chrome 按 `Ctrl + Shift + R` 重新載入。

將來部署到外網：一定要 HTTPS，否則 Chrome 不給麥克風，按鈕也不會出現（決策 348 (a)）。
