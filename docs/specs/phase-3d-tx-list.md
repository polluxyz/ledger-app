## 1. 目標與成功樣貌

交易頁看起來太亂。原因有五個：篩選一直佔著畫面上方；分類用文字表示；有的交易有名稱、有的沒有，列的高度不一；刪除按鈕有的列有、有的沒有；日期分組之間太擠。另外要預留語言轉換：英文單字比中文長很多，排版不能靠文字長度撐開。

本步完成後：

1. 篩選收進列表右上的漏斗圖示，按了才往下展開；有條件時圖示上顯示數量。
2. 每一筆交易是**一列、固定高度**：左邊分類圖示、中間名稱、右邊金額。
3. 分類有圖示：預設分類一建立就有，分類彈窗可以挑；交易列、分類頁、記帳表單的分類選單都顯示。
4. 列上不放刪除按鈕，刪除收進編輯面板。
5. 不同天的分組之間留 24px。
6. 名稱、分類換成很長的英文，版面不亂、金額欄位置不動。

### 範圍外

- 真的切換語言（i18n 框架、翻譯檔、語言設定）。本步只寫規劃（§6）並讓版面禁得起長字。
- AI 產生分類圖示（開發者 2026-10-03 提出，列入延後項目）。
- 每日小計：要後端算，另開一輪再談。

## 3. 資料模型與 API

> 依 `CLAUDE.md` §14，schema 變更與新增相依都要先說明。本節與 T3 核可即視為同意。

```prisma
model Category {
  // …既有欄位
  /// 圖示代號（3d），允許的值見 @ledger/shared 的 CATEGORY_ICONS；null 顯示通用圖示。
  icon String?
}
```

- migration：加欄位；依 T4 對既有資料做一次 `UPDATE`（預設名稱 → 預設圖示）。
- `Category` 回應、`CreateCategoryRequest`、`UpdateCategoryRequest` 多一個 `icon`（選填，`null` 清除）。只增欄位。
- 交易回應的 `category` 從 `{ id, name }` 變成 `{ id, name, icon }`。只增欄位。
- `DEFAULT_CATEGORIES` 每一筆多一個 `icon`。

圖示代號（草案，實作時可在清單內增減，不改規則）：

## 4. 可驗證的成功條件

- **SC-T1**：篩選預設收起；按漏斗展開、再按收起；選了分類後圖示上顯示「1」，按「清除」歸零。
- **SC-T2**：有名稱、沒名稱、借還、分帳、轉帳的列，高度全部相同。
- **SC-T3**：名稱與分類換成 40 字的英文長字串，金額欄的位置不變，頁面沒有橫向捲動（1440 與 375 寬都驗）。
- **SC-T4**：不同天的分組之間至少 24px。
- **SC-T5**：每列左邊有圖示；分類沒設圖示的顯示通用圖示；借還、轉帳顯示 T5 的固定圖示。
- **SC-T6**：列上沒有刪除按鈕；一般交易的編輯面板有「刪除」，刪除後列表更新、右側欄收起。
- **SC-T7**：分類彈窗可以選圖示並儲存；送不在清單裡的代號 → 400。新帳本的預設分類都有圖示；migration 後既有的預設分類有圖示。
- **SC-T8**：總覽的「最近交易」用同一種列。
- **SC-T9**：`pnpm lint / typecheck / test / build / format:check` 與兩套 e2e 全綠；migration 進版控且重跑無 pending。

## 6. 語言轉換的規劃（本步不實作）

開發者 2026-10-03：「先為未來提出規劃，不要到時候要整個大改。」以下是之後做 i18n 時的做法，本步只做第 1 點，其餘先寫下來，避免現在的寫法擋住未來。

1. **版面規則**（本步就做，T11）：不依賴文字長度；長字截斷；固定寬度只給圖示、金額、按鈕。新元件都照這條。
2. **字串集中**：之後導入翻譯框架（候選 `react-i18next`），每個 feature 一份字串檔。現在新寫的元件，畫面文字盡量集中在元件頂端的常數，之後抽字串比較好找。
3. **日期與數字**：`lib/format.ts` 與 `@ledger/shared` 的格式化都用 `Intl`，之後改成讀「目前語言」，不在元件裡自己拼日期。
4. **預設分類的名稱**：分類名稱是使用者資料。之後在 `Category` 加 `systemKey`（預設分類才有），沒被改名時依語言顯示翻譯，被改名後顯示使用者的名字。本步的 `icon` 不受語言影響。
5. **後端訊息**：前端已經依 `errorCode` 對應中文（`lib/error-messages.ts`），之後同一張表加英文即可，後端不回在地化文字。
6. **App**：行動 App 共用 `@ledger/shared` 的格式化與字串鍵，翻譯檔各自一份。

## 8. 界線

- **Always**：圖示只存代號；代號清單只有 shared 一份；文字一律可截斷。
- **Ask first**：再新增前端或後端套件；改交易列表的 API 形狀（本步只增欄位）。
- **Never**：在資料庫存圖示庫的元件名稱或 SVG；靠文字長度決定欄寬。
