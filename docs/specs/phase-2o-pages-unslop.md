## 1. 目標

1. 登入、註冊用同一套身份版面，桌機品牌欄加表單兩欄，手機單欄同一左緣。
2. 個人資料分成唯讀 Email 與名稱表單，儲存後看得到「已儲存」。
3. 統計頁的範圍控制（帳本、期間、口徑）和分析分頁分層，固定分頁不被頂列擋住。
4. 統計分類與成員分頁改成兩欄：明細清單加圖。
5. 統計趨勢用一張合成圖，同時讀到收入、支出、結餘，不再有圖型切換與表格。
6. 選定頁面與全站共用元件（切換鈕、卡片外觀、手機觸控區）與首頁 2m 風格一致。

### 範圍外

- TX-5：AI 記帳星芒圖示維持現況（4a W246）。
- SH-3：無內容頂列維持 56px 高度（2i SC-38）。
- 未選頁面（交易、對象、帳本、帳戶、分類、邀請等）的版面與功能。只套用決策 421 的共用元件外觀；其他差異記在 plan 的「未處理」清單，之後再挑。
- 首頁版面、首頁 2m 趨勢圖（`HomeFinancialTrendChart`）、2n 的修整。
- 任何後端、金額計算、API 欄位、localStorage key 名稱。

## 5. 界線

- Always：設計 token、CSS Modules、CSP `style-src 'self'`、整數分與既有 `formatMoney`、百分比只用後端 `percentageBps`、鍵盤操作、深淺主題、讀屏名稱、介面文字極簡（不加說明段）。
- Ask first：API、schema、相依、CI、超出 §1 的頁面改版、localStorage key 改名。
- Never：前端計算金額或百分比、改顏色語意、改首頁版面與首頁趨勢圖、未經開發者確認就合併。

## 6. 成功條件

- **SC-O1**（W313）：1280px 與 390px，捲到統計頁底部時分頁籤完整露出，上緣不低於頂列下緣、不被蓋住。摘要在頁面只出現一次，結餘卡有淡金底。
- **SC-O2**（W314、W315）：1280px 清單在左、圖在右，兩欄頂端對齊；390px 圖在上、清單在下。兩種寬度用 Tab 走一遍，焦點順序等於畫面由上到下、由左到右。
- **SC-O3**（W314、W315）：分類與成員分頁沒有「圓餅／長條」切換，圖那一欄只有圓餅，清單每列有橫條且顏色等於圓餅同一塊。切支出／收入，清單、橫條與圓餅同時更新；舊網址 `tab=cat&chart=bar` 或 `tab=member&chart=bar` 以 replace 去掉 `chart`；百分比字串等於 `formatPercentageBps(percentageBps)`。點分類仍跳到交易頁並帶入篩選。
- **SC-O4**（W315）：共享帳本成員清單每人同時有支出與收入金額；選支出時支出是主數字，選收入時反過來。$0 成員仍在清單。
- **SC-O5**（W316）：趨勢頁沒有「長條／折線／表格」切換鈕，也沒有 `趨勢表格`。合成圖有 12 個月的收入柱、支出柱、結餘點；含負結餘的資料點在零線下。390px 頁面 `scrollWidth` 等於視窗寬。鍵盤左右鍵換月，Enter 切期間，讀屏名稱含三個精確金額。
- **SC-O6**（W317）：月期間預設不顯示詳情列，聚焦其他月份後出現；詳情列出現前後，圖表上緣 y 座標相同（誤差 ±1px）。
- **SC-O7**（W222 修訂）：打開 `/stats?tab=trend&chart=table` 後網址變成不帶 `chart`，返回鍵不會回到帶 `chart` 的網址。localStorage `stats.chart` 有任何舊值時頁面正常。
- **SC-O8**（W318）：登入頁、註冊頁 1280px 兩欄、390px 單欄且無橫向捲動；首頁與邀請頁的登入彈窗沒有品牌欄。登入、註冊、導回原頁的既有 e2e 通過。
- **SC-O9**（W319）：改名稱後儲存，儲存鈕旁出現「已儲存」，頂列名稱同步；再改名稱，「已儲存」消失。「Email 不可變更」仍在。
- **SC-O10**（W320）：390px 量測選定頁面與各分段切換鈕，可點控制項高度 ≥44px；1280px 仍是 36px；交易頁交易列仍是 52px。未選頁面除切換鈕與卡片外觀外，版面截圖與基線相同。
- **SC-O11**（不退步）：2j、2m、2n 的成功條件與既有 web e2e 全部通過（必要時只改圖型切換相關斷言）。
- **SC-O12**：`pnpm format:check`、`lint`、`typecheck`、`test`、build、web e2e 全部通過；diff 只含 `apps/web`、`docs/specs`、`docs/README.md`、`tasks`。PR 有 3 組 commit，各組單獨 revert 後 typecheck 與 test 仍通過。

### 9.5 測試策略

- API 單元：篩選 SQL 的成員、分類、帳戶、未分類、其他帳戶與組合；月平均分母的三種情況；DTO 驗證（UUID、上限、布林、`MINE`＋`personIds`）。
- API e2e：跨帳本與他人帳戶 id 回 400、帳本不可讀 404、不帶篩選時回應不變、首頁用的 `ledger`／`mine` 不受篩選影響。
- API 單元：移動平均窗口、開帳後前 5 個月、窗口跨查詢起點、當月為 `null`、篩選只改分子（決策 435）。
