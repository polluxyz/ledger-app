## 1. 目標與成功樣貌

3f 讓借還頁回答「每個人總共跟我差多少」，但操作散在三個地方：借還頁看總額、右側欄看明細、交易頁的「結清」記帳本結清。已還清的紀錄跟未還清的混在一起，使用者要自己往下找。

本步把借還整理成一個地方，分四個子分頁，點哪一列就在那一列下方展開，不再開右側欄。

用 3f 的測試資料（我＝test）貫穿全篇，另外補兩個個人往來對象：

| 對象 | 紀錄（舊 → 新）                                     | 個人往來餘額 |
| ---- | --------------------------------------------------- | ------------ |
| 明哥 | 3/1 借出 300、3/5 明哥還 300（歸零）、3/10 借出 500 | 500          |
| 房東 | 3/2 借出 93、3/6 房東還 90 並以此結清（差額 −3）    | 0            |

花蓮三日的轉帳照 3f：小華 ─▶ 我 1,394、小明 ─▶ 我 512、小明 ─▶ 小美 400、小明 ─▶ 阿美 200。小明指向明哥。

本步完成後：

1. 交易頁只有「明細」「借還」兩個分頁。借還底下四個子分頁：「總覽」「個人」「共享」「歷史」。
2. **總覽**：明哥一列 `明哥 ─▶ 我 $1,012`，點了在下方展開：上面是個人往來未還清的 3/10 借出 500，下面是「花蓮三日」一行 `小明 ─▶ 我 $512`。只能看，沒有操作。小華列在下方花蓮三日群組。
3. **個人**：只列個人往來餘額不是 0 的人（明哥）。房東兩清，不列。展開後可以記一筆、免除剩餘，每筆紀錄的「⋯」可以修改、撤銷。
4. **共享**：花蓮三日一張卡片，四條轉帳各一個方塊。點 `小明 ─▶ 我 $512` 的方塊，結清表單在那一排下方展開並預填。
5. **歷史**：個人往來一段，列出明哥（3/5、3/1 兩筆）與房東（3/6 還款、差額、3/2 借出）；共享帳本一段，列出花蓮三日已記的結清。這些都可以修改、撤銷。
6. 撤銷房東 3/6 那筆還款：差額 −3 一起撤銷，房東的餘額回到 93，回到「個人」分頁。差額不能單獨撤銷。

### 範圍外（見 §9）

- 在借還頁一次還清總額、由系統分配到各來源（3f 延後項目，照舊延後）。
- 最上排的 AI 功能（本步只清空最上排，留位置）。
- 舊資料的還款與差額補綁定。

## 3. 資料模型

> 依 `CLAUDE.md` §14，schema 變更屬於「先說明再做」。本節核可即視為同意；實作前協調者會再列一次實際的 migration SQL。

```prisma
model DebtEntry {
  // …既有欄位不變
  /// 這筆結清差額屬於哪一筆還款（3g 決策 156）。只有 SETTLEMENT 會有值。
  settlesEntryId String?    @unique
  settlesEntry   DebtEntry? @relation("SettlementOfRepayment", fields: [settlesEntryId], references: [id], onDelete: Restrict)
  settledBy      DebtEntry? @relation("SettlementOfRepayment")
}
```

- 一筆還款最多一筆差額，所以 `@unique`。
- 往來紀錄只做軟刪除，不會真刪；`Restrict` 是最後防線。
- **沒有回填**。3g 之前的差額 `settlesEntryId` 是 null，照決策 157 可以單獨撤銷。
- 連動（3b-2）的對方那邊：對方接受「以此結清」的新增時，他那邊的差額也寫入 `settlesEntryId`。撤銷還款送給對方的變更，接受時同樣一起撤銷差額。

## 4. API

> 依 `CLAUDE.md` §14，API 介面變更屬於「先說明再做」。本節核可即視為同意。前端只顯示，分界、過濾、分組都由後端算。新參數都是選填，不帶時行為跟現在一樣。

### 4.1 往來紀錄

- `GET /counterparties/{id}/entries` 新參數 `?section=outstanding|history`（決策 153）。分頁套用在篩選後的結果；`balanceAfter` 照舊以全部紀錄累計。
- `GET /counterparties` 新參數：
  - `?personalNonZero=true`：只回個人往來 `balance ≠ 0` 的對象（個人分頁，W157）。現有的 `nonZero` 看 `totalBalance`，給總覽用，照舊。
  - `?hasHistory=true`：只回至少有一筆已還清紀錄的對象（歷史分頁，W161）。
- `DebtEntry` 回應多一個欄位 `settlesEntryId: string | null`。畫面用它決定差額有沒有「⋯」（決策 157）。
- `DELETE /debt-entries/{id}`：
  - 還款有綁定的差額時，一起軟刪除（同一個時間戳，決策 156）。
  - 對綁定的差額呼叫回 `409 SETTLEMENT_BOUND_TO_REPAYMENT`（新錯誤碼，決策 157）。
- `PATCH /debt-entries/{id}`：綁定的還款改金額時重算差額（決策 158）。

### 4.2 共享帳本

- `GET /ledgers/{ledgerId}/settlements`（新）：那本帳本已記的結清，新到舊、分頁。現任成員看到全部；已退出的人只看到他是任一方的結清（3f 決策 151 的範圍）。回應的每一筆是現有的 `Transaction`（帶 `settlement`）。
- `GET /ledger-groups` 新參數 `?hasSettlements=true`：只回有我看得到的結清的帳本（歷史分頁，W161），每組多一個欄位 `settlementCount`。含已退出的帳本。
- 共享分頁的已退出帳本（W160）用現有的 `GET /ledger-groups`（3f 已經只回跟我還有轉帳的已退出帳本），不新增端點。
- 修改、撤銷結清用現有的 `PATCH`／`DELETE /ledgers/{ledgerId}/settlements/{settlementId}`，不改。

### 4.3 錯誤碼（新增）

| 錯誤碼                          | 狀態  | 情況                       |
| ------------------------------- | ----- | -------------------------- |
| `SETTLEMENT_BOUND_TO_REPAYMENT` | `409` | 單獨撤銷綁定在還款上的差額 |

別人的對象、紀錄、我沒參與過的帳本，一律 `404`（照舊）。

## 5. 成功條件

金額寫成元，API 是分。以 §1 的資料為準。

- **SC-G1**：明哥 `GET …/entries?section=outstanding` 只回 3/10；`?section=history` 回 3/5、3/1。不帶參數回三筆。
- **SC-G2**：`GET /counterparties?personalNonZero=true` 有明哥、沒有房東；`?hasHistory=true` 有明哥、房東。
- **SC-G3**：房東 3/6 的差額 `settlesEntryId` 等於那筆還款的 id。撤銷還款 → 差額一起撤銷、房東餘額 9300；單獨撤銷差額 → `409 SETTLEMENT_BOUND_TO_REPAYMENT`。
- **SC-G4**：把房東那筆還款改成 91 → 差額變 −2，餘額仍 0；改成 95 → 差額變 +2（多收 2），餘額仍 0；改成 93 → 差額撤銷，餘額仍 0。每次修改，那筆還款的交易金額都等於新金額。
- **SC-G5**：連動的對象記「以此結清」的還款，對方接受後他那邊的差額也有綁定；我撤銷還款，對方接受後他那邊的還款與差額都撤銷。
- **SC-G6**：`GET /ledgers/{花蓮三日}/settlements` 回已記的結清，新到舊。我退出花蓮三日後只回我是任一方的結清。`GET /ledger-groups?hasSettlements=true` 有花蓮三日、`settlementCount` 正確。
- **SC-G7**（隔離）：別人的對象帶 `section`、`hasHistory` 一律看不到；沒參與過的帳本 `GET …/settlements` 回 `404`；退出後看不到別人之間的結清。
- **SC-G8**（畫面）：§1 的 1～6 都做得到。元件測試涵蓋：四個子分頁、列內展開一次一列、共享方塊與全寬表單、已退出帳本的唯讀卡片、歷史兩段、「⋯」與撤銷確認框、綁定差額沒有「⋯」、載入更多。
- **SC-G9**：回歸：3f 的總額、指向、退出唯讀全綠；`pnpm lint / typecheck / test / build / format:check` 與兩套 e2e 全綠。Web e2e 改成新版面（借還、連動、帳本分帳、3f 主線、版面、切換帳本的共用步驟）。

## 6. 測試策略

- **授權先行**：SC-G7 的隔離測試由協調者先寫、先看到紅燈。
- **單元測試**：已還清的分界（含從未歸零、剛好最新一筆歸零）、綁定差額的撤銷與重算、退出後結清清單的範圍。
- **API e2e**：SC-G1～G6。
- **Web**：元件測試涵蓋 SC-G8；Web e2e 一條主線：個人分頁記一筆 → 以此結清還款 → 移到歷史 → 撤銷還款 → 回到個人分頁；另一條：共享方塊記結清 → 歷史出現 → 撤銷。

---

## 7. 界線

- **Always**：已還清的分界、過濾、分組由後端算；還款與綁定差額在同一個資料庫交易裡寫入與撤銷；退出後的結清範圍在後端過濾。
- **Ask first**：改「餘額歸零為界」的規則；讓退出的人寫入；回填舊資料的綁定。
- **Never**：前端自己切已還清或加總；綁定的差額被單獨撤銷；退出的人看到跟他無關的結清。
