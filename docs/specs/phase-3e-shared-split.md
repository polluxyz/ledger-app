## 1. 目標與成功樣貌

共享帳本裡的人一起出錢時，系統算出誰欠誰，並建議怎麼轉最少次就結清。帳本的全部成員看到同一組數字，不需要互送待確認。沒有帳號、沒加入帳本的人，也能以「非成員」的身分一起分。

用一個例子貫穿全篇：**共享帳本「花蓮三日」，成員是我、小明、小華（都有帳號），帳本與帳戶連動。**

| 交易 | 付款人 | 金額  | 分給         | 每人份額 |
| ---- | ------ | ----- | ------------ | -------- |
| 住宿 | 我     | 6,000 | 3 人均分     | 2,000    |
| 晚餐 | 小明   | 1,500 | 3 人均分     | 500      |
| 油錢 | 小華   | 900   | 我、小華均分 | 450      |

淨額（＋＝別人欠他、−＝他欠別人）：我 +3,050、小明 −1,000、小華 −2,050。

結清建議兩筆：`小華 ──2,050──▶ 我`、`小明 ──1,000──▶ 我`。小華按「結清」並選自己的帳戶，小華的帳戶 −2,050；我選自己的帳戶收款，我的帳戶 +2,050。

第二天，小明的朋友阿美（沒有帳號）加入一起玩。我在帳本裡加一個非成員「阿美」，阿美付了門票 800，我和阿美均分。阿美出現在結清裡，淨額 +400。

本步完成後，使用者可以：

1. 在共享帳本加非成員（只有名字），也能改名或刪除。
2. 在共享帳本記支出或收入時選付款人（收款人），預設是自己。
3. 把一筆交易分給帳本裡的人：均分、自訂金額、自訂比例。新交易預設「全部均分」。
4. 在共享帳本的「結清」檢視看到每個人的淨額與結清建議。
5. 記一筆結清，有帳號的一方各自選帳戶，餘額照實際收付。

### 範圍內

- 帳本裡的人（成員與非成員）、付款人、分帳名單、結清的資料模型與 API。
- 淨額與結清建議的純函式（`@ledger/shared`）。
- 「帳戶待補」：付款人或收錢的人是別的成員時，由他自己補帳戶。
- 單元測試、隔離測試、e2e。畫面在 `phase-3e-web.md`，本檔 §7 只記方向。

### 範圍外（見 §9）

- 非成員日後註冊、加入帳本時，跟成員合併成同一人。
- 每個人的支出統計（等 B 統計報表）。
- 共享帳本的分帳與個人往來帳互相轉換。
- 多人一起付款（3c 已延後）。

## 3. 概念與規則

### 3.1 名詞

| 名詞       | 意思                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------- |
| 帳本裡的人 | 一本共享帳本裡可以分帳的人（`LedgerPerson`）：成員（有帳號）或非成員（只有名字）          |
| 非成員     | 帳本裡沒有帳號的人，只有名字，看不到帳本                                                  |
| 帳本分帳   | 共享帳本一筆交易分給哪些人、每人多少（`LedgerSplit`）。跟 3c 的「分帳」（對象、個人）不同 |
| 付款人     | 先付（收）這筆錢的人。收入時畫面叫「收款人」                                              |
| 名單       | 分這筆錢的人（`LedgerShare`）                                                             |
| 淨額       | 一個人在這本帳本的「別人欠他」減「他欠別人」。全部的人加起來是 0                          |
| 結清       | 一個人付錢給另一個人，抵掉欠款（`LedgerSettlement`，一筆轉帳）                            |
| 帳戶待補   | 連動帳本裡，付款人（收錢的人）是別的成員，帳戶還沒選                                      |

畫面上「分帳」一詞照用；`LedgerSplit` 只是程式裡跟 3c 的 `Split` 區分。

### 3.2 淨額怎麼算

只算這本帳本未刪除的交易。設 `P` 是付款人、`T` 是總額、`s_i` 是名單裡第 `i` 個人的份額。

| 來源             | 付款人（付錢的人） | 名單裡的每個人 `i` |
| ---------------- | ------------------ | ------------------ |
| 支出分帳         | `+T`               | `−s_i`             |
| 收入分帳         | `−T`               | `+s_i`             |
| 結清（A 付給 B） | A：`+金額`         | B：`−金額`         |

- 付款人也在名單裡時，兩列都要算。例：住宿 6,000，我 `+6,000`、我 `−2,000`，淨 `+4,000`。
- 每一筆的加總都是 0，所以全部的人加總恆為 0。
- 帳戶待補**不影響**淨額：淨額只看誰付、誰分，跟用哪個帳戶無關。

### 3.3 結清建議

純函式 `suggestSettlements`，放在 `@ledger/shared`。後端以它算出建議，回給畫面，畫面不自己算。

1. 淨額 > 0 的是收錢的人，< 0 的是付錢的人；淨額 0 的不參加。
2. 兩邊各依淨額絕對值由大到小排；一樣大時依「帳本裡的人」建立的先後。
3. 取兩邊第一位，轉 `min(|付|, |收|)`；扣掉後歸零的人移出，重複到兩邊都空。

這個做法最多產生「有淨額的人數 − 1」筆，結果固定，同一組淨額永遠得到同一組建議。它不保證是數學上最少的筆數（找最少筆數要窮舉，人數一多就算不動）。

例：我 +3,050、小明 −1,000、小華 −2,050 → `小華 ──2,050──▶ 我`、`小明 ──1,000──▶ 我`。

### 3.4 份額計算

沿用 3c 的 `computeSplitShares`（`phase-3c-split.md` §3.4）。目前它用「對象 id，`null`＝我」表示人；本步把它改成以任意字串 id 表示人，3c 傳對象 id，3e 傳 `LedgerPerson` id。規則不變。

### 3.5 誰能做什麼

| 角色           | 能做                                                                             | 不能做            |
| -------------- | -------------------------------------------------------------------------------- | ----------------- |
| OWNER、EDITOR  | 讀；加、改名、刪非成員；記與改任何一筆交易的付款人與名單；記、改、刪任何一筆結清 | 替別人選帳戶      |
| VIEWER         | 讀交易的付款人、名單、份額；讀帳本裡的人；讀結清檢視                             | 任何寫入（`403`） |
| 付款人本人     | 補自己的帳戶（帳戶待補），角色是 VIEWER 也可以                                   | —                 |
| 非成員         | 不是使用者，沒有任何存取                                                         | —                 |
| 已離開的成員   | 無（跟沒加入的人一樣）                                                           | —                 |
| 沒加入帳本的人 | 無                                                                               | 任何讀寫（`404`） |

- 封存帳本唯讀：結清檢視照樣能看，任何寫入回 `409 LEDGER_ARCHIVED`。
- 「付款人本人補帳戶」是 VIEWER 唯一能做的寫入，只能改帳戶欄位，走 §5.5 的專用端點。理由：錢是他付的，他要能讓自己的餘額正確。

## 4. 資料模型（Prisma）

> 依 `CLAUDE.md` §14，schema 變更屬於「先說明再做」。本節核可即視為同意；實作前協調者會再列一次實際的 migration SQL。

```prisma
/// 共享帳本裡可以分帳的人（3e）。成員加入時自動建立；非成員由使用者建立。
model LedgerPerson {
  id        String    @id @default(uuid())
  ledgerId  String
  /// 有值＝成員（或已離開的成員）；null＝非成員。
  userId    String?
  /// 只有非成員有值；成員的名字從 User 取。
  name      String?
  /// 只有非成員會被刪（決策 139）；成員離開不刪這一筆。
  deletedAt DateTime?
  createdAt DateTime  @default(now())
  updatedAt DateTime  @updatedAt

  ledger Ledger @relation(fields: [ledgerId], references: [id], onDelete: Cascade)
  user   User?  @relation(fields: [userId], references: [id], onDelete: Restrict)

  @@unique([ledgerId, userId])
  @@index([ledgerId])
}

model Transaction {
  // …既有欄位
  /// 付款人（收入時是收款人）。只有共享帳本的 EXPENSE、INCOME 有值；null＝記帳的人（決策 117）。
  payerPersonId String?
  ledgerSplit   LedgerSplit?
  settlement    LedgerSettlement?
  // payer 關聯：onDelete Restrict
}

/// 共享帳本一筆交易的分帳（3e）。帳本的全部成員都看得到。
model LedgerSplit {
  id            String         @id @default(uuid())
  transactionId String         @unique
  method        SplitMethod
  precision     SplitPrecision @default(CENT)
  createdAt     DateTime       @default(now())
  updatedAt     DateTime       @updatedAt

  transaction Transaction   @relation(fields: [transactionId], references: [id], onDelete: Cascade)
  shares      LedgerShare[]
}

/// 名單裡的一個人。份額由後端算好存下來。
model LedgerShare {
  id            String @id @default(uuid())
  ledgerSplitId String
  personId      String
  share         Int    // 分，> 0
  ratio         Int?   // 萬分比，只有 RATIO 有值
  sortOrder     Int

  ledgerSplit LedgerSplit  @relation(fields: [ledgerSplitId], references: [id], onDelete: Cascade)
  person      LedgerPerson @relation(fields: [personId], references: [id], onDelete: Restrict)

  @@unique([ledgerSplitId, personId])
  @@index([personId])
}

/// 一筆結清（3e）。交易本身是 TRANSFER：accountId＝付錢的人的帳戶，toAccountId＝收錢的人的帳戶。
model LedgerSettlement {
  id             String @id @default(uuid())
  transactionId  String @unique
  fromPersonId   String
  toPersonId     String

  transaction Transaction  @relation(fields: [transactionId], references: [id], onDelete: Cascade)
  fromPerson  LedgerPerson @relation("SettlementFrom", fields: [fromPersonId], references: [id], onDelete: Restrict)
  toPerson    LedgerPerson @relation("SettlementTo", fields: [toPersonId], references: [id], onDelete: Restrict)

  @@index([fromPersonId])
  @@index([toPersonId])
}
```

- 非成員的名字不重複（決策 136）用部分唯一索引：`UNIQUE (ledgerId, name) WHERE userId IS NULL AND deletedAt IS NULL`，寫在 migration SQL 裡。
- migration 替**既有共享帳本的每個成員**補一筆 `LedgerPerson`。之後成員加入時由 `LedgersService` 在同一個資料庫交易裡建立。
- 「已離開」＝`LedgerPerson.userId` 有值，但 `LedgerMember` 裡已經沒有這個人。不另存欄位。
- 軟刪除跟著交易的 `deletedAt`；`LedgerSplit`、`LedgerShare`、`LedgerSettlement` 不另外存。
- 沒有新的交易型別、沒有新的 enum；`SplitMethod`、`SplitPrecision` 沿用 3c。
- 餘額計算不改：帳本分帳的交易照原本的 `EXPENSE`／`INCOME` 算；結清照 `TRANSFER` 算。帳戶空著時自然不計入。
- 現有的轉帳規則（兩個帳戶都屬於呼叫者、不能相同）只適用於一般轉帳。結清的轉帳改由決策 129 的規則檢查。

## 5. API

### 5.1 帳本裡的人（`/ledgers/{ledgerId}/people`）

| 方法與路徑                               | 用途                       | 成功  |
| ---------------------------------------- | -------------------------- | ----- |
| `GET /ledgers/{ledgerId}/people`         | 列出帳本裡的人（含已離開） | `200` |
| `POST /ledgers/{ledgerId}/people`        | 新增非成員（`{ name }`）   | `201` |
| `PATCH /ledgers/{ledgerId}/people/{id}`  | 非成員改名                 | `200` |
| `DELETE /ledgers/{ledgerId}/people/{id}` | 刪除沒用到的非成員         | `204` |

```ts
interface LedgerPerson {
  id: string;
  name: string;
  /** 有帳號的成員才有；非成員為 null。 */
  userId: string | null;
  /** MEMBER＝現任成員、LEFT＝已離開、GUEST＝非成員。 */
  status: 'MEMBER' | 'LEFT' | 'GUEST';
}
```

只有共享帳本有這組端點；個人帳本回 `404`。成員那一筆不能用 `PATCH`／`DELETE` 改（`400`）。

### 5.2 交易端點的變更（`/ledgers/{ledgerId}/transactions`）

`POST`、`PATCH` 的 body 新增兩個選填欄位，只有共享帳本可用，個人帳本帶了回 `400 LEDGER_SPLIT_NOT_ALLOWED`：

```ts
payerPersonId?: string;     // 帳本裡的人；省略＝我
ledgerSplit?: {
  method: SplitMethod;
  precision?: SplitPrecision;
  shares: { personId: string; amount?: Cents; ratio?: number }[];
} | null;                   // null＝不分帳（PATCH 時拿掉名單）
```

回應的 `Transaction` 新增三個欄位，**帳本全部成員都有值**（跟 3c 的 `split` 只給擁有者不同）：

```ts
payer: LedgerPerson | null;  // 只有共享帳本的 EXPENSE、INCOME 有值
ledgerSplit: {
  method: SplitMethod;
  precision: SplitPrecision;
  shares: { person: LedgerPerson; share: Cents; ratio: number | null }[];
} | null;
/** 這筆的帳戶待補，而且要由「目前的檢視者」補。只有檢視者本人會看到 true。 */
accountPending: boolean;
```

新的列表篩選：`?payerPersonId=`（看某個人付的）。

### 5.3 結清端點

| 方法與路徑                                    | 用途                                     | 成功  |
| --------------------------------------------- | ---------------------------------------- | ----- |
| `GET /ledgers/{ledgerId}/settlement-summary`  | 每個人的淨額＋結清建議                   | `200` |
| `POST /ledgers/{ledgerId}/settlements`        | 記一筆結清                               | `201` |
| `PATCH /ledgers/{ledgerId}/settlements/{id}`  | 改金額、日期、備註、付錢與收錢的人、帳戶 | `200` |
| `DELETE /ledgers/{ledgerId}/settlements/{id}` | 刪除（軟刪除那筆交易）                   | `204` |

```ts
interface SettlementSummary {
  /** 依建立順序；淨額 0 的也列。沒出現在任何交易裡的非成員也列（淨額 0）。 */
  people: { person: LedgerPerson; net: Cents }[];
  suggestions: { fromPersonId: string; toPersonId: string; amount: Cents }[];
}

interface CreateSettlementBody {
  fromPersonId?: string; // 省略＝我
  toPersonId: string;
  amount: Cents; // > 0，≤ 2,000 萬元
  date: string;
  note?: string;
  fromAccountId?: string; // 只有付錢的人是我時能帶；連動帳本裡這時必填
  toAccountId?: string; // 只有收錢的人是我時能帶；連動帳本裡這時必填
}
```

結清在交易列表裡是一筆 `TRANSFER`，回應多一個欄位：

```ts
settlement: { id: string; from: LedgerPerson; to: LedgerPerson } | null;
```

### 5.4 錯誤碼（新增）

| 錯誤碼                             | 狀態  | 情況                                                                |
| ---------------------------------- | ----- | ------------------------------------------------------------------- |
| `LEDGER_SPLIT_NOT_ALLOWED`         | `400` | 個人帳本帶付款人或名單；或交易型別不能帶名單（決策 122）            |
| `LEDGER_PERSON_NOT_SELECTABLE`     | `400` | 付款人或名單放了已離開的成員、已刪除的非成員（決策 134 的例外除外） |
| `LEDGER_PERSON_NAME_TAKEN`         | `409` | 非成員的名字重複                                                    |
| `LEDGER_PERSON_IN_USE`             | `409` | 刪除還出現在交易或結清裡的非成員（決策 139）                        |
| `ACCOUNT_NOT_PAYERS`               | `400` | 帳戶不屬於付款人；或替別人選帳戶                                    |
| `SETTLEMENT_SAME_PERSON`           | `400` | 付錢的人與收錢的人相同                                              |
| `SETTLEMENT_TRANSACTION_READ_ONLY` | `409` | 用一般交易端點改、刪結清（決策 132）                                |

別本帳本的 `LedgerPerson` id 一律回 `404`（不透露存在）。

### 5.5 補帳戶端點（2026-10-04 plan 核可時補上）

| 方法與路徑                                          | 用途                                     | 成功  |
| --------------------------------------------------- | ---------------------------------------- | ----- |
| `PUT /ledgers/{ledgerId}/transactions/{id}/account` | 付款人補（或換）自己在這筆交易的帳戶     | `200` |
| `PUT /ledgers/{ledgerId}/settlements/{id}/account`  | 付錢或收錢的人補（或換）自己那一邊的帳戶 | `200` |

- body 只有 `{ accountId }`，回應是更新後的 `Transaction`。
- `VIEWER` 以上可呼叫；服務層再檢查「呼叫者就是付款人（結清時是付錢或收錢的那一位）」，不是的話回 `400 ACCOUNT_NOT_PAYERS`。帳戶必須屬於呼叫者，否則 `404`。不連動的帳本回 `400 ACCOUNT_NOT_ALLOWED`；封存帳本回 `409 LEDGER_ARCHIVED`。
- 為什麼不用 `PATCH`：`PATCH` 只給 `EDITOR` 以上。為了 VIEWER 放寬它，等於讓 VIEWER 有機會改到其他欄位。專用端點只收帳戶，寫入面最小。份額相關沿用 3c：`SPLIT_SUM_MISMATCH`、`SPLIT_SHARE_NOT_POSITIVE`、`SPLIT_PARTICIPANTS_INVALID`。

## 6. 成功條件

金額寫成元，API 與資料庫是分。除非另外說明，都以 §1 的「花蓮三日」為準。

- **SC-E1**：既有共享帳本跑完 migration → 每個成員各有一筆 `LedgerPerson`；之後新加入的成員自動有一筆。
- **SC-E2**：我記住宿 6,000（不帶 `payerPersonId`，名單 3 人均分）→ 一筆 `EXPENSE` 6,000，付款人是我，我的帳戶 −6,000；名單份額各 2,000。
- **SC-E3**：我記晚餐 1,500，付款人＝小明，3 人均分 → 交易沒有帳戶；我的帳戶不動；小明讀這筆 `accountPending: true`，我與小華讀到 `false`；小明的帳戶頁沒有這筆、餘額不變。小明用 `PUT …/transactions/{id}/account` 帶自己的帳戶 → 小明的帳戶 −1,500，`accountPending` 變 `false`。
- **SC-E4**：SC-E2～E3 加上小華記油錢 900（我、小華均分）後，`settlement-summary` 回：我 +3,050、小明 −1,000、小華 −2,050；建議 `小華→我 2,050`、`小明→我 1,000`。
- **SC-E5**：小華記結清 `小華→我 2,050`，帶自己的帳戶 → 一筆 `TRANSFER`，小華的帳戶 −2,050；我讀到 `accountPending: true`；我用 `PUT …/settlements/{id}/account` 補帳戶後，我的帳戶 +2,050。summary 變成我 +1,000、小明 −1,000、小華 0。
- **SC-E6**：小明記結清 `小明→我 1,200`（多付 200）→ 我 −200、小明 +200；建議 `我→小明 200`。
- **SC-E7**：把晚餐的付款人從小明改成我 → 帳戶清空；同一次 `PATCH` 沒帶我的帳戶 → `400`；帶了 → 我的帳戶 −1,500，小明那邊的扣款消失。
- **SC-E8**：晚餐 `PATCH ledgerSplit: null` → 名單刪除，淨額裡晚餐的影響消失。
- **SC-E9**（非成員）：在 SC-E4 的狀態下，我新增非成員「阿美」，記門票 800，付款人＝阿美，我與阿美均分 → 交易沒有帳戶、沒有人 `accountPending`；summary：我 +2,650、小明 −1,000、小華 −2,050、阿美 +400；建議 `小華→我 2,050`、`小明→我 600`、`小明→阿美 400`。小明記結清 `小明→阿美 400`，帶自己的帳戶 → 小明的帳戶 −400，收錢那邊沒有帳戶。
- **SC-E10**（非成員管理）：再加一個「阿美」→ `409 LEDGER_PERSON_NAME_TAKEN`；刪除阿美 → `409 LEDGER_PERSON_IN_USE`；新增「小美」後直接刪除 → `204`；改阿美的名字 → 交易與結清裡顯示新名字；`PATCH` 成員那一筆 → `400`。
- **SC-E11**：本步上線前就存在的共享帳本交易 → `ledgerSplit: null`、`payer` 是記帳的人，不影響淨額（決策 121）。
- **SC-E12**：個人帳本的交易帶 `payerPersonId` 或 `ledgerSplit` → `400 LEDGER_SPLIT_NOT_ALLOWED`；共享帳本的轉帳、借還交易、3c 分帳的交易帶名單 → 同樣 `400`；個人帳本打 `/people` → `404`。
- **SC-E13**：用 `PATCH`／`DELETE /transactions/{id}` 改、刪結清 → `409 SETTLEMENT_TRANSACTION_READ_ONLY`。
- **SC-E14**：小明離開帳本後，summary 仍列小明（`status: LEFT`）與他的淨額；新交易的名單或付款人放小明 → `400 LEDGER_PERSON_NOT_SELECTABLE`；我替小明記 `小明→我` 的結清 → 成功（決策 133）；改晚餐的金額 → 成功，名單裡的小明保留。
- **SC-E15**：份額規則與 3c 相同：自訂金額加總不符、比例加總不是 100%、份額 ≤ 0 → 對應的 `400`，什麼都不留下。
- **SC-E16**：`suggestSettlements` 的單元測試：§3.3 與 SC-E9 的例子；全部淨額 0 → 空陣列；同額時依建立順序；筆數 ≤ 有淨額人數 − 1。
- **SC-E17**（隔離）：沒加入帳本的人讀 people、summary、結清、帶名單的交易 → `404`；名單、付款人、結清放別本帳本的 `LedgerPerson` id → `404`；VIEWER 記交易、記結清、改名單、加非成員 → `403`；VIEWER 是付款人時用補帳戶端點補自己的帳戶 → 成功，用 `PATCH` 改金額 → `403`；不是付款人的人打補帳戶端點、或替別人選帳戶 → `400 ACCOUNT_NOT_PAYERS`；封存帳本寫入 → `409`。任一失敗都不留下資料。
- **SC-E18**（隔離）：成員讀別人付的交易與結清時，`account`、`toAccount` 仍是 `null`（沿用帳戶隱私規則）。帳本分帳與結清不出現在任何人的往來帳、對象頁、待確認。
- **SC-E19**：回歸：3c 的分帳在共享帳本照舊運作，`split` 只給擁有者；3b、3b-2、3c 的 e2e 維持綠燈。
- **SC-E20**：`pnpm lint / typecheck / test / build / format:check` 與兩套 e2e 全綠；migration 進版控且重跑無 pending。

## 7. 畫面方向（細節在 `phase-3e-web.md`）

只在共享帳本出現，個人帳本的畫面不變。

1. **記帳表單**：帳戶那一列的切換圖示，在共享帳本改成選**付款人（帳本裡的人）**，預設我。選了別人，帳戶欄位消失。
2. **分帳開關預設打開**，下面列出帳本裡的全部人與均分金額；點「›」進側欄子頁改分法，沿用 3c 的均分／金額／比例分頁。共享帳本的表單不提供 3c 的「從對象選人」分帳。
3. **非成員**：在選人的清單底部可以直接新增一個名字；改名、刪除放在帳本頁的成員區。
4. **交易頁**：共享帳本的「明細／借還」那一列多一格「**結清**」。
5. **結清檢視**：上面是每個人的淨額，下面是建議，用箭頭寫法；每條建議右邊一個「結清」按鈕，打開右側欄並帶好付錢的人、收錢的人、金額。
6. **帳戶待補**：交易列與結清列對需要補的人顯示提示；點開直接選帳戶。
7. **交易列表**：分帳的列金額顯示總額，標「分帳」；展開用箭頭列出每個人欠付款人多少。結清的列用轉帳圖示，名稱位置寫 `小華 ──▶ 我`。

## 10. 界線（Always / Ask first / Never）

- **Always**：份額、淨額、結清建議一律由後端算；寫入名單與交易在同一個資料庫交易裡；帳戶只能由主人選；隔離測試先於實作。
- **Ask first**：讓帳本分帳影響個人往來帳；回溯補既有交易的名單；讓非成員看到任何東西。
- **Never**：前端自己算淨額或建議（只能顯示）；讓一個成員看到別人的帳戶名稱；金額使用浮點數。

## 12. 核可時一併確認

以下是本 spec 新提出、開發者還沒明確回覆的。照建議定案，除非開發者另外說：

1. **結清是一筆轉帳**（決策 128）：不新增交易型別。代價是要放寬「轉帳兩個帳戶都屬於自己」的檢查，只對結清放寬。
2. **成員可以帶著欠款離開**（決策 133）。替代做法是擋下，但欠錢的人可以靠不結清讓自己（或被移除的人）一直卡住。
3. **既有交易不補名單**（決策 121）：已經記在共享帳本的舊交易不算進結清。要算的話，打開那筆、打開分帳再存。
4. **VIEWER 能補自己的帳戶**（§3.5）：唯一的例外寫入。
5. **共享帳本的表單不提供 3c 的對象分帳**（§7 第 2 點）。不在帳本裡的人改用非成員（決策 136）。3c 的 API 照舊接受共享帳本，已存在的 3c 分帳照舊能改。
6. **非成員屬於帳本**（決策 137）：任何 EDITOR 都能改名或刪除，不限加他的人。
7. **預設均分包含非成員**（決策 118）：例如家庭帳本加了小孩，預設每筆都會分給小孩一份，要手動取消。替代做法是「預設只分給成員」，但出遊時臨時加入的朋友就要每筆手動勾。
