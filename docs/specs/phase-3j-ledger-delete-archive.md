## 1. 目標與成功樣貌

帳本現在有 3 個問題：

1. 借還紀錄在檢視者身分或封存的帳本裡還改得動、撤銷得了。
2. 封存回不去，封存前還要打名稱。
3. 刪除帳本前看不到會改到哪些餘額；私人帳本記過借還或分帳就刪不掉，記錯了只能封存。

另外補一個寫 spec 時查到的漏洞：共享帳本裡我記「小華付的」支出，會記到小華的臨時帳戶（3h 決策 167），但刪除規則只看「誰記的」，我刪掉帳本時小華的餘額會被改掉。

用 dev 的測試資料（我＝test；小華＝c@c.com；花蓮三日是共享帳本）：

1. 小華在花蓮三日被降為檢視者，借還頁上那本帳本的紀錄沒有「修改」「撤銷」；直接打 API 改金額 → 403。帳本封存後撤銷 → 409。
2. 擁有者打開已封存的帳本，按「取消封存」→ 帳本回到切換器，又能記帳。封存時只跳確認，不用打名稱。
3. 我在私人帳本「日本旅遊」記了現金支出、借明哥 $500 → 按「刪除帳本」，先看到「現金 $X → $Y」「明哥 $500 → 兩清」，下面有「封存」與「刪除」。打對名稱按刪除 → 帳本消失，借出照「撤銷」處理，連動的明哥收到撤銷請他確認。
4. 花蓮三日有我記的「小華付的」支出 → 按「刪除帳本」只看到「有其他成員的交易，只能封存」。

### 延後（等複製功能一起做）

退出後帳戶餘額要不要再算那本帳本，3f 決策 152 定的是「照算，由留下的人替退出者記結清」。原本 3j 想改成「退出就不算」，會讓沒結清就退出的人錢被算兩次，所以先不動退出。下面這些等複製功能（2c §8「封存時的消費規整」）做時，跟 3f 決策 151、152 一起重新想：

- 退出前先看影響、退出時撤銷借還（「撤銷並退出」）。
- 共享帳本只剩自己一個成員時就能刪、移除成員的新限制。
- 退出或刪除時把借還複製到別的帳本。
- **放寬決策 187**：如果到時候定案為「退出就不算」，別人退出後，他臨時帳戶上的交易已經不算進他的餘額，決策 187 就要跟著放寬，只擋還是成員的人。不放寬的話，共享帳本會因為已退出的人而永遠刪不掉。

### 範圍外

- **隱藏帳本**：要記每個人各自隱藏了哪些帳本，需要改 schema，另案。
- **封存的帳本退出、刪除**：照舊不能（API 本來就擋封存帳本的寫入）。要刪先取消封存。
- 借還頁的列顯示名稱與分類、共享帳本其他成員看到的借出標籤（3i 已知限制）：另案。

## 3. 資料模型

**不改資料表與欄位，只放寬 1 條 CHECK（實作時發現，開發者 2026-10-17 同意）。** 刪除私人帳本前要先處理資料庫的關聯：往來紀錄 → 交易（`DebtEntry.transactionId`）、往來紀錄 → 分帳（`DebtEntry.splitId`）、分帳 → 帳本（`Split.ledgerId`）都是 `Restrict`。

做法：撤銷後，把指向這本帳本的往來紀錄（此時都已撤銷）的 `transactionId`、`splitId` 設成 `null`，刪掉分帳，再刪帳本。往來紀錄本身留著，對方的待確認、配對紀錄都還在。**如果做不到、一定要改 schema，停下來問開發者。**

實作時發現：「別人替我付」「別人替我收」（`PAID_FOR_ME`、`RECEIVED_FOR_ME`）有 CHECK 規定一定要有交易（3h migration `20261014160000_forgiveness_has_transaction`），撤銷後也清不掉 `transactionId`。開發者 2026-10-17 選「放寬規則」：migration `20261017140000_debt_entry_withdrawn_without_transaction` 讓這 2 種紀錄**已撤銷時**可以沒有交易，沒撤銷的照舊一定要有。另外分帳產生的交易指向分帳（`Transaction.splitId`）也是 `Restrict`，刪分帳前先清掉，不必改 schema。

## 4. API

### 4.1 `POST /ledgers/{ledgerId}/unarchive`（新）

- 權限：擁有者（`LedgerAccessGuard` 的 OWNER，加 `@AllowOnArchived`）。不是成員 404，非擁有者 403。
- 沒封存 → 409 `LEDGER_NOT_ARCHIVED`。成功回 `LedgerDetail`。

### 4.2 `GET /ledgers/{ledgerId}/removal-preview`（新）

只有擁有者（刪除本來就只有擁有者能做）。不是成員 404，非擁有者 403。

```ts
interface LedgerRemovalPreview {
  accounts: Array<{
    accountId: string;
    name: string;
    balance: Cents; // 現在
    balanceAfter: Cents; // 刪除後
  }>; // 只列有變化的帳戶
  counterparties: Array<{
    counterpartyId: string;
    displayName: string;
    linked: boolean; // 連動中：撤銷會送給對方確認
    balance: Cents;
    balanceAfter: Cents;
  }>; // 只列刪除後餘額會變的對象（借了又還清的不列，開發者 2026-10-17）
  withdrawsDebts: boolean; // 刪除時會撤銷借還（決策 186）
  delete: {
    allowed: boolean;
    blockedBy: 'LEDGER_ARCHIVED' | 'HAS_OTHERS_TRANSACTIONS' | 'SHARED_HAS_DEBTS' | null;
  };
}
```

- 不能刪時 `accounts`、`counterparties` 回空陣列，畫面只顯示原因。
- 只回呼叫者自己的帳戶與對象，不回別人的。
- 能刪時帳本裡的交易都是我記的、也都記在我的帳戶（決策 187），所以 `accounts` 就是我的帳戶扣掉這本帳本的有效交易。

### 4.3 `DELETE /ledgers/{ledgerId}`

- 多一個 query `withdrawDebts`。
- 擋下的順序：
  1. `confirm`（帳本名稱）不對 → 400（照舊）。
  2. 有別人記的交易，或有記到別人帳戶的交易（含已軟刪除）→ 409 `LEDGER_HAS_OTHERS_TRANSACTIONS`（決策 187）。
  3. 共享帳本有借還或分帳 → 409 `LEDGER_HAS_DEBT_TRANSACTIONS`（照舊）。
  4. 私人帳本有我**沒撤銷**的借還或分帳，沒帶 `withdrawDebts=true` → 409 `DEBT_WITHDRAWAL_REQUIRED`。
- 保險：別人在這本帳本有**沒撤銷**的往來紀錄 → 409 `LEDGER_HAS_DEBT_TRANSACTIONS`，不替別人撤銷。
- 以前撤銷過的借還不擋。

### 4.4 借還的寫入（決策 183）

`PATCH /debt-entries/{id}`、`DELETE /debt-entries/{id}`、`POST /debt-proposals/{id}/accept`（修改、撤銷兩種）多 404／403／409 三種錯誤，條件同 `assertLedgerWritable`。

### 4.5 shared

- 新型別 `LedgerRemovalPreview`。
- 新錯誤碼：`LEDGER_NOT_ARCHIVED`、`DEBT_WITHDRAWAL_REQUIRED`。

## 5. 成功條件

- **SC-J1**（借還寫入權）：降為檢視者後 `PATCH { amount }`、`PATCH { note }`、`DELETE` → 403；帳本封存後 → 409 `LEDGER_ARCHIVED`；接受對方的修改、撤銷 → 同上；拒絕 → 200。失敗時往來紀錄、交易、提議都不變。
- **SC-J2**（取消封存）：擁有者 → 200，之後能記帳、`GET /ledgers` 預設就列出；編輯者 → 403；不是成員 → 404；沒封存 → 409 `LEDGER_NOT_ARCHIVED`。
- **SC-J3**（刪除私人帳本）：有借出、還款含分支、分帳 → 不帶 `withdrawDebts` → 409 `DEBT_WITHDRAWAL_REQUIRED`，什麼都沒變；帶 `true` → 204，連動的對象收到撤銷提議，對方的往來紀錄不變；以前撤銷過的借還不擋。
- **SC-J4**（記到別人帳戶）：共享帳本裡我記一筆付款人是小華的支出 → 刪除 409 `LEDGER_HAS_OTHERS_TRANSACTIONS`，預覽 `blockedBy: 'HAS_OTHERS_TRANSACTIONS'`；小華的帳戶餘額不變。
- **SC-J5**（預覽）：預覽的 `balanceAfter` 等於實際刪除後 `GET /accounts`、對象餘額的數字。共享帳本有借還 → `SHARED_HAS_DEBTS`；封存 → `LEDGER_ARCHIVED`。
- **SC-J6**（隔離）：不是成員查預覽、取消封存 → 404；編輯者查預覽 → 403；預覽只含呼叫者自己的帳戶與對象；`withdrawDebts` 只撤銷呼叫者自己的往來紀錄，絕不撤銷別人的。
- **SC-J7**（畫面）：§1 的 1～4 做得到。元件測試涵蓋：刪除對話框的能刪（有借還、只有一般收支）與不能刪兩種樣子、刪除要打對名稱才能按、封存不用打名稱、取消封存只有擁有者看得到、借還頁的修改與撤銷照每一筆的帳本判斷。

## 6. 測試策略

- **隔離測試**（協調者先寫、先紅）：SC-J1、SC-J6，與 SC-J2 的權限部分。
- **單元測試**：預覽的扣除與實際刪除用同一個函式、刪除前的關聯處理、撤銷失敗時整筆回滾。
- **API e2e**：SC-J1～J6。
- **Web**：元件測試涵蓋 SC-J7；Web e2e 一條主線：在私人帳本記一筆支出與一筆借出 → 刪除帳本（看到影響、打名稱）→ 帳本消失、帳戶餘額回來。

## 7. 界線

- **Always**：刪除與撤銷借還在同一個資料庫交易裡完成；預覽與執行用同一套計算；只撤銷呼叫者自己的往來紀錄。
- **Ask first**：改 schema（例如關聯改成 `SetNull`）；替別人撤銷；動到退出的規則（已延後）。
- **Never**：刪除帳本時刪掉往來紀錄本身（對方的待確認會跟著消失）；前端自己算預覽的數字。

- 有 1 個 migration（放寬 CHECK，不動資料）。部署前先備份 `ledger_dev`，再 `prisma migrate deploy`。不改餘額公式，部署後既有的餘額都不變。

- 不改 schema、不改餘額公式，部署後既有的餘額都不變。
- 決策 187 讓一些原本刪得掉的共享帳本刪不掉了。這是預期的，部署前不用查資料。
