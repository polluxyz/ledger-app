## 1. 目標與成功樣貌

2h 定下了黑金視覺，但版面還有四個問題：

| 問題               | 現況                                                                     |
| ------------------ | ------------------------------------------------------------------------ |
| 側欄收合是瞬間切換 | 沒有動畫；帳本區塊從兩行字變成方塊，下面的導覽 icon 跟著往上跳           |
| 收合鈕會換位置     | 展開時在站名右邊，收合後 72px 放不下                                     |
| 首頁塞太多         | 統計卡、篩選、20 筆交易、新增表單、帳戶餘額都在同一頁                    |
| 中間區貼齊左邊     | 管理頁內容只有 600–800px 寬，右邊一大片空白；2560px 時交易列欄位隔得很遠 |

做完之後：

- **左側欄**：開合有動畫（約 220ms）。收合前後，每個 icon 的位置（上下與左右）完全相同。
- **使用者選單**：點側欄底部的使用者，浮出「設定、個人資料、登出」。點「設定」再浮出設定選單，裡面是外觀（跟隨系統／淺色／深色）。
- **帳本切換器**移到總覽與交易頁的標題上方，取代原本的「日常開銷・私人帳本」那一行。側欄不再有帳本區塊。
- **首頁是 dashboard**：統計卡、最近 5 筆交易、帳戶餘額。交易表格、篩選、分頁搬到新的「交易」分頁 `/transactions`。
- **右側欄**：所有登入頁都有，預設打開，可以收起，開合有動畫。裡面是「新增一筆交易」；點一筆交易就換成「編輯交易」。每一頁標題列最右邊有「＋ 新增交易」按鈕。
- **中間區置中**：內容在兩側欄之間的空間置中，側欄開合時跟著平滑移動。清單頁用窄的最大寬度，dashboard 與交易頁用寬的。

## 3. 可驗證的成功條件

### SC-31｜左側欄

1. 收合前後，品牌、每個導覽 icon、收合鈕 icon、使用者頭像的中心座標差 ≤ 0.5px。
2. 開合有寬度動畫，時間 150–250ms。系統設定「減少動態效果」時沒有動畫。
3. 收合時文字仍然視覺隱藏（不是移除），無障礙名稱不變。
4. 側欄不再有帳本區塊、齒輪列、深淺色切換列（分別移到頁首與使用者選單）。
5. 導覽多一個「交易」連結（`/transactions`）。

### SC-32｜使用者選單與設定選單

1. 點側欄底部的使用者，浮出選單「設定、個人資料、登出」。按鈕的 `aria-expanded` 跟著變。
2. 點「設定」浮出設定選單，裡面是外觀三選一（跟隨系統／淺色／深色）。選了立刻生效並記住（沿用 SC-29）。
3. 鍵盤可以完成全部操作：Enter／Space 開啟、方向鍵移動、Esc 關閉一層並把焦點送回開啟它的按鈕。點選單外面也會關閉。
4. 側欄收合時選單仍然可用，浮在側欄右邊。

### SC-33｜帳本切換器在頁首

1. 總覽與交易頁的標題上方是帳本切換器，顯示「〈帳本名稱〉・私人帳本／共享帳本」。無障礙名稱是「作用中帳本」。
2. 只有一本帳本時顯示成文字，不是下拉（沿用 2h 行為）。
3. 切換後，該頁資料與右側欄的「記到：」同時換成新帳本。

### SC-34｜首頁 dashboard 與交易分頁

1. `/` 登入後顯示：頁首、3 張「即將推出」統計卡、最近 5 筆交易（附「查看全部」連到 `/transactions`）、帳戶餘額（附「管理」連到 `/accounts`）。
2. `/transactions` 是 2h 首頁的交易表格：篩選、依日期分組的列表、分頁、鉛筆與垃圾桶。行為與 2h 相同（SC-25.2～SC-25.6 移到這一頁）。
3. `/transactions` 需要登入（掛在 `ProtectedRoute` 之下）。
4. 1440×900 的 `/transactions` 首屏至少看得到 10 筆交易（SC-24.3 移到這一頁）。

### SC-35｜右側欄

1. 所有登入頁都有右側欄，第一次使用時是打開的。
2. 收起、打開都有動畫（150–250ms）；減少動態效果時沒有動畫。收起的狀態重新整理後維持。
3. 每一頁標題列最右邊有「＋ 新增交易」。右側欄收起時按它會打開並把焦點送到金額欄；已經打開時直接把焦點送到金額欄。
4. 點交易頁（或 dashboard）的一筆交易，右側欄換成「編輯交易」（非 modal 的 `dialog`，名稱不變）。儲存、取消、Esc 回到新增，焦點回到觸發的按鈕（沿用 SC-25.3）。
5. 新增表單的群組名稱仍是「新增一筆交易」。
6. ≤ 900px 右側欄是蓋在內容上的抽屜，預設關閉，不造成橫向捲動。

### SC-36｜中間區置中

1. ≥ 901px 時，中間內容在兩側欄之間置中：內容左右兩邊到側欄的距離差 ≤ 1px。
2. 左側欄或右側欄開合後，內容仍然置中，而且移動過程是連續的動畫，不是瞬間跳過去。
3. 總覽、交易的內容最大寬度是寬 token；帳本、帳本明細、帳戶、分類、個人資料是窄 token。
4. 取代 SC-24.5：同一種寬度的頁面，內容的置中軸相同（誤差 ≤ 1px）。

### SC-37｜相容與測試

1. e2e 只改導航步驟（§6 表格列出每一處）；除了假設 14 的 SC-24.5，**斷言一行不改**。
2. 單元測試只增不減；修改選取方式的每一處列在 PR 描述（沿用 SC-27.2）。
3. 新增測試：使用者選單與設定選單（開關、鍵盤、Esc 焦點回歸）、右側欄開合與記憶、「＋ 新增交易」的焦點、頁首帳本切換器、dashboard 最近 5 筆、`/transactions` 的路由保護。e2e 新增 SC-31.1、SC-35.2、SC-36.1、SC-36.2 的量測。
4. `pnpm lint`、`typecheck`、`test`、`format:check`、`build`、兩套 e2e 全綠。不新增任何 npm 相依。
5. 沿用：SC-24.6（375–2560px 不橫向捲動）、SC-26.7（焦點框看得見）、SC-29（深淺色與不閃）。

## 4. 設計決策

### 4.1 開發者的決定（2026-09-23，原文）

> D1 選方案 C（備註：可以 但之後一定會看情況增加或調整圖表）、D2 選方案 A（備註：我覺得是以第一次使用的人為角度來考量 常駐打開可以讓使用者比較直覺去操作）、D3 選方案 A、D4 選方案 A（設定放：外觀（深淺色）、個人資料連結、登出）（備註：修改一下 改成是由點擊使用者名稱會跳出設定 個人資料 登出等選項 如果點擊設定 就會再浮出設定選單）、D5 選方案 B（備註：不能全部同寬 這樣會導致交易 帳戶 等資訊 左右兩側差太遠 造成資訊閱讀不易）、D6 選方案 A（備註：切換帳本的部分可以把他放到 總覽或交易等標題的上方(日常開銷・私人帳本 這一欄)嗎 這樣一來就不用把他放在右側選單 也比較清楚目前是哪個帳本）、D7 選方案 A。其餘照提案執行。

D6 的備註讓提案的 D6（收合時的帳本方塊）不再需要：側欄沒有帳本區塊了。

### 4.2 版面結構

```
┌────────┬──────────────────────────────┬───────────┐
│ 側欄   │        中間區（置中）          │  右側欄    │
│ 240/72 │   ┌────────────────────┐     │  360      │
│        │   │ 內容 max 72/52rem  │     │  （可收起）│
│        │   └────────────────────┘     │           │
└────────┴──────────────────────────────┴───────────┘
```

- 外殼改成三欄 grid：`grid-template-columns: var(--sidebar-current) minmax(0, 1fr) var(--panel-current)`。
- 兩側欄寬度變化時，瀏覽器對 `grid-template-columns` 做過渡，中間區自然跟著移動。中間內容用 `margin-inline: auto` 加最大寬度置中。
- 右側欄從 2h 的「首頁內部欄位」升級成**外殼的一部分**，所有登入頁共用。它的開關狀態放在一個新的 Context（`RightPanelProvider`），頁首的「＋ 新增交易」與交易列都透過它控制。
- 兩個側欄都用 `position: sticky; height: 100vh`，中間區自己捲動。

### 4.3 左側欄：icon 不動的做法

- 每一列固定高度（品牌 48px、導覽 40px、底部各列 40px）。沒有任何一列在收合時改變高度。
- icon 固定在離左邊 20px 的位置。收合只是把側欄寬度從 240px 縮到 72px，右邊的文字被裁掉並淡出（`opacity`，約 160ms）。
- 選中標示（底色與左緣金線）的右邊界跟著寬度一起縮。
- 由上到下：品牌 → 導覽（首頁、交易、帳本、帳戶、分類）→ 彈性空白 → 收合側欄 → 使用者。
- 901–1199px 一律收合、≤ 900px 沿用 ☰（2h 規則不變）。

### 4.4 使用者選單

- 觸發按鈕是整個使用者列（頭像＋名字），無障礙名稱是「〈名字〉的選單」。email 仍然只放在 `title`（2h 的決定，避免 `getByText(email)` 撞到成員列表）。
- 第一層：設定（有向右的箭頭，表示還有下一層）、個人資料（連結）、登出（按鈕，名稱仍是「登出」）。
- 第二層「設定選單」浮在第一層的右邊；空間不夠時改成覆蓋第一層（窄螢幕）。
- 選單用原生 `<button>` 與 `<a>`，加 `role="menu"`／`menuitem`，方向鍵移動。不引用任何選單套件。

### 4.5 右側欄

- 標題「新增一筆交易」旁邊有收起鈕（`«`／`»` 圖示，名稱「收起新增面板」／「展開新增面板」）。
- 收起後寬度 0，不留窄條——要打開用頁首的「＋ 新增交易」。
- 標題下一行小字「記到：〈帳本名稱〉」（假設 3）。
- 編輯模式沿用 2h 的 `Dialog` panel 變體與 `TransactionDialog`。

### 4.6 頁首的帳本切換器

- `PageHeader` 的 `context` 那一行（2h 顯示「📖 日常開銷・私人帳本」）改成放 `LedgerSwitcher`。外觀仍是一行小字加一個向下箭頭，點了是原生 `<select>`。
- `LedgerSwitcher` 不再有收合狀態的樣式（它不在側欄了），相關 CSS 移除。

### 4.7 dashboard

```
┌ 頁首：作用中帳本／總覽 ─────────────── ＋ 新增交易 ┐
├ 本月支出 │ 本月收入 │ 結餘（即將推出）                │
├ 最近交易（5 筆）  查看全部 │ 帳戶餘額        管理     │
└─────────────────────────────────────────────────────┘
```

- 最近 5 筆用既有的交易列表 API（`limit=5`，後端排序），前端不做計算。
- 2j 的圖表加在第三列，本步不放佔位。

### 4.8 中間區寬度

| token                  | 值（初始） | 頁面                                 |
| ---------------------- | ---------- | ------------------------------------ |
| `--content-max-wide`   | 72rem      | 總覽、交易                           |
| `--content-max-narrow` | 52rem      | 帳本、帳本明細、帳戶、分類、個人資料 |

2h 的 `--content-max: 70rem` 目前沒有人使用，由這兩個取代並刪除。

### 4.9 動畫

- 時間：側欄與右側欄的寬度 220ms，文字淡出 160ms，選單 160ms。緩動 `cubic-bezier(.2, .8, .2, 1)`。寫成 `--motion-*` token。
- `prefers-reduced-motion: reduce` 時全部 0ms。
- 只用 CSS `transition`。`grid-template-columns` 的過渡在 Chrome 107+、Firefox 66+、Safari 16+ 都支援；不支援的瀏覽器只是沒有動畫，版面照樣正確。

### 4.10 被否決的替代方案

| 方案                                  | 否決原因                                                              |
| ------------------------------------- | --------------------------------------------------------------------- |
| 右側欄平常收起、需要才開（提案 D2-B） | 開發者：第一次使用的人看不到「在哪裡記帳」，常駐比較直覺。            |
| 右側欄蓋在內容上（提案 D2-C）         | 會蓋住交易列的金額。                                                  |
| 所有頁面同寬（提案 D5-A）             | 開發者：清單頁左右兩側差太遠，資訊不易閱讀。                          |
| 側欄底部放獨立齒輪（提案 D4-A 原版）  | 開發者改成由使用者名稱觸發，把帳號相關的東西收在一起。                |
| 收合時帳本縮成首字方塊（提案 D6-A）   | 開發者把帳本切換器移到頁首，側欄不再需要它。                          |
| 這一輪就加彙總 API（提案 D1-B）       | 範圍大約多一倍，彙總的期間、時區與共享帳本權限需要自己的 spec（2j）。 |

## 7. 界線

**Always**

- 無障礙名稱不改（新加的「交易」連結與選單除外）。
- 收合時文字用視覺隱藏，不用 `display: none`。
- 動畫尊重 `prefers-reduced-motion`。
- 顏色、間距、動畫時間全部來自 `global.css` 的 token。

**Ask first**

- 任何 e2e 斷言的修改（目前只有假設 14 一處）。
- 新增 npm 相依（本步預期為零）。
- 任何後端或 API 的變動（本步預期為零；dashboard 的數字留給 2j）。

**Never**

- 在前端加總金額或算統計（單一後端原則）。
- 為了讓 e2e 不用改而在首頁保留舊表格（提案 D7-B 已否決）。

- 訪客首頁的重新設計。
