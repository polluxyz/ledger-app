## 1. 目標與成功樣貌

階段二做完了功能，但外觀是「把散落的值收攏」的結果，沒有經過設計。實際截圖量測（提案 v2 第 1 節）找到的主要問題：

| 問題                         | 量測值                        |
| ---------------------------- | ----------------------------- |
| 1440×900 首屏看得到的交易    | 5 筆（每列 81–104px、三行字） |
| 390×844 手機第一筆交易的位置 | 1,150px（第 1.36 個螢幕）     |
| 首頁的列內按鈕               | 40 顆，其中 20 顆紅色刪除鈕   |
| 管理頁內容與側欄、右緣的距離 | 左 72px、右 312px（不對齊）   |
| 篩選列欄位高度               | 40px 與 44px 混用             |
| 作用中帳本切換器             | 124px 寬的小下拉，首頁無標題  |
| `*.module.css` 裡寫死的顏色  | 9 處                          |

做完之後：

- **編排**：左邊是可收合的側欄（帳本卡、導覽、使用者），中間是單行的交易表格，右邊是常駐面板——平常是「新增一筆交易」，點一筆交易就變成「編輯交易」。
- **風格**：黑金。深色是暖黑底配金色；淺色是「象牙金」（象牙白內容、黑色側欄、黑底金字按鈕）。預設跟隨作業系統，使用者可以手動切換，載入時不會閃。
- **建立類的表單**（例如「建立帳本」）不再跳小視窗，改成從頁首下方往下展開。
- 所有頁面共用同一個頁首樣式、同一條內容左緣。
- 功能、資料流、可及性名稱**完全不變**。

**這一步不做新功能、不改路由、不改任何 API 呼叫。**

## 3. 可驗證的成功條件

### SC-24｜版面

1. ≥ 1200px：側欄（展開 240px／收合 72px）＋ 交易表格 ＋ 右側面板（360px）三欄並排。寬度是初始值（假設 3），調整後更新本條。
2. 側欄收合的選擇重新整理後仍保留；901–1199px 一律收合；≤ 900px 單欄並使用 ☰（900px 本身算窄螢幕，沿用 2f 的斷點；2026-09-23 實作後更正原文的「900–1199／< 900」）。
3. **1440×900 首屏至少看得到 10 筆交易**（2h 之前 1440×900 是 5 筆）。原訂 1280×800，2026-09-23 實作後量測：保留三張統計卡（D5）與每日日期標題（D16）時 1280×800 放不下 10 筆，開發者決定改以 1440×900 驗收、設計不變、只收緊間距（見 §4.8）。
4. **< 900px 只保證不壞**（假設 4）：單欄、☰ 可用、新增與編輯交易都做得到、沒有橫向捲動。不追求版面品質，手機設計另開一步。
5. 所有登入後頁面的內容左緣在同一條線上（誤差 ≤ 1px）。
6. 375–2560px 任何寬度都沒有橫向捲動（沿用 SC-19.3）。
7. SC-19.1（導覽在側邊欄、內容不超過 70rem）與 SC-19.2（900px 以下單欄）由本條取代；SC-19.4（既有 e2e 不改）由 SC-27.1 延續。

### SC-25｜首頁工作台

1. 右側面板預設顯示新增表單，群組名稱仍是「新增一筆交易」。
2. 按一筆交易的鉛筆鈕，或點那一列的空白處，面板換成編輯。它的角色是 `dialog`、名稱是「編輯交易」。
3. 按儲存成功、取消、關閉鈕或 Esc，面板回到新增表單，焦點回到當初觸發的按鈕。
4. 刪除仍走確認彈窗（modal），名稱仍是「刪除交易」。
5. < 900px 編輯時面板要看得到、存得了（只保證不壞，見 SC-24.4）。做法是編輯時用 CSS 隱藏列表，關閉後列表回來。
6. 首頁上唯一的 `<li>` 仍然只有交易列。日期分組標題不是 `<li>`。

### SC-26｜視覺

1. 所有顏色來自 `global.css` 的 token。`*.module.css` 裡沒有任何色碼（註解除外）。現在的 9 處寫死值全部改走 token。
2. 深色與淺色兩組 token 依 §4.3 的表；使用者沒選過時隨 `prefers-color-scheme`，選過之後依選擇（SC-29）。
3. §4.3 對比表的每一組在兩種模式下都及格：文字 ≥ 4.5:1（WCAG AA 正文標準），焦點框 ≥ 3:1。
4. 金色只用在：品牌標誌、主要按鈕、側欄與表格的選中標示、深色模式的連結。
5. 交易表格：單行、列高 44px、依日期分組、金額右對齊且用等寬數字。支出、收入、轉帳三種顏色，轉帳是中性色。
6. 列上的編輯與刪除是圖示鈕（鉛筆＝編輯、垃圾桶＝刪除），滑過或聚焦時顯示文字提示，無障礙名稱不變。
7. 鍵盤焦點框在兩種模式、內容區與側欄都看得見（`--color-focus-ring` 與 `--color-chrome-focus-ring`）。
8. 首頁的三張「即將推出」統計卡原樣保留，只換樣式（D5）。

### SC-27｜相容

1. **既有 20 條 e2e 一行都不改**就全數通過。
2. 單元測試只增不減。唯一允許的修改是**選取方式**：例如把沒有名稱的 `getByRole('dialog')` 改成帶名稱，因為首頁可能同時有兩個 dialog（編輯面板＋刪除確認）。斷言的意圖不能變，每一處都列在 PR 描述裡。
3. `pnpm lint`、`typecheck`、`test`、`format:check`、`build` 全綠。
4. 不新增任何 npm 相依。字體用系統字體（D6），圖示寫成 inline SVG（D6b）。

### SC-28｜新增測試

1. 新增 `e2e/layout.spec.ts`，驗 SC-24.3、SC-24.5、篩選列欄位同高、375px 時沒有橫向捲動，以及 SC-29.3（選淺色後重新整理，第一個畫面就是淺色）。
2. 新增單元測試：`Icon`、`PageHeader`、`ThemeToggle`、`use-theme`、`theme-init.js`、側欄收合的記憶、面板在新增與編輯之間切換、日期分組不產生額外的 `listitem`、往下展開的開關與焦點。

### SC-29｜深淺色切換

1. 側欄（收合時也在）與訪客頂列有一顆切換鈕，按一下依序換成：跟隨系統 → 淺色 → 深色。按鈕的文字與圖示顯示目前狀態。
2. 選擇記在 `localStorage['ledger.theme']`，重新整理、重新登入後仍保留。
3. **不閃**：選了淺色的人重新整理時，第一個畫出來的畫面就是淺色。
4. 淺色 token 在 CSS 裡出現兩處（手動選的、跟系統的），兩處內容完全相同，由單元測試比對。
5. CSP 不改；`csp.spec.ts` 照樣通過。
6. 下拉選單、日期選擇器、捲軸跟著深淺色變（`color-scheme`）。

### SC-30｜往下展開的建立表單

1. §4.7 表上的四個按鈕，按下後表單在指定位置往下展開，推開下面的內容，不蓋住它。
2. 再按一次、取消、Esc、建立成功都會收起；收起後焦點回到按鈕。按鈕的 `aria-expanded` 跟著變。
3. 展開與收起有約 200ms 動畫；`prefers-reduced-motion` 時沒有動畫。
4. 角色仍是 `dialog`、名稱不變，相關 e2e（`ledgers.spec.ts:24–30, 97–98`、`categories.spec.ts:21–25`）一行不改就過。
5. 分類頁同一時間只展開一個。
6. 編輯、改名、確認類的小視窗行為不變。

### 4.4 為什麼右側面板是「非 modal」

編輯表單放在面板裡，目的是**邊看列表邊改**：編輯中可以直接點另一列換過去。modal 會把列表鎖住，那就只是換了位置的彈窗。

代價：焦點不被鎖在面板裡。所以窄螢幕（< 900px）編輯時用 CSS 把列表整個隱藏，Tab 不會跑到看不見的地方。刪除確認仍是 modal——不可逆的操作應該擋住其他動作。

### 4.5 被否決的替代方案

| 方案                        | 為什麼不選                                                            |
| --------------------------- | --------------------------------------------------------------------- |
| 面板在窄螢幕改用 modal 彈窗 | 要在 JS 讀斷點。2f 已決定斷點只存在 CSS，兩邊寫會分岔                 |
| 收合時把帳本切換器搬到頁首  | 同一個控制項出現兩份，`getByLabel('作用中帳本')` 會同時對到兩個而失敗 |
| 列操作收進「⋯」選單         | e2e 直接點「編輯」「刪除」，選單會多一步                              |
| 深淺切換用三顆並排的按鈕    | 收合的側欄只有 72px 放不下；做兩種 DOM 又會讓同一個控制項出現兩份     |
| 防閃爍用 inline script      | 2g 的 CSP 禁止 inline script，放寬等於取消 CSP                        |
| 往下展開的表單蓋在內容上方  | 會擋住下面的列表；往下推開內容，使用者才看得到新建的項目出現在哪      |

### 4.6 深淺色切換（假設 1）

- **一顆按鈕，按一下換下一種**：跟隨系統 → 淺色 → 深色 → 跟隨系統。按鈕文字寫出目前狀態（例如「外觀：跟隨系統」），圖示跟著換。
- **位置**：側欄底部、使用者區塊旁。側欄收合時只剩圖示，文字視覺隱藏。訪客頂列也放同一個元件（訪客與登入不會同時渲染，所以不會出現兩份）。
- **記住選擇**：`localStorage['ledger.theme']`，值是 `system`／`light`／`dark`。讀不到一律當 `system`。
- **防止閃一下**：新增 `apps/web/public/theme-init.js`，在 `index.html` 的 `<head>` 最前面用 `<script src>` 同步載入。它在 React 執行之前讀 `localStorage`，把 `data-theme` 設到 `<html>` 上。它是外部檔，CSP 的 `script-src 'self'` 本來就允許，**CSP 不用改**。
- **CSS 結構**：深色寫在 `:root`；淺色寫兩處——`:root[data-theme='light']` 與 `@media (prefers-color-scheme: light) { :root:not([data-theme='dark']) }`。兩塊內容必須完全相同，由 token 測試比對（見 SC-29.4）。
- **原生控制項跟著換色**：兩組 token 各自設定 `color-scheme`，下拉選單、日期選擇器、捲軸才會跟著變深或變淺。

### 4.7 往下展開的建立表單（假設 8）

**判斷規則：「新增／建立」往下展開；「編輯／改名」與所有確認視窗維持小視窗。**
理由：建立是在一張清單上多加一項，展開在清單上方，建立完就看到它出現在清單裡；編輯是針對某一列，小視窗蓋在那一列上比較直覺；確認視窗要擋住其他操作，必須是 modal。

依這條規則，會改成往下展開的有四個（其餘不變）：

| 頁面     | 按鈕                       | 展開的位置         | 元件                         |
| -------- | -------------------------- | ------------------ | ---------------------------- |
| 帳本     | 建立帳本                   | 頁首下方、清單上方 | `LedgerDialog`               |
| 帳戶     | 新增帳戶                   | 頁首下方、清單上方 | `AccountDialog`（新增模式）  |
| 分類     | 新增支出分類、新增收入分類 | 各自區塊的標題下方 | `CategoryDialog`（新增模式） |
| 帳本明細 | 加入成員                   | 「成員」標題下方   | `MemberDialog`               |

維持小視窗的：編輯帳戶、改名分類、改名帳本、所有刪除／封存／移除成員／退出的確認。

行為：

- 按按鈕展開，再按一次、按「取消」或 Esc 收起；建立成功也收起。
- 展開時往下推開下面的內容，不蓋住它。展開與收起各有約 200ms 的動畫；使用者設定「減少動態效果」（`prefers-reduced-motion`）時不做動畫。
- 展開後焦點移到第一個欄位；收起後焦點回到按鈕。按鈕帶 `aria-expanded`。
- 它仍是 `dialog` 角色、名稱不變（例如「建立帳本」），用的是 §4.4 同一個非 modal 變體——e2e 的 `getByRole('dialog', { name: '建立帳本' })` 照樣對得到。
- 分類頁同一時間只展開一個（打開「新增收入分類」會收起「新增支出分類」），避免頁面上有兩個同類表單。

## 7. 界線

**Always**

- 可及性名稱一個字都不改（e2e 釘住 74 個選取器）。
- 所有顏色走 token。
- 斷點硬寫在 CSS（900px、1200px），並同步更新 `global.css` 的說明註解。

**Ask first**

- 任何需要改既有 e2e 的情況。
- 新增 npm 相依、改 CSP、改 CI。
- 偏離 §4 的版面或 token。

**Never**

- 在前端加總金額（統計卡維持「即將推出」）。
- 讓同一個控制項在 DOM 裡出現兩份。
- 把「登出」收進下拉選單（e2e 要求一直看得見）。
- 新增 UI 或 CSS 框架。
