## 1. 目標與成功樣貌

3e 把共享帳本的欠款放在交易頁的「結清」，跟借還分開。同一個人在借還有一筆、在共享帳本又有一筆時，使用者要自己加總，搞不清楚到底欠多少。

本步讓**借還頁回答「每個人總共跟我差多少」**，結清檢視照舊回答「這群人怎麼最少次結清」。兩邊用同一組數字。

用 3e 的測試資料（我＝test）貫穿全篇。花蓮三日的結清轉帳（3e 原樣）：

| 轉帳         | 金額  | 跟我有關 |
| ------------ | ----- | -------- |
| 小華 ─▶ 我   | 1,394 | 是       |
| 小明 ─▶ 我   | 512   | 是       |
| 小明 ─▶ 小美 | 400   |          |
| 小明 ─▶ 阿美 | 200   |          |

明哥是我原本就有的連動對象，帳號跟帳本裡的小明相同；個人往來裡明哥欠我 500。

本步完成後：

1. 對象頁多一組「花蓮三日」：小明自動指向明哥，其他人可以手動指向我已建立的對象。
2. 借還頁：明哥一列，總額 `明哥 ─▶ 我 $1,012`（個人往來 500＋花蓮三日 512），展開看來源。小華沒指向，列在下方「花蓮三日」群組，`小華 ─▶ 我 $1,394`。小美、阿美跟我之間沒有轉帳，不出現。兩清的對象不列。
3. 點「花蓮三日 ›」：切到那本帳本的「結清」，右側欄打開結清表單，預填 `小明 ─▶ 我 $512`。
4. 帳本頁的成員區變成一個清單，「非成員」改叫「虛擬成員」；只有一顆「新增成員」，可以從我的對象加人。
5. 我退出帳本後：借還頁照樣顯示我跟別人之間的轉帳，帳戶餘額不變；點帳本名稱打開唯讀畫面，只看得到跟我有關的帳。

### 範圍外（見 §9）

- 在借還頁一次還清總額、由系統分配到各來源。
- 指向後自動跟對方連動，或把帳本裡的人轉成我的對象。
- 結清檢視改成兩兩相算。

## 3. 資料模型

> 依 `CLAUDE.md` §14，schema 變更屬於「先說明再做」。本節核可即視為同意；實作前協調者會再列一次實際的 migration SQL。

```prisma
/// 我把共享帳本裡的某個人指向我的某個對象（3f 決策 146）。只有 userId 本人讀得到。
model LedgerPersonPointer {
  id             String   @id @default(uuid())
  userId         String
  ledgerPersonId String
  /// null＝明確「不指向」（蓋過自動指向，決策 148）
  counterpartyId String?
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt

  user         User          @relation(fields: [userId], references: [id], onDelete: Cascade)
  ledgerPerson LedgerPerson  @relation(fields: [ledgerPersonId], references: [id], onDelete: Cascade)
  counterparty Counterparty? @relation(fields: [counterpartyId], references: [id], onDelete: Cascade)

  @@unique([userId, ledgerPersonId])
  @@index([counterpartyId])
}
```

- 沒有這一列＝套用自動指向（決策 148）。刪除對象時這一列跟著刪（決策 149），之後回到自動判斷。
- `counterpartyId` 必須屬於 `userId`，`ledgerPersonId` 的帳本 `userId` 必須參與過（現任或離開），由服務層檢查（不能用 FK 表達）。
- 沒有回填；舊資料一律走自動指向。

## 4. API

> 依 `CLAUDE.md` §14，API 介面變更屬於「先說明再做」。本節核可即視為同意。前端只顯示，金額、合併、分組都由後端算。

### 4.1 指向

| 方法與路徑                                             | 用途                                                |
| ------------------------------------------------------ | --------------------------------------------------- |
| `PUT /ledgers/{ledgerId}/people/{personId}/pointer`    | 設定指向，body `{ counterpartyId: string \| null }` |
| `DELETE /ledgers/{ledgerId}/people/{personId}/pointer` | 清掉設定，回到自動指向                              |

現任成員才能呼叫（`VIEWER` 以上）；已退出的帳本回 `409 LEDGER_LEFT`（新錯誤碼）。不能指向自己那一筆（`400`）。

### 4.2 對象頁與借還頁

- `GET /counterparties` 每一筆多兩個欄位，`balance` 意義不變：

  ```ts
  ledgerParts: {
    ledgerId: string;
    ledgerName: string;
    personId: string;
    personName: string;
    amount: Cents;
    left: boolean;
  }
  [];
  totalBalance: Cents; // balance ＋ ledgerParts 加總
  ```

  新查詢參數 `?nonZero=true`：只回 `totalBalance ≠ 0` 的對象（借還頁用，W136）。分頁與排序以 `totalBalance` 為準。

- `GET /ledger-groups`（新）：我所在（含已退出且有轉帳）的每本共享帳本一組，供對象頁 W130 與借還頁 W135 使用：

  ```ts
  {
    ledger: {
      id: string;
      name: string;
      left: boolean;
    }
    people: {
      person: LedgerPerson;
      amount: Cents;
      pointer: {
        counterpartyId: string | null;
        auto: boolean;
      }
    }
    [];
  }
  [];
  ```

  `?unpointed=true` 只回沒指向、`amount ≠ 0` 的人（借還頁）。

### 4.3 帳本頁的新增成員

- `POST /ledgers/{ledgerId}/members` 多一種 body：`{ counterpartyId, role }`，只接受**已連動**的對象，後端用連動的帳號加入（前端拿不到對方 email）。原本的 `{ email, role }` 照舊。
- `POST /ledgers/{ledgerId}/people` 多一個選填欄位 `counterpartyId`：建立虛擬成員的同時，替呼叫者設定指向（同一個資料庫交易）。

### 4.4 退出後的唯讀

- `GET /ledgers/{ledgerId}/transactions` 對已退出的人：只回 §151 範圍的交易，`role` 視為唯讀。其他端點（people、settlement-summary、寫入）照舊回 `404`。
- `GET /ledgers/{ledgerId}` 對已退出的人回帳本名稱與 `left: true`，供唯讀畫面標題。

### 4.5 錯誤碼（新增）

| 錯誤碼                    | 狀態  | 情況                                     |
| ------------------------- | ----- | ---------------------------------------- |
| `LEDGER_LEFT`             | `409` | 已退出的人對那本帳本做寫入（含設定指向） |
| `COUNTERPARTY_NOT_LINKED` | `400` | 用沒連動的對象 `POST …/members`          |

別人的對象、我沒參與過的帳本或人，一律 `404`。

## 5. 成功條件

金額寫成元，API 是分。以 §1 的資料為準。

- **SC-F1**：`GET /counterparties` 的明哥：`balance` 50000、`ledgerParts` 一筆（花蓮三日、小明、51200）、`totalBalance` 101200。沒設定任何指向（自動指向）。
- **SC-F2**：`GET /ledger-groups?unpointed=true` 的花蓮三日只有小華 139400；小美、阿美、阿傑不在。
- **SC-F3**：小華 `PUT …/pointer` 指向房東 → 房東的 `totalBalance` 多 139400，unpointed 群組變空；`DELETE …/pointer` → 回到群組。
- **SC-F4**：小明 `PUT …/pointer { counterpartyId: null }` → 明哥的 `ledgerParts` 變空、小明出現在 unpointed 群組；刪掉這個設定 → 回到自動指向明哥。
- **SC-F5**：刪除房東（有被指向）→ 指向設定消失，那個人回到群組。
- **SC-F6**：小明記結清 `小明 ─▶ 我 512` → 明哥的 `totalBalance` 變 50000。
- **SC-F7**：`?nonZero=true` 不回兩清的對象。
- **SC-F8**：帳本頁 `POST …/members { counterpartyId: 明哥 }` → 明哥的帳號成為成員（可編輯）；用未連動的房東 → `400 COUNTERPARTY_NOT_LINKED`。`POST …/people { name: 房東, counterpartyId: 房東 }` → 虛擬成員＋指向。
- **SC-F9**：我退出花蓮三日 → 借還頁照樣有小華 1,394、明哥的花蓮三日 512（`left: true`）；`GET …/transactions` 只回我付、名單有我、結清有我的交易；`GET …/people`、`…/settlement-summary` 回 `404`；設定指向回 `409 LEDGER_LEFT`；帳戶餘額不變。
- **SC-F10**（隔離）：別人讀不到我的指向；`PUT …/pointer` 帶別人的對象、或帶我沒參與過的帳本的人 → `404`；退出後讀不到別人之間的交易。
- **SC-F11**（畫面）：對象頁的帳本群組、指向彈窗；借還頁的總額、展開、帳本群組、兩清不列；點帳本來源切到結清並預填；帳本頁的單一清單、滑出選項、邀請確認；結清檢視兩張卡片；已退出的唯讀畫面。
- **SC-F12**：回歸：3e 的結清數字不變；個人往來、3c、3e 的既有測試全綠。`pnpm lint / typecheck / test / build / format:check` 與兩套 e2e 全綠。

## 6. 測試策略

- **授權先行**：SC-F9、SC-F10 的隔離測試由協調者先寫、先看到紅燈。
- **單元測試**：從結清轉帳取出「跟我有關」的金額、自動指向的判斷、總額合併。
- **API e2e**：SC-F1～F9。
- **Web**：元件測試涵蓋 SC-F11；Web e2e 一條主線：設定指向 → 借還頁總額 → 點來源記結清 → 總額更新。

---

## 7. 界線

- **Always**：總額、合併、分組由後端算；指向只有本人讀寫；退出後的唯讀範圍在後端過濾。
- **Ask first**：改結清檢視的算法；讓退出的人寫入；指向會通知對方或影響別人的畫面。
- **Never**：前端自己加總或分組；讓別人看到我的指向；退出的人看到跟他無關的帳。
