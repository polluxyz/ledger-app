# Spec：階段三 (3e) — 共享帳本分帳與結清的 Web 畫面

> 狀態：**已核可**（2026-10-04）
> 依據：`phase-3e-shared-split.md` §7 的畫面方向；2026-10-04 假設清單（26 點）與開發者回覆：第 9 點改成勾選框的說明、已離開的人不標註並當成非成員（§5 修訂後端決策 134）、預設均分只含現任成員（修訂決策 118）。其餘照建議同意。
> 前置：3e 後端（#104）已合併。
> 定位：主要只動 Web。唯一的後端改動在 §5，跟畫面同一個 PR。

## 1. 目標與成功樣貌

延續 3e spec 的「花蓮三日」：共享帳本，成員是我、小明、小華，帳本與帳戶連動。

1. 我在記帳表單填住宿 6,000、選帳戶。分帳開關已經打開，名單是我、小明、小華，各 $2,000。按「新增」。
2. 我記晚餐 1,500：按 ⇄，付款人選小明，帳戶欄位消失。名單照樣 3 人均分，下方預覽 `我 ──$500──▶ 小明`、`小華 ──$500──▶ 小明`。
3. 小明打開交易頁，晚餐那一列標「待補」。點「待補」，右側欄只有一個帳戶下拉，選好按「儲存」。
4. 交易頁切到「結清」：上面是 `我 +$3,050`、`小明 −$1,000`、`小華 −$2,050`；下面是兩條建議 `小華 ──$2,050──▶ 我`、`小明 ──$1,000──▶ 我`，各有一顆「結清」。
5. 小華按第一條的「結清」，右側欄的結清表單已經填好付錢的人、收錢的人、金額。小華選自己的帳戶，按「新增」。
6. 我在帳本頁的「非成員」區加入阿美。之後記帳時，名單多一列「阿美」，預設不勾。

### 範圍內

- 共享帳本的記帳表單：付款人、帳本分帳的名單與分帳選項。
- 交易頁：結清檢視、結清表單、補帳戶、列表的分帳列與結清列。
- 帳本頁：非成員的管理。
- 後端一處小改動（§5）。

### 範圍外

- 個人帳本的畫面。個人帳本與 3c 分帳全部不變。
- 帳戶待補的提醒（總覽或通知），見 3e spec §9。
- 交易篩選加「付款人」（`?payerPersonId=`），等操作後看需求。
- 行動 App、每個人的支出統計。

## 3. 可驗證的成功條件

金額寫成元，API 是分。都以 §1 的「花蓮三日」為準。

- **SC-W87**：共享帳本的支出表單一打開，分帳開關是開的，名單有我、小明、小華（都勾）與非成員阿美（不勾）。金額 6,000 → 勾選的三人各 $2,000。送出 `POST …/transactions`，沒有 `payerPersonId`，`ledgerSplit` 是 `EQUAL`、3 人。
- **SC-W88**：按 ⇄ → 付款人欄位空白，清單沒有「我」；選小明 → 帳戶欄位消失、分帳開關還在；預覽 `我 ──$500──▶ 小明`、`小華 ──$500──▶ 小明`。送出帶 `payerPersonId`＝小明、沒有 `accountId`。
- **SC-W89**：取消勾選小華 → 小華那一列還在、沒有金額，我與小明各 $750；再勾回 → 各 $500。全部取消勾選 → 「新增」停用。
- **SC-W90**：在付款人清單打「阿美」（新名字）並送出 → 先打 `POST /people`，再用回傳的 id 送交易。
- **SC-W91**：編輯一筆 3e 上線前的共享帳本交易 → 分帳開關是關的；打開後名單只勾現任成員；儲存送出名單。編輯有名單的交易、把分帳關掉 → `PATCH` 帶 `ledgerSplit: null`。
- **SC-W92**：個人帳本的記帳表單、列表與 3c 分帳行為不變（既有測試全綠）。
- **SC-W93**：交易頁在共享帳本有「明細／借還／結清」三格，個人帳本只有兩格。切到結清 → 網址 `?view=settle`、淨額三列 `+$3,050`／`−$1,000`／`−$2,050`、建議兩條箭頭。
- **SC-W94**：按 `小華 ──$2,050──▶ 我` 的「結清」→ 右側欄的結清表單預填小華、我、2,050。以小華登入、選帳戶送出 → `POST /settlements` 沒有 `fromPersonId`、有 `fromAccountId`；之後 summary 與列表都更新。
- **SC-W95**：結清表單付錢的人與收錢的人選同一人 → 「新增」停用。我不是任何一方 → 沒有帳戶欄位。
- **SC-W96**：明細裡的分帳列顯示 `−$1,500`、「分帳」、「小明付」；「›」展開兩行箭頭。結清列顯示 `小華 ──▶ 我` 與 `$2,050`；點了打開結清表單，「刪除」打 `DELETE /settlements/{settlement.id}`。
- **SC-W97**：`accountPending: true` 的列有「待補」；點了只出現帳戶下拉；儲存打 `PUT …/account`。VIEWER 也看得到並能儲存。
- **SC-W98**：帳本頁「非成員」區：新增阿美 → 出現在清單；再新增阿美 → 顯示 `LEDGER_PERSON_NAME_TAKEN` 的訊息；刪除用到的阿美 → 顯示 `LEDGER_PERSON_IN_USE` 的訊息；VIEWER 看不到新增、改名、刪除。
- **SC-W99**：小明離開帳本後：名單與付款人清單照樣有小明、沒有「已離開」字樣、預設不勾；以小明為付款人或名單送出 → 成功（§5）。
- **SC-W100**（e2e）：兩個使用者（甲、乙）在一本連動的共享帳本。甲記住宿 6,000（均分），甲的帳戶 −6,000。甲記晚餐 1,500、付款人乙（均分）。乙登入看到晚餐「待補」，補帳戶後乙的帳戶 −1,500。結清檢視：甲 `+$2,250`、乙 `−$2,250`，建議 `乙 ──$2,250──▶ 甲`。乙按「結清」、選帳戶送出，乙的帳戶共 −3,750。甲看到結清列「待補」，補帳戶後甲的帳戶共 −3,750。結清檢視兩人都是 `$0`、沒有建議。
- **SC-W101**：`pnpm lint / typecheck / test / build / format:check` 與兩套 e2e 全綠。

## 5. 對 3e 後端的修訂（2026-10-04 開發者回覆）

同步改 `phase-3e-shared-split.md`：

| 原決策 | 改成                                                                                                                                            |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 118    | 新交易的分帳預設打開，**預設只勾現任成員**；非成員與已離開的人列在名單裡、預設不勾。這是表單的預設，後端不變（省略 `ledgerSplit` 照舊＝不分帳） |
| 134    | **已離開的人跟非成員一樣可以被選**：新交易的名單、付款人、結清都可以。他當付款人時交易沒有帳戶；他重新加入帳本後，那些交易對他顯示「待補」      |

- 理由：非成員也看不到帳本，照樣能被選；「人已離開，事後才發現還有一筆跟他有關」確實會發生。
- 後端改動：交易端點鎖定與驗證付款人、名單時，`lockPeople` 的 `allowLeft` 一律為 `true`（`transactions.service.ts` 兩處）。結清端點本來就允許。`LEDGER_PERSON_NOT_SELECTABLE` 之後只剩「已刪除的非成員」會用到。
- 帳戶規則不變：已離開的人有 `userId`、不是呼叫者，所以照決策 123 的「別的成員」處理，帳戶必須空著。
- SC-E14 改成：小明離開後，新交易的名單或付款人放小明 → 成功。
- 這是 API 行為變更（`CLAUDE.md` §14），本節核可即視為同意。

## 6. 界線

- **Always**：淨額、建議、份額以後端回應為準；名單預覽只是顯示；用 `Ledger.kind` 判斷共享帳本。
- **Ask first**：§5 以外的後端改動；在畫面上自己算淨額或建議；新增前端套件。
- **Never**：顯示別人的帳戶名稱；畫面出現「好友」「已離開」；個人帳本的行為改變。
