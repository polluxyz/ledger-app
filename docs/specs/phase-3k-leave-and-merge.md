## 1. 目標與成功樣貌

現在退出共享帳本後，那本帳本照樣算進我的帳戶餘額（3f 決策 152），帳本卻已經不是我的，我也改不了。對我來說，退出應該等於從我這邊刪掉這本帳本。但旅行真的花過錢、真的刷過卡，帳戶餘額也不能因為退出就跳掉。

本步讓**退出前先把跟我有關的帳合併到我的另一本帳本**。合併後帳戶餘額不變，統計只算我自己的份額，還沒結清的錢變成我跟那個人的個人借還。不想合併的交易，退出前會先看到哪些帳戶會變。

用一個例子貫穿全篇。共享帳本「花蓮三日」有我、小明、小華 3 人：

| #   | 交易 | 誰付                | 名單     | 我的份額 |
| --- | ---- | ------------------- | -------- | -------- |
| 1   | 住宿 | 我，信用卡 $3,000   | 3 人平分 | $1,000   |
| 2   | 晚餐 | 小明 $1,500         | 3 人平分 | $500     |
| 3   | 結清 | 小華付我現金 $1,000 | —        | —        |

退出前：信用卡 −$3,000、現金 +$1,000（這本帳本的部分）；借還頁「小華 ─▶ 我 $500」；小明跟我兩清。

本步完成後：

1. 我按「退出帳本」→ 對話框「退出「花蓮三日」」，只有一個「合併到」下拉，預設是我的第一本私人帳本「日常」。帳戶全部不變，所以不列帳戶；往來只列「小華 ─▶ 我 $500」。按「退出」。
2. 「日常」多了 3 筆，都標「花蓮三日」：
   - 「住宿 $3,000」，標出我的份額 $1,000。信用卡扣 $3,000，統計只算 $1,000。
   - 「晚餐 $500」，沒有帳戶，算進統計。
   - 「結清 小華 +$1,000」，進現金，不算統計。
3. 信用卡、現金的餘額跟退出前一樣。統計多 $1,500。借還頁的小華多一筆「花蓮三日 $500」，總額照舊是「小華 ─▶ 我 $500」。花蓮三日不再出現在借還頁、對象頁與帳本切換清單。
4. 進階：在對話框點「選擇交易」打開選擇畫面，取消勾選「住宿」→ 選擇畫面下方的帳戶段馬上出現信用卡少扣 $3,000（例：`−$12,400 → −$9,400`）；按「完成」，退出對話框顯示一樣的數字。退出後「日常」只多晚餐和結清。小華欠我的 $500 照樣轉成個人借還。
5. 小明在我退出後記一筆「我付的」計程車費 → 這筆沒有帳戶，我的帳戶餘額不變。
6. 其他人都退出後，擁有者按「刪除帳本」→ 同一個對話框，多一個帳本名稱欄。打對名稱按「刪除」→ 先合併再刪除。
7. 擁有者想移除還有帳的小華 → 「小華在這本帳本有帳，只能改成檢視者，由他自己退出」。

### 範圍外

- **私人帳本刪除時合併**：3j 的刪除照舊（撤銷借還、不合併）。要的話另案。
- **合併到別的共享帳本後，再拆給那本的成員**：合併只寫我自己的帳。
- **合併後還原**：重新加入帳本不會把合併的帳搬回去（決策 199）。
- **隱藏帳本**：照 3j 範圍外。
- **封存的帳本退出**：照舊不能（3j 範圍外），要先取消封存。

## 3. 資料模型

**要改 schema（開發者 2026-10-18 同意方向，細節在此核可）。** 決策 196 要把兩筆內部紀錄當成一筆顯示，決策 199 要認得哪些交易合併過，決策 198 要一種不動帳戶的新借還。

```prisma
/// 一次合併（3k）。只有本人看得到。來源帳本可能之後被刪掉，所以存名稱、不設外鍵。
model LedgerMerge {
  id               String   @id @default(uuid())
  userId           String
  sourceLedgerId   String   // 不設外鍵：來源帳本刪掉後合併的帳要留著
  sourceLedgerName String   // 當下的名稱，畫面標來源用
  targetLedgerId   String?  // 全部取消勾選時為 null
  createdAt        DateTime @default(now())

  user         User          @relation(fields: [userId], references: [id], onDelete: Cascade)
  targetLedger Ledger?       @relation(fields: [targetLedgerId], references: [id], onDelete: Cascade)
  transactions Transaction[]
  debtEntries  DebtEntry[]

  @@index([userId, sourceLedgerId])
}

model Transaction {
  // ...既有欄位
  /// 合併來的交易屬於哪一次合併（3k）。
  mergeId      String?
  /// 合併自哪一筆原交易（不設外鍵：原交易可能跟著來源帳本刪掉）。同一筆原交易的份額與代墊共用這個值，畫面據此顯示成一筆。
  mergedFromId String?

  merge LedgerMerge? @relation(fields: [mergeId], references: [id], onDelete: Restrict)

  @@index([mergedFromId])
}

enum DebtEntryKind {
  // ...既有種類
  LEDGER_CARRY_OVER // 帳本轉入（3k 決策 198）：退出時沒結清的錢；不產生交易
}

model DebtEntry {
  // ...既有欄位
  mergeId String? // 帳本轉入才有值
  merge   LedgerMerge? @relation(fields: [mergeId], references: [id], onDelete: Restrict)
}
```

CHECK：

- `Transaction`：`mergedFromId` 有值 ⇔ `mergeId` 有值。
- `DebtEntry`：`kind = 'LEDGER_CARRY_OVER'` ⇔ `mergeId` 有值；且此時 `transactionId` 為 `null`。

**帳本往來用既有的借還型別**：代墊與付出的結清記 `LEND`，收到的結清記 `COLLECT`，代收記 `BORROW`。餘額公式（`directionOf`）與「借還不算統計」都不用改。

- 這打破「借還交易只能從往來帳產生」（shared `DEBT_TRANSACTION_TYPES` 的註解）：多一個例外「`mergeId` 有值」。交易端點對借還型別的限制照舊，合併來的另外依決策 202 開放。
- 替代方案：新增一個交易型別「帳本往來」。比較清楚，但餘額公式、統計、所有依型別分支的地方都要改，範圍大很多。

不改餘額公式。退出時清帳戶（決策 190）、合併寫入、撤銷沒勾的借還，都在同一個資料庫交易。

部署：migration 只加表、加欄位、加 enum 值、加 CHECK，不動既有資料。部署前備份 `ledger_dev`。

## 4. API

### 4.1 `POST /ledgers/{ledgerId}/leave-preview`（新）

權限：這本帳本的成員（檢視者也可以，退出不需要寫入權）。不是成員 404。封存 → 預覽回 `leave.allowed: false`。

```ts
interface LeaveRequest {
  targetLedgerId: string | null; // 全部取消勾選時可以是 null
  excludedItemIds: string[]; // 取消勾選的項目（LeaveItem.id）
  deleteLedger?: boolean; // 最後一個人刪除帳本（決策 204）
  confirm?: string; // deleteLedger 時的帳本名稱（只有執行時要）
}

interface LedgerLeavePreview {
  items: Array<{
    id: string; // 原交易 id；個人分帳用分帳 id
    date: string;
    title: string | null;
    categoryIcon: string | null;
    accountEffects: Array<{ accountId: string; name: string; delta: Cents }>; // 對我各帳戶的加減；別人付的為空陣列
    share: Cents | null; // 我的份額（算統計的部分）
    paidByName: string | null; // 別人付時的付款人顯示名稱；我付或我的個人借還為 null
    kind: 'SHARED' | 'PERSONAL_DEBT' | 'PERSONAL_SPLIT';
  }>;
  accounts: Array<{ accountId: string; name: string; balance: Cents; balanceAfter: Cents }>; // 只列會變的
  carryOvers: Array<{
    ledgerPersonId: string;
    displayName: string;
    amount: Cents;
    counterpartyId: string | null;
  }>; // amount 正＝對方欠我；counterpartyId null＝會新增對象
  withdrawals: Array<{
    counterpartyId: string;
    displayName: string;
    linked: boolean;
    balance: Cents;
    balanceAfter: Cents;
  }>; // 沒勾而撤銷的個人借還
  leave: {
    allowed: boolean;
    blockedBy:
      'LEDGER_ARCHIVED' | 'LAST_OWNER' | 'HAS_OTHER_MEMBERS' | 'HAS_OTHERS_TRANSACTIONS' | null;

```

- 只回呼叫者自己的帳戶與對象。
- `targetLedgerId` 檢查同執行（§4.2）。
- 預覽與執行共用同一個計畫函式（同 3j `removalPlan` 的作法）。

### 4.2 `POST /ledgers/{ledgerId}/leave`（新）

body 同 `LeaveRequest`。成功 204。

擋下的順序：

1. 不是成員 → 404。封存 → 409 `LEDGER_ARCHIVED`。
2. `deleteLedger`：不是擁有者 → 403；還有其他成員 → 409 `LEDGER_HAS_OTHER_MEMBERS`；`confirm` 不對 → 400；有交易記到別人的帳戶 → 409 `LEDGER_HAS_OTHERS_TRANSACTIONS`。
3. 不是 `deleteLedger`：我是最後一位擁有者 → 409 `LAST_OWNER_CANNOT_LEAVE`（照舊）。
4. 有要合併的項目、`targetLedgerId` 是 `null` → 400。目標帳本：不是成員 404、檢視者 403、封存 409 `LEDGER_ARCHIVED`、等於來源帳本 400。
5. `excludedItemIds` 有不屬於 `items` 的 id → 400。

執行（同一個資料庫交易）：建 `LedgerMerge` → 寫合併的交易、搬個人借還（分類依決策 200）→ 撤銷沒勾的個人借還（沿用 `removeInTransaction`）→ 寫帳本轉入 → 清帳戶（決策 190）→ 刪指向 → 刪成員（或 `deleteLedger` 時照 3j §3 的順序刪帳本）。

### 4.3 既有端點的改變

- `POST /ledgers/{id}/members`：加回曾退出的人時，撤銷他上次退出這本帳本留下的帳本轉入（決策 208）。回應不變。
- `DELETE /ledgers/{id}/members/{自己}` → 409 `LEAVE_REQUIRES_MERGE`（決策 207）。
- `DELETE /ledgers/{id}/members/{別人}`：對方有帳 → 409 `MEMBER_HAS_TRANSACTIONS`（決策 206）。
- `DELETE /ledgers/{id}`、`GET /ledgers/{id}/removal-preview`：共享帳本改照決策 204 判斷；只剩我一個時預覽回 `blockedBy: null`，畫面改用 §4.1、§4.2。
- 建立、修改交易與結清：已退出的人當付款人或結清方 → 不記帳戶（決策 191）。
- `PATCH /ledgers/{id}/transactions/{tid}` 補帳戶：這筆我合併過 → 409 `TRANSACTION_ALREADY_MERGED`（決策 199）；回應的 `accountPending` 對合併過的為 `false`。
- 合併來的交易：可以改名稱、分類、帳戶與刪除，其他欄位 → 400（決策 202）。兩筆內部紀錄一起改、一起刪。
- `Transaction` 回應多 `merge: { sourceLedgerName: string; share: Cents | null } | null`。
- `DebtEntry` 回應多 `merge: { sourceLedgerName: string } | null`：帳本轉入才有值，往來紀錄列用它顯示帳本名（W192；開發者 2026-10-19 核可補進契約）。
- 借還頁、對象頁、統計的共享帳本部分：只算我現在是成員的帳本（決策 189）。

### 4.4 shared

- 錯誤碼：`LEDGER_HAS_OTHER_MEMBERS`、`MEMBER_HAS_TRANSACTIONS`、`LEAVE_REQUIRES_MERGE`、`TRANSACTION_ALREADY_MERGED`。
- `DebtEntryKind` 加 `LEDGER_CARRY_OVER`；`DEBT_TRANSACTION_TYPES` 的註解改寫例外。

## 5. 成功條件

- **SC-K1**（合併後餘額不變）：§1 的例子退出並全部合併 → 每個帳戶的 `GET /accounts` 餘額跟退出前一樣；目標帳本統計多 $1,500；借還頁小華總額照舊 $500。
- **SC-K2**（取消勾選）：取消勾選住宿 → 預覽信用卡的 `balanceAfter` 比 `balance` 多 300000（分），執行後 `GET /accounts` 等於預覽；小華的帳本轉入照樣有。
- **SC-K3**（退出後不再算）：退出後 `GET /accounts`、借還頁、對象頁、統計都不含花蓮三日；`GET /ledgers/{花蓮三日}` → 404。
- **SC-K4**（已退出的人當付款人）：我退出後小明記「我付的」→ 交易 `accountId` 為 `null`；我的帳戶餘額不變。結清同理。
- **SC-K5**（重新加入）：退出並合併後被加回 → 帳戶餘額不變；合併過的交易沒有「帳戶待補」、補帳戶 → 409 `TRANSACTION_ALREADY_MERGED`；沒合併的可以補。上次的帳本轉入已撤銷，借還頁對那個人的總額跟退出前一樣；再退出只有一筆帳本轉入、已合併過的交易不再合併（決策 208）。
- **SC-K6**（個人借還搬家）：我在花蓮三日記的借明哥 $500（連動）→ 勾選：交易改到目標帳本，配對與往來餘額不變，明哥沒收到提議；不勾：照 3j 撤銷，明哥收到撤銷提議。
- **SC-K7**（分類）：目標帳本有「住宿」就用它；沒有就建一個同名同圖示的；合併來的交易不會指到來源帳本的分類。
- **SC-K8**（最後一個人刪除）：其他人都退出後，擁有者帶 `deleteLedger` → 204，帳本消失，合併的帳在目標帳本。還有其他成員 → 409 `LEDGER_HAS_OTHER_MEMBERS`。
- **SC-K9**（移除成員）：小華有帳 → 移除 409 `MEMBER_HAS_TRANSACTIONS`，改成檢視者 200；沒帳的成員可以移除。舊的自己退出端點 → 409 `LEAVE_REQUIRES_MERGE`。
- **SC-K10**（隔離）：不是成員查預覽、退出 → 404；目標帳本不是我的 → 404、檢視者 → 403；預覽只含我的帳戶與對象；合併寫入的交易只用我的帳戶；退出不會改到其他成員的帳戶、借還與他看到的交易。
- **SC-K11**（一致與回滾）：預覽的 `balanceAfter` 等於執行後的數字；寫入中途失敗（例如目標帳本同時被封存）→ 整筆回滾，還是成員、帳戶不變。
- **SC-K12**（畫面）：§1 的 1～7 做得到。元件測試涵蓋 W188～W193。

## 7. 界線

- **Always**：退出的所有寫入在同一個資料庫交易；預覽與執行用同一套計算；只動呼叫者自己的帳戶、對象與借還；合併的分類一律用目標帳本的。
- **Ask first**：改餘額公式；改成新增交易型別（§3 替代方案）；替別人退出或合併；私人帳本刪除也合併（範圍外）。
- **Never**：退出時刪掉或改動其他成員看得到的交易內容；把別人的帳戶寫進合併的交易；前端自己算預覽或合併的數字。
